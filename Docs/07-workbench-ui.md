# 07 工作台界面

本文件说明 FORGE 的桌面外壳、停靠布局、项目树、各面板、会话转录与输入框、命令面板、通知、设置、外观与本地化。

## 7.1 窗口外壳

- `WindowDecorations="BorderOnly"` + 扩展客户区：保留系统可缩放边框、去掉系统标题栏，客户区铺到窗口上边缘；标题行自绘，40 px，底色与 panel 标题栏同色。
- 标题行左侧：18×18 Forge 图标（`Assets/forge.png`，透明通道保留）、“自动化任务”入口（闪电 + 文字，徽标只计执行中与等待中的运行，0 时隐藏）；右侧：放大镜（命令面板）、扩展宿主状态点（绿=运行 / 黄=启动中 / 红=失败 / 灰=其余，tooltip 给状态、进程 id、失败原因）、终端图标、设置、最小化、最大化、关闭。
- 窗口标题仍是 Forge（任务栏与辅助功能识别）；所有窗口共用应用图标；主窗口启动居中于所在屏幕 `WorkingArea`，按桌面缩放换算尺寸并计入原生边框，可用区域过小时降低最小尺寸；用户后续移动/缩放不再重新居中。
- 标题行可拖动、双击最大化；按在按钮/输入框上不拖动；`CaptionPress` 是主窗口与浮出窗口共用的一份规则。
- 单实例：打开 `forge.db` 之前取数据根上的独占锁，拿不到只显示“Forge 已在运行。”后退出（不转交、不唤醒已有窗口）。

## 7.2 停靠布局

- 三个区域按**角色**命名而不按位置：**项目区**、**主区**、**检视区**；默认顺序 项目 | 主 | 检视，可拖拽互换（内容跟着角色走）。
- 项目区：上下叠放「项目」与「常规对话」两块 panel，中间 1 px 线可拖，比例存 `WorkbenchLayout.ProjectSplitRatio`（默认 0.5，任一侧不低于最小高度）。
- 主区：主选项卡组（只放会话标签）+ 底部组（子 Agent 选项卡组；终端也是这里的标签）。
- 检视区：上为文件 panel，下为 TODO | 评审 | 规格树 | 问题 选项卡组；两块之间的 1 px 线可拖，高度按 panel id 存快照的 `belowHeights`（缺省按已拖过者均值，全无则平分）；分配与夹紧由纯函数 `PanelStackSolver` 完成。
- 宽度：项目/检视最小 200 px、主区最小 360 px；首次默认 项目 260 / 检视 275 / 预览列 420。拖分隔条时另一侧吸收全部增量；被挤压的一侧主区先缩到最小，再按离分隔条由近到远缩其余区域；边栏缩到最小后继续拖，越过最小宽度一半（`CollapseOvershoot` = 0.5）才自动隐藏；主区永不隐藏。计算由 `RegionWidthSolver` 完成（拖动路径不分配，松手才写快照）。
- Panel 标题栏 28 px：单块标题用 `FontSizeMd` + Bold，选项卡标签用正文档字号 + Normal；字重只取 400/700（中文侧没有 600 字体面）。
- 按钮按能力显示：自动隐藏/停靠（图钉实心=已停靠、空心=已隐藏）、缩小/还原（有可接收空间的同伴时可见；缩小只留 28 px 标题栏，正文隐藏但不销毁；同伴消失时自动还原）、新窗口/停靠（只给可浮出的对象）；除预览组外不放关闭按钮。没有“放大”按钮：局部放大用缩小同伴或把标签浮出。
- 标签：25 px 高、贴标题栏底边；激活标签上圆角 5 px、两条侧边到底边**向外**拐 5 px 圆角（`ClipToBounds=False` 才能画出），底边压在下方面板分隔线上；可关闭标签预留 16 px 关闭槽 + 6 px 间距，会话标签多一个 14 px 气泡图标（激活时填充）；不可关闭标签（TODO/评审/规格树）左右内边距对称。标签放不下时右端出现 `…`，列出被裁剪的标签并滚进视口。
- 停靠条与自动隐藏：仅自动隐藏的边栏在窗口边缘显示 32 px 停靠条（竖排标签、3 px 指示条：抽屉打开为 `DockIndicatorIdleBrush`、关闭为 `AccentBrush`）；抽屉贴停靠条内侧弹出、覆盖主区上方，点外部或 Esc 收起；两个自动隐藏边栏在同一侧时并排。
- 浮动窗口：只允许浮出选项卡（任意组）与文件 panel；文件 panel 浮出时预览组随它进同一个窗口、回位一起回。一个对象一个 `FloatingPanelWindow`（默认 900×640，文件 panel 320×420），同视图模型重新套模板；浮出的标签仍在原组集合里（只标记浮动），点停靠或关窗天然回到原槽位；最小化期间不写回几何；窗口整体带 1 px 边框；标题条 28 px 可拖动、双击最大化。
- 预览列宽度只由一个状态驱动（检视区当前是否含预览列），打开/关闭/浮出都走这一处，避免宽度漂移。
- 区域置换：按住 panel 标题栏空白处横向拖，出现三个落点，放下后两区互换，宽度跟着区域走；自动隐藏中的区域不能拖。

## 7.3 布局快照

- 两份快照都用源生成 JSON 存 `forge.db` 的 `ui_state`：
  - `LayoutSnapshot` v5：区域顺序、宽度、自动隐藏状态、底部组高度与是否缩小、各区 panel 高度比例、预览组开关与宽度、浮动窗口（对象 + 几何）、`belowHeights`（可选追加字段，旧版本缺省即平分）。
  - `OpenTabsSnapshot` v2：打开的标签（预览选项卡存绝对路径）。
- 版本不认识、缺 `version` 或解析失败一律回落默认布局，不迁移；未知 id 丢弃；缺失项保持默认位置；浮动窗口在它装的选项卡存在之后才应用，坐标落在所有屏幕之外时移回主窗口所在屏幕；未放置过的浮动窗口不存坐标，恢复时居中。
- 拖动分隔条松手与切换选项卡各触发一次保存；800 ms 防抖写入。退出时最后一次布局在后台保存，UI 线程最多等 3 秒（超时只记日志）。

## 7.4 项目树

- 行高 28 px；扁平 `RangeObservableCollection` + 虚拟化 `ListBox`；展开/折叠按路径/id 记状态，展开状态跨刷新保留。
- 层级：项目（工作区层，Bold）→ **仓库根检出**（第一个子行；标签取真实分支名，游离显示“游离 HEAD”，非仓库不出现）→ 其它 worktree 分组 → 会话行 → 子 Agent 行（可到孙 Agent）；归档会话收进“历史 (n)”。
- 整行可点：会话行打开会话；有子项的行展开/折叠；没有子项的项目/worktree 行新建会话；子 Agent 行先把会话带到主区前台、再展开底部组并选中该标签（活的与已结束的都算）；Enter/空格对选中行生效；点在行内按钮只执行按钮。
- 行尾“+”：项目行是分支加号（新建 worktree 分支）、常规对话/worktree 行是纯加号（新建会话），两者 12 px（按钮 22 px），tooltip 写清是哪一种。
- 子树图标：Scout 放大镜、Worker 锤子、Plan 三行、Reviewer 对勾、未知回落会话气泡；状态：排队/运行/失败/已停止/未知是圆点，正常完成是绿色对勾，文案退到 tooltip；运行中带透明度呼吸动画（受“减少动画”闸门控制）。
- 活动会话行浅强调底；底部组当前选中的子 Agent 标签让树里对应行拿同样的 active 底。
- 会话行带自动化闪电标记（tooltip “由自动化任务创建”）；已删除/已移除/目录缺失/worktree prunable/未登记/状态未知的标记见 01.8。

## 7.5 文件面板与预览列

- 两个标签：**全部**（文件索引的文件数）与**已改动**（当前范围的改动文件数），各有中性数量徽标（选中时翻成面板底 + 强调色数字），0 照常画 0；数字同时进辅助功能名字。
- 右上角刷新；「已改动」时刷新换成全部折叠/展开。
- 「已改动」下方是自绘范围下拉与基线下拉（语义见 04.2），选中项命令执行后才关闭弹层。
- 面板最上面两行 git（本地同步行 + 出货行，详见 04.4），无仓库时隐藏。
- 检出区缩到 200 px 时先让位分支名、再让位结果文字，三个动词永不裁剪；出货行先收远程读数，两个药丸保持完整。
- 点文件在检视区靠主区一侧打开**预览组**（文件预览与逐行审阅）；“全部”里单击复用预览选项卡、右键才新建；“已改动”里点文件打开固定的“改动”选项卡并定位到该文件；预览组“铺满主区”按钮盖住整个主区。
- 行内工具栏：20 px 图标切换自动换行；支持选择、复制、撤销/重做、工具栏保存 / Ctrl+S。

## 7.6 检视区面板

### TODO 面板

- 结构：置顶排队输入行（`＋` + 无边框输入框，Enter 添加为**待排散项**，`TodoOrigin.User`）→ 未完成分组（组行 + 缩进步骤，未完成组始终展开、无删除与折叠入口）→ 待排散项 → 完成区（已完成分组收成一行、点整行展开；已完成散项排其后）→ 历史压底。
- 步骤状态四态且不可点：未开始空心圆 / 进行中绿点圈 / 暂停灰 `⏸` / 完成绿 √；分组状态由步骤推导（全 done → ✓；有 in_progress → ⊙；否则有 paused → ⏸；否则 ○），从不存储。
- 面板**只读展示**：没有勾选框、不能改状态；只支持新建、删除（悬停/聚焦时行尾 `×`）、同层拖拽调序、失败步骤重试提交。人工添加的行右端多一枚线框 user 图标。
- 状态行只在没会话/清单为空/存储报错时显示一行说明；有内容时没有汇总行。

### 计划面板

- 窗口标题行右侧的计划按钮打开当前会话计划；再点一次、关闭按钮、点遮罩或 Esc 关掉；切换会话时自动关闭；没有活动会话时按钮禁用。
- 居中卡片（最宽 1120、最高 760）：左列摘要 + 步骤，右栏下一步 + 三个出口 + 修订历史。
- 摘要：`todo plan_summary_set` 写的 Markdown，按聊天同一渲染器渲染，只在文本变化时重建；标题右“更新于 MM-dd HH:mm”；没写过时显示一行说明。
- 步骤：扁平虚拟化列表，分组行画成 band，步骤行画状态图标、标题（下一步带强调色小片）、`改动:`、带对勾的 `验证:`、note、7 位 sha 或提交失败原因（危险色）；分组顺序与 `PrBodyRenderer` 一致（分组顺序 → 组内顺序 → 无分组散项归“其他步骤”）；行按 key 就地更新，刷新不滚回顶部。
- 只读是契约：不写存储、没有勾选框；唯一动作是“把这一步交回 agent”（写入该会话输入框并发送；回合中则排队；输入框已有用户文字或附件时不覆盖、不夹带，改为报一行提示；只读/交接/压缩/门控中报不可用）。
- 下一步：第一个 `in_progress`，否则第一个 `pending`；全做完写“没有未完成的步骤了”。
- 修订历史：`plan_summary_revisions` 最近 50 条，新→旧，每行时间 + 首行预览 + 复制；点整行预览该版本（顶部提示 + “回到当前摘要”）。
- 三个出口：`复制 Markdown`（= `PrBodyRenderer`）、`导出 Markdown…`（保存对话框，建议文件名 `<会话标题>-plan.md`）、`从计划开 PR…`（与提交目标行同一个命令，可用性随之刷新）。

### 评审面板

- 列出当前工作区的 PR 评审线程与本地行评审（草稿、已发送），支持单条/批量发送、回复与解决（语义见 04.9）；顶部给数量摘要，无会话/读失败时一行说明。

### 规格树面板

见 [05-spec-graph.md](05-spec-graph.md) 5.3。

### 问题面板

## 7.7 转录（聊天时间轴）

- 主会话与子 Agent 共用同一组模板，排成一条时间轴：左侧贯穿细竖线，每个事件一个节点图标落在轴上，内容在节点右侧。
- 节点：用户消息、助手回复、工具调用（按工具名分类：读文件/搜索/编辑/命令/网络/MCP/子 Agent/计划/通用）、转录提示（只有失败时改用错误图标）、被拒绝的审批（警示色）、回合脚注错误；轮次抬头（第 N 轮 · 耗时 · token）不是事件，通常无节点，必要时作为轴端。
- 状态：运行中（实心 + 强调色 + 脉冲）、失败（危险色）、审批被拒（警示色）、其余空心 + 次要色；节点不抢焦点、不可点击，`AutomationProperties.Name` 是当前语言的可读名称 + 状态词。
- 工具名到节点的映射在纯函数里（逐个内置工具名 + MCP 的 `server__tool` 分隔符 + 未知名回退），可读名称在 `Strings.Timeline.cs`。
- 几何在纯函数 `TimelineLayout`：每行只回答“上方有节点/下方有节点”，轴从第一个节点起、最后一个节点下截止；虚拟化回收容器时最多 3 次后台重试，耗尽后只画节点不画线，由下一次集合变化纠正。
- 轮次卡头：第 N 轮 · 时间 · 耗时 · 输入/输出（`AgentTurnCompleted` 是实例累计，卡上显示本轮差值；未上报显示“—”）。
- 工具行折叠时只显示名字、参数摘要与状态；展开后显示输出尾部与结果图片缩略图（首次读 `Thumbnail` 才后台解码，长边默认 256 px、可调 64–1024，不重新编码存下的字节）。
- 思考行：`AgentThinkingDelta` 实时渲染成折叠的思考行、流式追加；思考不落库，重放没有思考行。
- **Markdown 增量渲染**：标题、段落、列表与任务项、引用、表格、分隔线、链接、围栏代码块；用户消息按纯文本（不解析 Markdown）。渲染分“已定稿块前缀 + 未定稿区”：定稿边界是围栏代码块之外的最后空行，前缀只追加、永不重排；未定稿区每帧整体重解析，末尾同段/同标题只换 Inlines，同围栏只换 Text，列表与表格就地生长；超过 4096 字的单段落按行收口；`Complete()` 再对全文解析一次并逐块比对，不一致才整篇替换——最终渲染恒等于“对全文做一次块解析”。
- 代码块：顶部语言标签 + 复制按钮，正文等宽、可横向滚动；`Update(text, info)` 就地换文本，流式不重建控件。每段回答文本各有复制按钮（整条纯文本 = 追加过的原文）。
- Mermaid：` ```mermaid ` 代码块在聊天、diff 预览与计划面板本地渲染成图——Mermaider 解析 + 布局 + SVG → 颜色预处理（算 `color-mix`）→ Svg.Skia 解析成 `SKPicture` → 渲染线程矢量回放（不栅格化、不编码 PNG、DPI 自动清晰）。后台线程、限 2 并发、超时默认 2000 ms（500–30000）、缓存 24 条（源码 + 调色板 + 白名单为键，失败不缓存）；不联网：mermaider 元素/属性白名单消毒 + 拒绝任何非 `#` 开头的 `href`/`url(...)`/`@import`；流式未闭合围栏只显示源码，定稿才渲染；图类型白名单是 `chat` 分区的逗号列表（默认 flowchart/sequence/state/class/er，另有 pie/quadrant/timeline/gitGraph/mindmap/gantt/journey/c4/requirement/kanban/radar/treemap/venn/sankey/xychart/packet/architecture/block/treeview）。失败保留源码并显示渲染器原文（带行号时写“第 N 行”）、重试按钮与“让模型修正”（固定英文消息，交给块所属会话，忙则进草稿；后台标签页的块绝不把消息发进别的会话）。
- 主题跟随：调色板取自界面表面/正文/强调/次要/边框令牌；主题变化与新挂回可视树时按新调色板重渲染（相同则不重渲）。

## 7.8 会话输入框（composer）

- 一张卡：白色上条（可见 34 px）+ 灰色输入区（四角全圆、上沿压在上条最后 10 px 上）；聚焦时两块边框一起换成强调色；卡片本身透明无边框。
- 上条左侧：`↑a ↓b`（≥640 px 才显示，唯一会让位的元素）、**“资源 ▾”**（把审批、技能、MCP、工具四枚计数合成一个菜单：`审批 2/5`、`工具 11/21` 等，点任意一行打开设置页对应分区；第五行“运行中的资源 (n)…”打开资源检查器）、子 Agent 开关（标签恒为“子 Agent”，徽标只数正在执行（`Running`）的子 Agent，0 时不画徽标，激活色属于展开一侧）、工作区按钮（文件夹 + 目录最后一段 + `▾`，菜单：在 VS Code 中打开项目/工作区、在资源管理器中打开项目/工作区；没有项目根时只显示工作区两项；解析不到 `code` 时隐藏 VS Code 两项）。
- 上条右侧：token 读数——`RC 98.5%` + 五段同尺寸斜四边形量规 + `62k/170k · 36%`（C / U · 百分比，窗口未知时只写 C）；整组是一个按钮（点击等同 `/compact`），悬停给固定五段 `↑输入 ↓输出 · R 缓存读 · W 缓存写 · RC 缓存命中率 · $成本 · C 上下文窗口`，缺数据写 0；量规三态（常态/警告/超限），U 或触发线未知时恒为常态。旁边还有缓存寿命小片与账号额度读数（见 02.10 / 03.5），额度读数与当前提供商不符时整段隐藏。

## 7.9 全局搜索与命令面板

- 一个覆盖层、五个来源：`Ctrl+P` 文件、`Ctrl+Shift+P` 命令、`Ctrl+Shift+F` 工作区文本；同一个手势再按一次关闭（手势属于来源，重复按不清查询）；标题栏放大镜是同一个动作的按钮；来源内还接受首字符前缀 `>` 命令、`#` 内容、`:` 会话、`@` 符号。切换前台会话即关闭。
- 文件来自 `FileIndex`（仓库内 `git ls-files`，否则有界遍历，遵守 `.gitignore` 与构建目录），匹配复用输入框 `@` 弹层的同一排序；内容来自 `GrepEngine`；会话来自会话目录（子会话与已删除会话不入列，归档带徽标、只读打开）；命令是静态表（行里带手势）；符号来自当前编辑器文档的语言服务器（上限 2000 后排序）。
- 刷新模型：每个来源“快照 + 后台刷新”，先用上一次快照立刻出列表，同时发起刷新；每次刷新带代号，换代后到达的答案丢弃；文件快照按工作区缓存；内容搜索 180 ms 去抖、同一时刻只跑一个。UI 线程每敲一键只做一遍快照过滤，默认上限 50 行（10–500）。
- 预览栏：命令与会话由行字段拼出；文件、匹配行、符号最多保留 256 K 字符、首 40 行或命中行 ±12 行、带行号，解码在后台线程，最近一个文件留在缓存里；读不到/空文件/二进制（首块含 NUL）给“没有可预览的内容”。
- 空与失败：列表为空时说清原因（没有会话、没有打开的编辑器文件、没有语言服务器、搜索失败带原因、首份快照还在读），以不可打开的 notice 行呈现。
- 可配置：`preferences.palettePerSourceLimit`（默认 50，10–500）与 `preferences.paletteExcludeDirectories`（目录名，任意层级整段匹配、大小写不敏感；留空只遵循 `.gitignore`）；配了排除目录时向引擎要 4 倍上限再过滤，过滤后仍超上限或引擎截断时状态行注明“只显示前 N 条”。

## 7.10 资源检查器

- 输入条“资源 ▾”菜单的“运行中的资源 (n)…”打开窗口覆盖层；列出**所有打开会话**（按会话分组，活动会话排最前，每组显示标题、数量、“当前会话”标记），按开始时间插入，行在结束前不重建。
- 内容：工具调用（谁在跑、耗时、参数摘要、实时输出尾部）与子 Agent（kind、状态、任务、耗时），各带停止按钮；两者混排在统一列表里。什么都没在跑时一行“打开的会话都没有正在运行的工具或子 Agent”。
- 线程模型：工具进度**不派发**（生产侧已限流每路每秒 ≤4 次、尾部 ≤16 KiB），快照线程只做查表 + volatile 字符串写；开始/结束走帧合并器；显示是拉模型，`Tick(maxLines, now)` 只在快照或行数上限变化时裁行。
- 停止的粒度：子 Agent 用 `SubAgentControl.Stop`（只杀该子 Agent）；工具调用**只停这一条**（`AgentHost.CancelToolCall`），回合继续，模型收到“用户取消了该调用”；排队中的子 Agent 没有停止按钮。
- 设置（`inspector` 分区）：行数 20–1000（默认 200）、刷新间隔 250–10000 ms（默认 1000）；行数上限再高也受生产侧 16 KiB 缓冲约束。
- 面板关闭（关闭按钮 / Esc / 点遮罩 / 窗口拆除）即 dispose：不持定时器、不订阅语言变化；关闭后这些成本为 0。

## 7.11 通知

- 唯一入口 `INotifications.NotifyAsync(level, title, body, key?, ct)`：开关关掉什么都不做；`IsBackground` 为真走系统通知，否则在窗口顶部居中弹 Toast。**任何界面功能要说“某件事发生了”都走这个入口**，不许自建 toast、横幅或第三方通知库。
- 四个等级决定等级条颜色与停留时长：`Info` 4 秒、`Success` 4 秒、`Warning` 6 秒、`Error` 8 秒；两行文本（标题说“发生了什么”，正文给“哪一次/为什么”），都进 `Strings.Notifications.cs`。
- Toast：最新在最上、最多 5 条；同 key 合并成一条并计数 `×N`（key 缺省是“等级 + 标题 + 正文”，重复到来重启计时）；到时先 `IsLeaving` 淡出下滑 180 ms 再移除；`IsHitTestVisible=False`，不挡点击；集合与计时只在 UI 线程动，`NotifyAsync` 可从任意线程调用。
- 窗口在最小化或没有 Forge 窗口在前台时才算后台。释放幂等：就地停计时器与字典，只在 UI 线程清空绑定集合。
- 通知权限引导（14f）：`INotificationPermissionGuide`（`NotApplicable`/`Unknown`/`Granted`/`Denied`）；`SendTestAsync` 真发一条测试通知并把状态落成 Granted/Denied；`OpenSettingsAsync` 打开平台页面（Windows `ms-settings:notifications`、macOS 通知偏好），Linux/NotApplicable 返回 false。设置分区 `notification-permission` 提供状态、发送测试、打开系统设置、`notificationPermissionReprompt`（再次提示）。
- 接入点（每条都带稳定去重 key）：回合/发送失败、提供商未配置、检查点失败、子 Agent 失败或停止、附件拒绝、图片拒绝、读文件失败与文件级上限、换模型后附件阻塞、步骤提交被拒、fetch/pull/push 失败、自动评审交接失败、扩展宿主失败、MCP 服务器失败、模型列表拉取失败、`settings.json` 回落默认、启动或数据库初始化失败、项目列表读取失败、彻底删除收尾重试失败、终端非零退出、文件保存失败、LSP 应用失败、评审保存失败、审批卡开始等待用户。
- 不接：生命周期对话框里当场可见的失败、上下文压缩、插话/排队回执、折叠与高亮降级、语言/模型切换、TODO 步骤提交成功。

## 7.14 本地化

- 界面语言中文 / English，切换即时生效（`Loc.Instance` + 编译索引器绑定）。
- 每个可见文案在 `Localization/Strings.<功能>.cs` 注册（`Register(key, 中文, English)`），`[ModuleInitializer]` 注册；同 key 两次注册不同文本直接抛异常；缺失 key 返回 `[key]` 且每个 key 只 Warning 一次。
- 格式：句式随语言，数字与时间不随区域——`TextFormat.Number` 千分位一律 `,`，标识符不分组，时间一律 `HH:mm:ss`，耗时写“4.2 秒 / 3 分 05 秒”。
- 存下来以后再显示的文本（启动诊断、提供商状态、通知、轮次脚注）存成 `LocText`，显示时解析；长生命周期所有者订阅 `LanguageChanged` 并向下刷新，逐行逐卡不订阅静态事件。
- 不翻译：模型输出、用户输入、文件内容与路径、插件文案、会话标题（默认标题按创建时语言生成并存库）、开发者才看的异常文本（英文）。
- “跟随系统”由纯函数 `SystemLanguageDetector.Resolve` 决定（文化名 `zh*` → Windows 注册表 `PreferredUILanguages` → … → `LC_ALL`/`LC_MESSAGES`/`LANG` → 英文）；注册表读取失败当作不存在，无 P/Invoke。
- 防回归要求（测试项目接线后由测试覆盖）：扫描 `src/Forge.App` 的 `.cs`/`.axaml`，`Strings.*.cs` 之外不得有中日韩字符；表完整性（中英齐全、英文无中日韩字符、占位符一致、XAML/C# 用到的键都已注册）。

## 7.15 首启向导与项目创建

- `OnboardingView` 是窗口内覆盖层，三步：界面语言（直接写偏好、当场切换，跳过也生效）、提供商（只显示状态并深链到 `provider` 分区，不重写编辑/测试/保存链）、通知权限（只经冻结接口读状态与打开系统设置）。
- 是否显示由 `ui_state` 的 `onboarding` 行决定（存在即“看过”，不是偏好）：该行不存在且库里没有**仓库项目**时才显示；已有仓库项目的安装视为非首启、静默补一条记录；`ui_state` 读不出来按已看过处理。
- 触发点在窗口、由应用程序开启：只有真窗口能显示覆盖层，自己造窗口的宿主（测试、录制）不置标志，所以它永远不会遮住工作台。
- “添加项目”是一次性选择：已有文件夹 / 克隆仓库 / 新建项目；三条分支共用同一个注册尾（`IProjectRegistry.AddAsync` + 刷新缓存 + 刷新两棵树），注册抛错时发错误通知而不是让异常逃进调度器。
- 克隆显示进度并可停止，取消或失败不留半截目录；窗口在克隆途中被关掉等同取消；完成通知在运行状态落定之后才发；超时失败呈现 `GitException.Message`（唯一说得清原因的一句）而不是一屏进度重绘的 stderr。

## 7.16 性能与布局纪律

- UI 线程只做渲染与输入；LSP、着色、Git、文件扫描一律后台线程，结果经不可变快照回到 UI。
- 树、列表、Diff 虚拟化；Diff 与编辑器增量渲染，不整体重绘；流式输出按渲染帧批量合并（每帧最多一次 UI 更新）。
- 工作台区域与面板必须按最终分配的宽高测量与排列：滚动视口不得沿用整窗口高度，分割/抽屉/最大化/缩放后 `ScrollViewer` 与虚拟化 `ListBox` 滚到末端要能完整看到最后一行——不用底部留白或滚动补偿掩盖布局错误；仍可见的面板不得在每次排列前临时排到零尺寸。
- 零分配细节：`NotifyingObject.SetAndNotify`、属性名缓存 `PropertyChangedEventArgs`、拖动路径不分配、`RegionWidthSolver` 纯函数、跟踪图标几何缓存。
