# 01 会话与工作区生命周期

会话是 FORGE 的工作单位：一个会话 = 一条对话历史 + 一个工作目录 + 最多一个活动 Agent 宿主。本文件说明会话如何创建、占用、只读查看、接手、分叉、合并、移除与恢复。

## 1.1 会话模型

- 会话元数据是 `forge.db` 的 `sessions` 列：项目、worktree、分支、父会话、Agent 种类、任务、归档状态、最后活动时间、谱系根、来源种类、前缀指纹。
- 状态三值：`Active`（可跑回合）、`Archived`（只读，进“历史”，可恢复会话或移除会话）、`Deleted`（只由启动自愈写入：目录被外部删除；行同样只读、可恢复或移除）。归档只改状态，不删任何记录、文件或目录；用户的“移除会话”是直接清除（见 1.7）。
- **一个工作区同一时刻只有一个活动根会话**，由部分唯一索引 `ux_sessions_occupancy`（`status='Active' AND parent_session_id IS NULL`）强制；占用键由存储层计算（规范化路径，Windows 大写）。冲突映射为 `WorktreeOccupiedException(HolderSessionId)`，界面进入占用对话框，而不是通用错误。
- 子会话带 `ParentSessionId` / `AgentKind` / `Task`，继承父会话的项目与 worktree；子会话不参与占用唯一索引。
- **Agent 会话（运行时见 02 §2.3）**：用户在一个活动根会话下手动增加的**用户驱动**子会话，共用根会话的目录（`parent_session_id` = 根、深度 1、初始上下文空白），不参与占用索引。它从属于根：根的忙判定包含它、根离开 `Active` 时它随之只读、移除（直接清除）级联；**只有根会话能改 git 状态**（可选的 Agent 种类不得持有 git 写与 PR 工具）。根与它之间唯一的通道是用户点名的 `message_session`。入口是 worktree 行“+”的第二项，常规对话不提供。回合进行中关掉它的标签不结束那个回合，重开同一子会话**回到仍在跑的那个视图**（不另建视图、不按存储回放）。
- 常规工作区 `General` 是单例项目（部分唯一索引保证），默认目录为 `文档/Forge/General`，可用 `FORGE_GENERAL_WORKSPACE` 覆盖。

## 1.2 三种会话环境

| 环境 | 工作目录 | 何时创建 | 特点 |
|---|---|---|---|
| 仓库 worktree 会话 | `<仓库>.worktrees/<slug>`（`SiblingOfRepository`） | 项目树上的“新建会话” | 新分支默认 `forge/session-MMdd-HHmmss`；不自动跟踪远程分支 |
| 常规（scratch）会话 | `scratch/<日期-标题>/` | 常规对话 panel 的“+” | 没有仓库，git 工具与 diff 面板按无仓库处理 |
| 自动化会话 | 暂存目录、指定仓库的 `forge/` 复用 worktree、或某会话下的 Scout 子 Agent | 自动化任务运行 | 带 `AutomationId` / `AutomationRunId`，树上有闪电标记 |

- **会话标题**：建会话时是创建默认标题（时间戳），发出第一条消息时本机按这条消息派生一个占位标题（取第一行、去掉代码/URL/路径/文件名，截成一个标签长度——24 字符），模型只能在这条消息开启的**第一轮**里经 `set_title` 换成任务名（3–6 词、用户语言，同样截成 24 字符），之后（包括关闭后重开）一律拒绝，用户手动重命名则永久优先——三者的优先级由 `sessions.title_source` 的一条条件写入保证。标题只影响显示：worktree 分支 `forge/<slug>`、目录名与提交说明沿用创建时的名字，改名不会动它们；派生只在本机发生，不额外发模型请求。
- 新建工作区对话框（标题「新建工作区」）：起点来自共享分支选择器（可含远程跟踪分支，先解析成提交再 `worktree add -b`，所以选 `origin/main` 不会把新分支的上游设成它）；名称实时校验（`git check-ref-format --branch`、本地重名），250 ms 防抖、后台校验、过期结果丢弃。
- 稀疏检出只在项目行“+”的新建工作区对话框中提供：`git worktree add --no-checkout` → `sparse-checkout set --cone` → `checkout`，任一步失败收回本次创建。
- 分叉/合并/移除等生命周期动作的 git 原语在 `Forge.Workspace`；会话记录与事务在 `forge.db`。

## 1.3 只读查看与“恢复会话”

- 打开会话从不改状态；非 `Active` 会话（历史行、按 id 打开、已归档、已删除）开成**只读标签**：不建 `SessionRuntime`，子 Agent 经 `ChildQuery` 回放，**不显示输入区**（composer 与旧只读条都不出现，标签只有转录；恢复会话入口在树的右键菜单）。
- 历史行（`Archived`，以及自愈产生的 `Deleted`）显示“恢复会话”：目录缺失时先重建，再走 `ISessionCatalog.ActivateAsync`（见 1.7）；目录在、但 `git worktree list --porcelain` 标为 prunable 或未列出时禁用并写 git 的说法（点击时后台重查，不信树上的旧读数）。
- 回合前校验（每个回合开始前后台读库）：会话仍是 `Active`，否则拒绝并提示“该会话已被接手”，释放 runtime 转只读；再读合并冲突快照与“工作区操作中”标志，命中则拒绝并暂停队列。
- 被拒时**消息不丢**：文本回到草稿（草稿非空时排到队首），只读标签不显示任何输入区；树上的“恢复会话”把草稿与排队消息带进新的活动视图。

## 1.4 接手（Handover）

把一个工作区的活动权从一个会话交给另一个会话，是**一个事务**（`HandoverAsync`），不是两步。

- 前置：先查目标/持有会话是否空闲（回合运行中、子 Agent 运行或排队、有排队消息、有未送达插话、正在交接、工作区操作中、合并冲突都算忙），忙时只给“等待 / 取消”，不排队、不强制；再过未保存缓冲区守卫，守卫后复查空闲。
- 对话框：未提交改动选“以旧会话名义提交”（默认）或“带进新会话”；新建会话时选上下文模式——**摘要（默认）/ 空白**，继续已有会话时不选模式。
- 执行顺序：读状态 → 需要时 `handover: <旧标题>` 提交（同一把路径门与护栏，不看逐步提交偏好）→ 构建上下文（摘要经 `HandoverSummary` 专用提示词生成一条用户消息，空白不带任何上下文）→ `HandoverAsync` 单事务换手（`BEGIN IMMEDIATE`，失败整体回滚）→ 新会话复制评审标记（失败只提示）。
- 成功：旧根降级为新根名下的归档 Agent 会话、其 Agent 家族（仍 `Active` 的与归档/已移除的）在同一事务内一并改挂到新根，打开着的 Active Agent 标签就地改挂、可继续对话；旧根的标签留在原地换只读的 Agent 视图（它已不是根），它的 runtime、终端与 `@` 授权随它结束；新会话以根视图打开、树刷新。角色以存储的 `parent_session_id` 为准，标签、runtime 与工具面（`extension_*` 只给 `Depth 0`）随它一起换。
- 失败：提交已落地时错误里写出提交 sha；摘要失败或取消不回滚已落地的提交；重试时工作树已干净。
- **Agent 会话**：忙判定同样包含它名下的 Agent 会话（回合、排队消息、未送达插话）；仍 `Active` 的 Agent 会话随接手会话改挂、保持可用（与「归档即换手」同规则），归档/已移除的原样跟随降级的旧根改挂——不复制、不重放；分支的「历史」组从此只有 Agent 会话行。

## 1.5 并行分叉（Fork）

在保持源会话继续跑的前提下，从某个提交点开出第二条独立分支。

- 入口：仓库项目的每个工作区行（主检出行与 worktree 行）和活动根会话行。
- 点击后后台读实时 HEAD：游离、未出生分支、非仓库即拒绝并通知；再读未提交改动与稀疏配置，打开对话框：新分支名（默认 `forge/fork-MMdd-HHmmss`）、未提交改动“先提交”（默认）/“照样分叉”、上下文模式（有源会话时）、稀疏与冷构建提示。
- 源会话忙时只给“照样分叉”。读 HEAD 前与执行前都重读源会话：已被接手或归档（不再是 `Active`）则拒绝，不建任何东西。
- “先提交”以 `handover: <源标题>` 走交接提交路径，起点是提交后的实时 HEAD；上下文先于 worktree 建好（摘要失败不建任何东西），再以新分支在起点建 worktree（带源的稀疏配置），最后建会话行（`fork_of_branch`、`fork_base_sha`、`lineage_root_id` 承自源，从不写 `parent_session_id`）并写首条消息。
- 上下文只有摘要（一条用户消息）或空白；todos、计划、评审标记都不复制。
- 任一步失败写明原因并收回本次所建（会话行软删后清除，再收回 worktree 与未移动的分支）；已落地的提交保留并写出 sha。
- **不复制 Agent 会话**：分叉只复制根会话；子会话留在原根下随之只读。

## 1.6 合并回与同步

分叉关系由“工作区最近一条记有 `fork_of_branch` 的会话”推出，树上的 worktree 行标“分叉自 <源>”并提供两个动作。

- **合并回 <源>**：在检出源分支的工作区 `merge --no-ff --no-edit`；目标工作树**不要求干净**（git 拒绝覆盖时原样转述文件列表）。
- **从 <源> 同步**：把源分支合进分叉分支，同一条路径。
- 目标空闲判定（活动标签忙原因 + 工作区状态）在确认前后各一次；通过后置“工作区操作中”、把目标活动标签置“正在交接”，合并前重读目标工作区当前检出分支（确认框可能久开）。
- 冲突：标记“合并冲突态”（该工作区不能开回合，分叉/合并/新建/归档/重命名禁用），对话框给“中止合并 / 稍后处理”，树上出现“中止合并”（`merge --abort`）。
- 源分支无人检出、改名或删除时降级为只给“推送分叉分支”（`push -u`），不做 PR、cherry-pick 或 rebase；已合入/已同步只通知。
- 合并回成功后给“移除分叉 / 保留”，走移除流水线（以源分支为守卫的 `baseBranch`）。

## 1.6b 归档即换手

归档 root 会话等于把工作区交给它最近的 Agent 会话（`ISessionCatalog.ArchiveAndPromoteAsync`，一个事务）：root 转 `Archived`、降级成继任者名下的归档 Agent 会话，继任者清空父指针与 `child_driver`、成为这个分支的 root，root 其余 Agent 会话（含已归档、已移除的）改挂到继任者下，所以历史里的 Agent 会话仍挂在分支的当前 root 下；没有 Agent 会话时只归档 root。树的“归档”、闲置自动归档（`Housekeeping`）、删除工作区前的归档都走这一条；Agent 会话行上的“晋升为主会话”是同一操作带指定继任者。归档 Agent 会话本身只归档它自己，该行进分支的“历史 (n)”。

## 1.7 归档、恢复、移除、关闭项目

### 归档

归档 root 会话走 `ArchiveAndPromoteAsync` 一个事务（见 1.6b），归档 Agent 会话只改它自己的状态；两者都只标记并把行送进“历史”，不删任何记录、文件或目录，分支与工作区原样保留。闲置自动归档与删除工作区前的归档走同一条路径。

### 移除会话

1. 重读会话：`Active` 拒绝（先归档）；不存在或状态已变化只提示。
2. 忙则列原因拒绝（回合、排队、子 Agent、交接中、工作区操作中或冲突）。
3. 一个确认框说明不可撤销：`PurgeAsync` 单事务删除会话及其子会话在 `forge.db` 的所有 `session_id` 行；再按会话 id 直接删除数据库外的附属内容（`artifacts` 表行与 `<UserData>/artifacts/<id>` 目录、评审标记/评论/结论、`ui_state` 里的会话输入区选择，即模型与推理档）。**不进回收站，也没有第二层“彻底删除”**。
4. **分支与工作区（worktree 目录）不因此删除或改动**；没有会话的工作区行仍留在树上，可再新建会话或单独移除工作区。分叉来源（`fork_of_branch`）记在会话上，所以把一个分叉工作区的会话都移除后，这条来源关系随之消失（分支本身不变，合并回/同步入口也不再出现）。
- 清理附属文件失败只警告（记录已删），失败 id 记入 `<UserData>/purge-pending.txt`，下次启动重试。**Agent 会话随根一并删除**，不单独提供入口。

### 移除工作区

计划与守卫不变（目录去向、未提交改动等删除守卫、未并入的分叉）；有活动会话 X 时按钮为“归档 X 并移除”。执行时先归档该目录下每一个未归档会话（归档 root 会把工作区交给它最近的 Agent 会话，所以循环到分支下没有 `Active` 会话为止），目录进回收站并 prune，然后按“新的先删”对目录下每个根会话（含历史会话，子会话级联）调用与“移除会话”**同一条**清除路径。目录进回收站失败时什么都不清除。分支从不删除。

### 恢复会话

历史行（`Archived`，或启动自愈产生的 `Deleted`）同一入口，根会话与 Agent 会话都能恢复：重读 → 目录不存在时重建（General 直接创建；worktree 先 prune 再以原分支 `worktree add`，分支已不在则停止；项目根/根检出缺失不重建）→ 目录存在时查 `git worktree list --porcelain`（prunable 或未列出则停止并写 git 的原因）→ `ActivateAsync`。
- 根会话：分支没有活动 root 就当上活动 root；已有活动 root 时改挂它名下成为 Active Agent 会话——恢复不弹占用对话框，接手语义只剩“新建会话”路径。
- Agent 会话：分支有活动 root 时挂到那个 root 下成为活动 Agent 会话（它原来挂在哪个历史 root 下不再重要）；分支没有活动 root 时它**成为这个分支的 root**——它原来挂着的那个父会话（归档或已移除）转成它名下的归档 Agent 会话（已移除的落回归档——目录刚被恢复重建），父会话的其它 Agent 会话（含归档与已移除）一并改挂到它名下；它本身就已经是 root 时不改任何关系（见上一行）。打开的标签按恢复后的角色重建（`SessionRoleRules`）：恢复成 root 的那张从 Agent 视图换成根视图（否则它跑的还是 `Depth 1` 的工具面），恢复成 Agent 会话的那张换成 Agent 视图并跟随新的 root。
- 重建成功但未激活时提示“目录已重建、会话未恢复”；恢复到已存在的目录只改会话行，不重读整盘 git。恢复工作区只重建目录，会话保持已移除。

### 关闭项目

软关闭（`projects.closed_at`），不删目录与会话记录；同一路径再添加时注册表复活原项目行，会话随之回来。关闭前任一忙即列原因拒绝。

## 1.8 树上的状态标记

项目树区分并显示：

- 项目行（工作区层，Bold 字重）、每个仓库项目的**第一个子行是仓库根检出**（`HEAD` 真实分支名，游离显示“游离 HEAD”，非仓库不出现）、其它 worktree 分组、会话行、子 Agent 行。
- 归档会话收进各 worktree 的“历史 (n)”；已移除（自愈）会话同样在其中。
- 没有会话的 git worktree 也有一行（刷新时从 `git worktree list` 补出）：可新建会话、显示、移除工作区、改名分支、分叉，与有会话的 worktree 行同一套菜单；分叉来源（合并回/同步）记在会话上，没有会话的行不显示这两项，裸库与锁定的 worktree 不出现。
- worktree 行标记：〔稀疏〕、〔目录缺失〕、〔已回收〕、〔git 标记为可清理〕、〔git 未登记〕、〔git 状态未知〕；标记决定哪些动作被禁用（原因写在 tooltip）。全部会话都已移除且目录不在的行才是〔已回收〕、整行变淡，只给“恢复工作区…”；没有会话、目录也不存在的 worktree 行标〔目录缺失〕，只留“移除工作区…”（清掉 git 登记后行随之消失）。
- 已移除根会话（自愈）：目录在时标〔已移除〕，不在时〔目录已回收〕，只能只读打开、恢复会话或移除会话。
- 行尾“+”分两种：项目行是分支加号（新建 worktree 分支），常规对话/worktree 行是纯加号（新建会话）；**Agent 会话把 worktree 行（含仓库根检出行）的纯加号改为两项菜单**：“新建会话” / “新增 Agent 会话”，后者挂到该 worktree 的活动根会话，没有活动根会话、合并冲突、工作区操作中时置灰并写入 tooltip。“新增 Agent 会话”本身是二级菜单（白底、比一级菜单宽，父行箭头 6×6）：Worker（默认，粗体）在首位，其余内置与用户自建种类按模板顺序，每行是“种类名 + 不超过 40 字的简述”，不能当 Agent 会话的种类置灰并说明原因；选定的种类就是该会话的身份，之后不可更换（输入区没有种类选择）。一个根名下的 Agent 会话数量不设上限（能跑几个由树内并发名额排队决定）。
- **Agent 会话行**：与根会话行同级并列（同一 worktree 行下、排在根之后），带区分标记；名字默认 `<Agent 种类> <序号>`（种类建时固定，用户手动改过名后不再覆盖），**树行与标签页可双击改名**，`@` 弹层的会话组显示同一个名字并随改名立即更新；点行在主组打开或切到它的标签，根会话进“历史”时随之。
- 行内点击即执行该行动作（会话行打开、有子项的行展开、worktree 行新建会话、子 Agent 行打开其标签）；点行内按钮只执行按钮。
- 刷新时后台先读 `git worktree list --porcelain`，再为每个登记了的工作区目录（有会话的与没有会话的都算）读一次 HEAD 种类、合并/变基进行中与稀疏配置，并读项目默认分支；读数缓存 15 秒（项目根 HEAD 也是这份缓存），最多 4 并发；只有分支、检出、worktree 或合并被改动的流程才作废缓存，归档/晋升/改名/恢复到已有目录这类只改会话行的刷新先用缓存立即重排，用过过期答案再在后台重读一次。没有会话的 worktree 行因此同样显示〔稀疏〕、游离 HEAD 与合并/变基造成的禁用，不另走一套读法。打开菜单不跑 git、不读库。

## 1.9 回合与检查点

- 每个主轮次开始/结束（含失败、取消）用 `SnapshotTreeAsync` 取树哈希写 `turn_checkpoints`（仅 git 会话）；轮次号从 `MAX(turn_checkpoints, turn_metrics)+1` 续接——`turn_metrics` 两种会话每轮一行（含失败轮，见 Docs/12 §12.2），General（非 git）会话重开窗口不再从 1 重新数。
- 树哈希实现把真实索引复制到临时文件后 `add --all` + `write-tree`，不改用户索引/HEAD/分支/stash。
- “已改动”面板按轮次列出差异时用的就是这些树。
- **Agent 会话**按**自己的会话 id** 记检查点与指标，轮次从 1 独立编号，其“已改动”面板按自己的轮次显示 diff；每轮指标只读**自己实例**的累计计数（不重复记根的 token）。已知限制：检查点是整棵树的快照，根与子会话回合**时间重叠**时双方这一轮的 diff 互含对方的改动（本期不做按工具调用归属过滤）。
