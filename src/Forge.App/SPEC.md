# Forge.App

Forge 的 Native AOT 桌面主程序(Avalonia 12.1.x,仅桌面)。承载组合根与停靠式工作台:把 `forge-core`(Agent 循环、存储)、`forge-workspace`、`forge-mcp`、`forge-editor`、`forge-host-client`(插件/CodeMode 代理)与 `forge-approval` 串成一个进程。

## 边界

- Native AOT(`IsAotCompatible` + `PublishAot`),依赖闭包不含 Roslyn、`AssemblyLoadContext`、`Forge.Scripting`/`Forge.ScriptExecutor`;只用源生成 JSON(`SettingsJsonContext`、`WorkbenchJsonContext`);无 DI 容器/MVVM 包(手写 `INotifyPropertyChanged` + `ICommand`)。
- **不实现任何存储或 Git 管道。** 只经 `ISessionStore`/`ISessionCatalog`/`IProjectRegistry`/`ITodoStore`/`IUiStateStore`/`ITurnCheckpointStore`、`GitCli`、`WorktreeManager`、`SpecGraph`、`ReviewStore` 组合;`src/Forge.App` 中不得出现 `SqliteConnection`、`CREATE TABLE`、`write-tree`、`GIT_INDEX_FILE`。
- 不直接读审批数据库做判断(哈希经 `plugins.status` 取);为状态面用只读连接数 `plugin_approval` 的行数,进程里不持有任何可写审批连接,也不建表、不迁移。计数只在文件不存在(不打开、不创建文件/`-wal`/`-shm`)或没有 `plugin_approval` 表时返回 0;其余错误上抛,设置页的 `approvals` 分区与输入框上条的计数显示"不可读",不把损坏或锁住的库显示成没有插件。
- UI 线程不碰存储:Microsoft.Data.Sqlite 的 `*Async` 是同步执行的,所以所有存储/SQLite/文件调用(含归档、重命名、`ui_state` 写入、TODO 增删)都经后台助手,不在调度器上 await。唯一例外是退出:最后一次布局保存在后台执行,但 UI 线程最多等它 3 秒(超时只记 Trace),保证关窗时快照尽量落盘又不卡死。
- 无 P/Invoke;进程归属是 `forge-extension-host` 的职责。App 只启动/重启 Host 子进程并保证退出时杀树等待。
- 工作台布局自写(`Workbench/`),不用任何停靠框架;原内化的 Dock 已移除。

## 组合根

构造顺序即依赖方向,拆除严格逆序:`AppPaths` → (审批数据库路径,不打开)→ `ExtensionHostSupervisor`(`--worker`/`--executor` 显式传路径)→ `WorkspaceServices` → `McpServices` → `EditorServices` → `ProviderSettings` + forge.db 上的 5 个存储 + `TurnCheckpointService` + `WorktreeService` → `AgentRuntimeManager`。审批库归 Host 所有,App 只拿到 `<host 数据目录>/approvals.db` 的路径。数据根默认 `%LOCALAPPDATA%/Forge`,`FORGE_DATA_DIR` 覆盖;常规工作区默认 `文档/Forge/General`,`FORGE_GENERAL_WORKSPACE` 覆盖。开发验证一律设置这两个变量,不写真实用户目录。

**模型提供方(多个已连接 + 一个默认)。** `settings.json` 的 `providers` 段是唯一配置源:`{version, defaultId, items[]}`,每条含 `id`/`preset`/`name`/`protocol`(`openai-compatible`|`anthropic`)/`baseUrl`/`auth{kind,envVar,secretRef}`/`models`/`defaultModel`/`thinking`/`maxOutputTokens`/`modelMeta`/`headers`。旧的单 `provider` 段只在第一次读到时迁移成一条(Anthropic 协议 → Anthropic 预设,其余 → 自定义 OpenAI 兼容);第一次保存写 `providers` 并删掉旧段。文件按 `JsonNode` 整份读改写,`preferences` 与未知字段原样保留,JSON 无效时拒绝保存而不是覆盖。完全没有配置时载入一条未保存的默认 Anthropic 条目,让设置页与输入框有可填的对象(它的状态如实显示缺密钥/待登录)。
- **密钥库。** 界面粘贴的 key 存 `<数据根>/provider-secrets.json`,AES-GCM,密钥是 `<数据根>/provider-secrets.key`(32 字节,非 Windows 上 `0600`),`settings.json` 只存 `secretRef`;环境变量优先于库内密钥,行内显示「环境变量 key · VAR · 托管中」。这是防误泄露与云同步,不承诺抵挡能读用户目录的本机攻击者——为此不引入 DPAPI 包,也不在 App 里写 P/Invoke。库损坏时 `Problem` 明确报出来,绝不把"读不出"当成"没有密钥"再覆盖写入。
- **预设目录**(`Forge.Core.Providers.ProviderPresets`):Anthropic(产品默认)/OpenAI/GitHub Copilot/OpenRouter/Kimi For Coding/Meta/OpenCode Zen/OpenCode Go/xAI/DeepSeek,外加无 URL 的「自定义 OpenAI 兼容」。每家给协议、base URL、环境变量名、文档链接、种子模型与是否支持 `/models`;模型 id 会变,种子只是离线首屏,列表以服务端为准。
- **三种认证。** `api-key`(库或环境变量)、`claude-subscription`(复用本机 `~/.claude/.credentials.json`,距过期 5 分钟内自动刷新并写回;推理请求带 `anthropic-beta` 与 Claude Code 身份 system 首块)、`github-copilot`(设备码 → `ghu_` token → 会话 token,`Copilot-Integration-Id: copilot-chat` 必须与铸 token 时一致,base URL 取响应里的 `endpoints.api`)。凭据在首次流读取时才解析(`CredentialedChatProvider`),首事件之前收到 401 会刷新后重试一次;第二个事件之后不重试,否则会重复输出。
- **模型元数据。** provider `/models` 返回的上下文窗口与价格折算成每百万 token 存进进程内缓存(`ProviderModelCache`),与内置表、用户 `modelMeta` 组成「内置 → 上报 → 用户」的合并链,未知的一半保持未知。刷新是显式动作,启动时不访问网络。
- **运行时。** `ProviderServices.CreateProvider(ModelSettings)` 按 `ModelSettings.ProviderId`(空 = 默认)构造,未知名回落默认;`Forge.Core/Providers/Internal/ChatProviderPipeline` 把重试作为中间件套在端点上。composer 的模型弹层列所有已连接提供方的并集,多于一家时每行右侧显示提供方名,选中行同时决定 `ProviderId`,新会话默认值仍只有模型与强度。
- **两个写者共用一个闸门。** `preferences` 与 `providers` 都会把整份 `settings.json` 读—合并—原子写;`SettingsFileMutex` 按路径互斥,否则后写者会把先写者的分区合并丢(`AtomicFile` 只保证文件完整,不保证合并正确)。文件根不是对象或 JSON 无效时拒绝保存,原文件保持不动。
- **先提交配置、再写密钥。** 编辑提供方时先把定义写进 `settings.json`,成功后才把用户输入的密钥写进密钥库:配置保存被拒(无效 JSON、写失败)时,已有提供方的旧密钥保持原样。只有"从服务端刷新模型"会先落密钥,因为那次请求本身要用它。新建提供方的 id 对已连接列表去重(同名加序号),保存按 id 匹配,所以两个同名提供方不会互相覆盖。
- **设置分区 `provider` 与两个窗口。** 分区列出已连接提供方:名称、凭据摘要、状态点(已连接/缺密钥/待登录/配置有误)、「编辑提供方」按钮、「(眼睛)N 个模型」按钮(打开模型元数据窗口),末尾是「+ 添加服务器」。编辑对话框(模态)有预设、名称、base URL、认证方式、环境变量、粘贴密钥/清除密钥、模型清单(可手加、可从服务端刷新)、默认模型、思考强度、最大输出、`设为默认`、删除(两次点击);Claude 与 Copilot 在这一页做登录(前者只显示本机 CLI 的登录状态,后者走设备码并显示代码与链接)。模型元数据窗口(同一提供方单实例、非模态)按模型编辑上下文窗口与四档单价,保存写回 `modelMeta`,空值不写 0。文案在 `Localization/Strings.Providers.cs`(`providers.` 前缀)。

## 关键决策

**面板滚动边界。** 工作台的区域和面板必须按最终分配的宽高测量与排列,滚动视口不得沿用整窗口或整区域的高度。分割、抽屉、最大化/恢复及窗口缩放后,`ScrollViewer` 与虚拟化 `ListBox` 滚到末端应能完整看到最后一行;不可用额外底部留白或滚动事件补偿掩盖布局错误。仍可见的面板不得在每次排列前临时排列到零尺寸,避免改变其滚动偏移。

标题栏 logo 尺寸为 18×18 DIP;PNG 与多尺寸 ICO 均保留源图的透明通道,不得合成灰色或主题色背景。

**应用标识与启动窗口。** 标题栏以 `Assets/forge.png` 替代原来的 Forge 文本,窗口标题仍保留 Forge 供任务栏与辅助功能识别。PNG 为提供的原始 logo;同源的 `Assets/forge.ico` 含 16/24/32/48/64/128/256 像素图层,经 `ApplicationIcon` 嵌入 Windows 可执行文件(安装后的程序与默认指向该程序的快捷方式使用同一图标),并复制到发布目录供安装打包引用。所有窗口通过应用样式共用该图标。主窗口启动居中于所在屏幕的 `WorkingArea`,不占任务栏;按桌面缩放换算尺寸并计入原生窗口边框。可用区域小于通常最小尺寸时降低最小尺寸,避免窗口底部或右侧越界;打开后用实际屏幕、桌面缩放与边框再校正一次,不在用户后续移动或调整尺寸时重新居中。

**偏好、文案与设置分区。** 三件共用的底座,界面语言、字体、终端、Git/PR、扩展与审批五个功能都从这里取,不再各写一份。

- **偏好。** `Preferences/AppPreferences.cs`:`AppPreferences` 的 setter 就是校验器(空字体族回退默认值,字号夹到 9–28),改完立刻生效;`PreferencesStore` 读写 `settings.json` 的 `preferences` 段。写回先把整份文件读成 `JsonNode`,只替换 `preferences` 节点,再用 `Forge.IO.AtomicFile` 原子替换,因此 `provider` 段(仍由 `ProviderSettings` 读)和任何未知字段原样保留。读写都在线程池(`LoadAsync`/`SaveAsync` 内部 `Task.Run`),UI 线程不碰文件;`LoadAsync` 只读不写,也不发通知(加载发生在窗口绑定之前,语言由组合根自己推给 `Loc`)。只有用户改了偏好才写:每次修改重启 500 ms 防抖窗口,窗口结束在线程池写一次;`DisposeAsync` 强制把待写的改动落盘(组合根拆除时调用)。文件损坏或 `preferences` 段无效时用默认值并填 `LoadProblem`,绝不因加载覆盖文件;第一次写入前先把损坏的原文件复制成 `settings.json.bak`,且只备份一次。源生成 JSON 走新增的 `PreferencesJsonContext`。
- **文案。** `Localization/Loc.cs` 是实时文案表:`Register(key, 中文, English)` 一名一键;`Language` 的 setter 把 `System` 解析成具体语言(永不为 `System`),切换时依次发出 `PropertyChanged("Item[]")`、`PropertyChanged("Item")` 与 `LanguageChanged`——Avalonia 编译索引器绑定(`{Binding [Key], Source={x:Static loc:Loc.Instance}}`,AOT 安全)只认 `Item`,只发 `Item[]` 会让所有绑定文本停在旧语言。缺失 key 返回 `[key]` 且每个 key 只 Trace 一次;同 key 两次注册文本不同直接抛异常(文本相同则幂等)。每个功能一张表:新建 `Localization/Strings.<功能>.cs`,类名 `<功能>Strings`,键名带功能前缀,在 `[ModuleInitializer]` 里调用 `Loc.Register(...)` 注册——没有共享清单文件,并行功能不会互相冲突,`Loc.EnsureRegistered()`(组合根启动时调用)因此只保住“所有表已注册”这个顺序点。通知按订阅者逐个 try/catch:某个订阅者抛错不能中断整批刷新(注意:Avalonia 对同一 INPC 源只挂一个弱事件订阅,其内部某个绑定抛错仍会截断其后的绑定,见下方 headless 测试一条)。“跟随系统”保留 `InvariantGlobalization`,由 `SystemLanguageDetector.Resolve`(纯函数,输入显式传入)决定:文化名为 `zh*` → Windows 注册表 `PreferredUILanguages` → `MuiCached\MachinePreferredUILanguages` → `International\LocaleName`(注册表优先于环境变量,Git Bash 会把 `LANG` 设成英文)→ `LC_ALL`/`LC_MESSAGES`/`LANG` 第一个已设置的 → 英文;注册表用 BCL 的 `Microsoft.Win32.Registry`,无 P/Invoke,读失败当作不存在。macOS 从 Dock 启动常无 `LANG`,会落到英文(未验证)。语言在设置分区 `language`(`Localization/LanguageSettingsViewModel.cs`:跟随系统 / 中文 / English,语言名不随界面语言变)。
- **设置分区。** `Preferences/SettingsSection.cs` 的 `SettingsSections` 是分区注册表:`Add` 按 `Order` 升序插入(同序保持加入顺序),id 重复抛异常;分区标题是 `Loc` key,`SettingsSection.Title` 在 `Loc.LanguageChanged` 时由设置视图模型重新抬一次。注册表由组合根创建并暴露成 `AppComposition.Settings`:功能在 `AppComposition.Create()` 里 `Settings.Add(new SettingsSection(id, 标题 key, order, 该功能的设置视图模型))`,再在 `App.axaml` 加一个按该视图模型类型的 `DataTemplate`,不碰设置页本身。设置是**独立窗口**(`Settings/SettingsWindow`,1040×760,最小 720×480,`BorderOnly` + 自绘标题行):左侧分区导航按 `AGENT` / `界面` / `系统` 三组排(`SettingsGroups`,每行图标来自 `Resources/Icons.axaml` 的 key),右侧 `ScrollViewer` 里一个按选中分区 `ViewModel` 的 `ContentControl`;默认选中 `provider`。窗口宽度小于 880 DIP 时左栏自动收成 48 DIP 的图标条(每行只剩图标 + tooltip),标题行的按钮另有一次手动收起,手动状态优先于宽度判定;两种状态都保留全部分区的入口,不出现"窗口窄了就没有模型分区"的情况。导航用 `Button` + `Click` 而不是 `ListBox`:分组标题不是可选中的条目。现有“提供方”“路径与服务”已改成 `provider`、`paths` 两个分区(顺序来自 `SettingsSectionIds`),内容与行为不变;git 功能新增 `git` 分区(拉取策略 `ff-only`/`rebase`/`merge` 与网络超时 10–600 秒,偏好在 `AppPreferences` 里同名属性、setter 即校验器,存 `settings.json` 的 `preferences` 段)。同一分区还有等待 PR 检查的四项:轮询间隔 `GitChecksPollSeconds`(默认 30,夹到 10–300)、最长等待 `GitChecksMaxWaitMinutes`(默认 30,夹到 1–180)、完成时系统通知开关 `GitNotifications`(默认开)、`gh` 可执行文件路径 `GitGhPath`(默认空 = 用 PATH 里的 `gh`,保存时去首尾空白,设置页输入框占位符是 `gh`)。这四项都在每次使用时从实时偏好读取,改完不用重启:`gh` 路径在加载偏好之后才有值,所以组合根传给 PR 工具和 Git panel的是 `ConfiguredGh`/`ConfiguredPrPlatform`(每次调用取当前路径,路径没变就复用同一个 `GhCli`),轮询时间由 `GitToolPreferences.ChecksOptions` 每次现算。设置页自身的文案(面板标题、两个分区标题、路径行标签、两个按钮)注册在 `Localization/Strings.Core.cs`,语言切换时随 `LanguageChanged` 刷新。输入框上条的四枚计数各开一个只读分区:`approvals`(审批库记录:插件 id、版本、状态、更新时间,库不可读时说“不可读”)、`skills`(`SkillCatalog.Discover` 的结果:名称、描述、SKILL.md 路径)、`mcp`(`mcp.json` 的服务器:名称、状态、启用与否、最近错误)、`tools`(活动会话的工具名清单,外加一行扩展宿主的插件/工具/命令总数,后者原先是状态栏的内容)。四个分区的视图模型在 `ViewModels/Settings/InstrumentSettingsSections.cs`,共用 `App.axaml` 里一个按键的 `InstrumentSectionBody` 模板;正文在分区被选中或页面打开时才读源(审批库与技能目录走线程池),语言切换重建行。`provider` 分区补一行提供方状态("提供方:…"),这条句子原先只出现在窗口状态栏。
- **在 headless 测试里切换语言**:前一个 headless 会话的控件被 Avalonia 静态量(`XamlIlRuntimeHelpers` 的 `s_lastApplication`、合成器序列化队列)强引用,回收不掉;它们对 `Loc.Instance` 的绑定在下次切换时跨线程抛错,截断同一弱事件订阅里新窗口的绑定。生产里只有一个 UI 线程,不会发生。因此即时切换测试放在独立项目 `tests/Forge.App.LiveSwitch.Tests`,整个程序集共用一个 `HeadlessUnitTestSession`;`Forge.App.Tests` 里不要写依赖 XAML 直绑 `Loc` 实时刷新的断言。所有 `LanguageChanged` 订阅者记下创建线程,收到别的线程的通知就忽略。
- **DispatcherTimer 与释放。** `DispatcherTimer.Stop()` 只是停用,调度器下次轮询才把它移出列表;不再泵的调度器会一直持有 `Tick` 目标。长生命周期所有者在 `Dispose` 里停止计时器并解开 `Tick`(`MainWindowViewModel`、`FilesPanelViewModel`);`AppComposition.DisposeAsync` 释放实现了 `IDisposable` 的设置分区视图模型。

**工作台布局。** 三个区域按角色命名,不按位置:项目区、主区、检视区。默认顺序 项目 | 主 | 检视,可以拖拽互换,内容跟着角色走。

**Git panel的 PR 部分(等待检查、通知、评审线程)。** 全部在 `Git/`,面板只拿一个可空的 `GitPrServices(Platform, Poller, Options, Notifier, Post)`:为空就是纯本地 git 面板,永不启动 `gh`。

- **读 PR 是第二阶段,不占 `IsBusy`。** 本地读完后,仅当仓库有远程且当前在某个分支上才去问平台(本地独立仓库、分离 HEAD 都不会启动 `gh`,现有测试仓库因此不受影响)。顺序:`GetAvailabilityAsync` → `ViewPullRequestAsync`(当前分支)→ PR 存在时 `GetReviewThreadsAsync`。都在线程池、挂在可取消的 CTS 上,新一轮读取、清空上下文、`Dispose` 都会取消上一轮;结果回到 UI 线程再套用,过期的结果丢弃。`gh` 缺失或未登录只影响 PR 部分:显示一块提示(`git-gh-not-ready`)加平台给的原因,本地 git 照常;“没有 PR”“读取失败”各是一行说明。可用性不缓存,每次刷新重问(调用次数可预测)。
- **等待检查。** “等待检查”对已加载的 PR 都出现(不看 PR 状态,字面照规格;已合并/关闭时结果就是 `NotOpen`)。点击后 `PrWatcher` 在线程池跑 `PrChecksPoller.WaitAsync`(与 `pr_checks` 工具同一个轮询器),每次读数和最终结果经 `Post` 缝合回 UI 线程,面板显示“通过 n · 失败 n · 进行中 n”、合并状态和一句结论(12 种 `PrWaitOutcome` 各有本地化文案,需要处理的用错误色)。取消后不再投递任何东西(包括已排队的读数、结果和通知),取消不发通知。每个 worktree 一个监视(`WorktreeState.Watch`),切走再切回仍在;正在运行的监视不被 16 项上限驱逐;启动它的会话关标签或归档(`MainWindowViewModel.ReleaseSession`)、面板 `Dispose` 时取消。
- **上条的 CI 标记只反映监视器**:等待中 `CI …`(看到失败检查即 `CI ✗`),结束后 `CI ✓`(就绪)/`CI ✗`(检查失败)/`CI –`(无 CI)/`CI !`(其余需要看一眼的结果),PR 已合并或关闭则清空。没有被动拉取检查快照,所以没点过“等待检查”的分支不显示标记(偏离:规格措辞可读成常驻指示,这里只做监视器驱动的一版,免得后台自己轮询 gh)。
- **系统通知。** `SystemNotifier`(`ISystemNotifier`)在等待自然结束时发一条:标题“Forge:PR #n”,正文就是结论句,按语言取字。受 `GitNotifications` 控制(每次调用读),失败只 `Trace` 一行 `[notify]`,绝不抛出,单次最长 5 秒,超时杀整个进程树。Windows:`powershell.exe -NoProfile -NonInteractive -Command` 跑固定脚本经 WinRT `ToastNotificationManager` 弹 toast,标题和正文只通过环境变量 `FORGE_NOTIFY_TITLE`/`FORGE_NOTIFY_BODY` 传入并用 `CreateTextNode` 放进 XML,**不会**拼进脚本,所以 PR 文本无法注入;**未打包程序没有自己的应用标识,toast 显示为“Windows PowerShell”发出**(给 Forge 自己的标识需要带 AppUserModelID 的开始菜单快捷方式,未做)。macOS:`osascript` 的 `on run argv`,文本作参数传入;Linux:`notify-send --app-name=Forge -- 标题 正文`。**macOS 与 Linux 两条路径只按工具文档写成,没有在对应系统上运行过**;Windows 路径在开发机上跑通(退出码 0)。
- **评审线程区(只读)。** 未解决的排在前面,每条显示 `路径:行`(过时线程用原始行)、已解决/未解决与过时标记、第一条评论(作者 + 截断到 400 字)、回复数、以及线程里**最新一条带 agent 标记行**的回复(`PrReplyLedger.TryParseMarker`)的结论(已应用 abc1234 / 反驳 / 需澄清)和去掉标记行的回复正文。回复、解决是 agent 工具的事,面板不提供。语言切换时按新语言重建条目。
- **截图按钮。** 有 PR 且项目声明了截图命令时,PR 分组显示“截图”按钮,旁边显示将要执行的命令;点击即运行(用户点按钮本身就是确认,不再弹审批),与 `pr_screenshots` 共用 `ScreenshotRunner`(执行命令在池线程,受 `.forge/screenshots.json` 的 timeoutSeconds 约束),结果写进面板结果区与失败提示。
- **接缝(给测试)。** `GitPrServices.Post` 是 UI 线程投递缝合(默认 `UiThreadDispatcher.Instance.Post`);`PrWatcher` 的构造参数 `post`/`onProgress`/`onCompleted`;`SystemNotifier(enabled, run, platform, time)` 的进程运行器、平台、时钟均可注入,`CreateStartInfo` 是纯函数(`internal`),命令行参数可直接断言;轮询器的 `TimeProvider` 决定等待时钟。

**会话运行。** 一个主会话一个 `AgentHost`(`AgentRuntimeManager` → `SessionRuntime`),各自取消源,可并发;关标签不取消运行;重开/取消归档走 `ResumeRootAsync`。在项目上新建会话 = 新 worktree(`SiblingOfRepository`:`<仓库>.worktrees/<slug>`),分支名与起点在“新建分支”对话框里选:起点是那份共享分支选择器(与改动面板的比较基线同一个 `BranchPickerViewModel`/`BranchPickerView`,这里不隐藏当前分支),名称预填 `forge/session-MMdd-HHmmss`、输入后 250ms 防抖校验(空 / `git check-ref-format --branch` 不过 / 本地已有同名分支,校验在线程池、结果回 UI 线程、过期结果丢弃),只有合法且未被占用的名字才允许创建;取消/Esc/关窗不建任何东西,绕过对话框的非法名或已存在分支仍走既有失败通知;**新分支从所选起点分叉**:起点先解析成它的提交再交给 `git worktree add -b`,所以选 `origin/main` 也不会把上游设成 `origin/main`(新分支不跟踪任何远程分支,`↑a ↓b` 要用户自己 `push -u`);常规会话在 `scratch/<日期-标题>/`。会话工具 = 宿主工具 + `run_code` + git 工具(`SessionRuntime.BuildTools()`,`AgentRuntimeServices.Git` 可空注入;git 工具不进 `run_code` 的脚本注册表,脚本调用绕过逐次审批呈现)+ 文件与 shell 工具(`AgentRuntimeServices.FileTools`,由 `Forge.IO.FileTools` 一次构造、全会话共享,取会话 worktree 作为工作区)。文件工具同样**不进** `run_code` 的注册表:脚本里的 `bash` 不会经过逐次审批呈现。它们读选项的工厂是 `ToolPreferences.From(偏好)`,改 `settings.json` 里的 `toolsShellPath`/`toolsRipgrepPath`/`toolsBashTimeoutSeconds` 不需重启(无设置页,只能手改文件——见推迟)。运行时的释放点在:归档、标签已关且该回合结束、组合根拆除前(`MainWindowViewModel.Dispose` 先于 `AppComposition.DisposeAsync`)。检查点快照失败不把会话卡在“运行中”:记入会话通知,状态重置与 `TurnCompleted` 放在嵌套 `finally`。

**步骤提交(`StepCommitter`)。** TODO 条目从非 done 变成 done 时(只有 Agent 能改状态:面板不再有勾选框,见下方“TODO 面板”),把会话 worktree 里全部未提交改动提交到会话分支;开关 `gitStepCommits`(默认开)。子会话(`ParentSessionId` 非空)继承父会话的 worktree,其步骤一律跳过(不把父会话的改动卷进子步骤);无 worktree 的常规会话跳过。范围是 `add -A` + `commit`(会话 worktree 专属),提交说明优先 `commit_subject`、否则条目标题,正文是 summary;verification 不进提交说明。失败(钩子拒绝、冲突中、游离 HEAD)不回滚 done:工具结果与 TODO 行显示失败原因并提供“重试提交”;提交尝试失败后把 index 复位到 HEAD(mixed `git reset`,不动工作区),被拒绝的改动回到未暂存。晚取消:提交对象与 ref 已存在、只差慢 `post-commit` 钩子时被取消(git 被杀),重读 HEAD,前进了就把新 sha 记到该步骤并报已提交;取消发生在 `git add` 阶段则照常抛取消。同 worktree 的提交按路径门串行,不同 worktree 并行。计划摘要(`plan_summaries`)加上各步骤的 sha/summary/verification 由 `PrBodyRenderer`(Workspace)渲染成 PR 正文。

**事件路由与渲染。** 按 `AgentEvent.AgentId` 分发到各自的轮次卡模型,子 Agent 文本不进主会话。所有非文本事件经 `FrameCoalescer<AgentEvent>` 合并:生产者在任意线程无锁入队(`ConcurrentQueue`),只有当前没有已排队的 flush 时才 `Dispatcher.UIThread.Post` 一次(`DispatcherPriority.Background`,用 `Interlocked` 标志控制);一次 flush 在 UI 线程按入队顺序处理当前积累的项目,单次上限 `MaxItemsPerFlush`(2048),超出留到下一帧。优先级选 `Background` 而非 `Render`:skill 建议大批量/低优先级更新用 `Background` 以免挤占输入与渲染,且 flush 本身不占用渲染帧;持续流下仍是每调度周期最多一次 UI 更新(≈ 每帧一次),无需 `TopLevel.RequestAnimationFrame` 或 16ms 定时器。文本增量在后台线程合并进 `TranscriptViewModel` 的 pending 缓冲,flush 由同一个合并器调度:每次 flush 先排空文本、再按 FIFO 处理非文本事件,所以文本落在其后的非文本事件之前;非文本事件间顺序与 Core 发出顺序一致。会话释放时合并器停止调度并丢弃未处理项,释放后不再往 UI 投递。流式增量收进 `TextSegmentViewModel` 段落(≤2048 字、段落边界收口),一次 flush 只重写未闭合段,避免整段回复反复复制。文件树、规格树各自展开成一个 `RangeObservableCollection` 行列表(改动 diff 走 AvaloniaEdit 文档,不再是行列表)配 `ListBox`/`VirtualizingStackPanel`(展开 = 区间插入/移除),树/行视图模型、`FileIndex` 与规格图读取都在线程池构建、UI 线程一次 `ReplaceAll`。轮次卡头“第 N 轮 · 时间 · 耗时 · 输入/输出”:`AgentTurnCompleted` 是实例累计用量,卡上显示本轮差值;子 Agent 用 `AgentSubAgentFinished` 的本 run 用量;未上报一律显示“—”。

**子 Agent 区。** 每个运行/排队中的子 Agent 一个标签,标签底部唯一的状态栏(状态、任务、模型、用量、实时耗时、"停止" → `SubAgentControl.Stop`),无输入框;标签携带所属主会话、绝不跨会话。结束的按顺序收进标题栏末端"已结束 (n)"(20px 扁平按钮 + Flyout 列表),选中后从子会话存储经 `TranscriptReplay` 重放为只读标签。"已结束"列表也算内容:没有未浮动的标签但有已结束条目时,整块仍留在布局里(标记为 `TabGroupModel.KeepsVisibleWhenEmpty`,由视图模型按条目数设置);两者都没有时整块从布局移除,再出现时按原比例放回。会话底部“子 Agent · 收起/展开”开关(展开时芯片为激活态,徽标给出正在运行的子 Agent 数)是手动收起入口,收起后本会话内不再自动弹出:收起就是把这组 panel 缩小成标题栏(标签、“已结束 (n)”与“+”都还在),标题栏的还原按钮能直接展开,两处是同一个状态(`WorkbenchLayout.IsBottomMinimized`,与 `SessionWorkspaceViewModel.SubAgentsCollapsed` 双向同步;启动时先由布局快照决定一次,之后以会话自己的选择为准)。**只有一个写入口**:除标题栏那个还原按钮(它长在 panel 里,只能经 `OnWorkbenchPropertyChanged` 回报)之外,展开一律是写会话标志再经 `SyncSubAgentRegion` 推到布局——树里的子 Agent 行与新建终端都调 `MainWindowViewModel.RevealBottomGroup`,`TerminalWorkbench` 通过构造参数拿到这个回调,不直接写 `WorkbenchLayout`。标题栏按钮与其它 panel 同序:`已结束 (n)`、`+`,再缩小/还原,最后浮出(没有图钉,该区域不自动隐藏;浮动按钮把当前选中的标签浮出去,只在“组还活着但没有标签”时消失)。

**轮次改动。** 每个主轮次开始/结束(含失败/取消)用 `GitCli.SnapshotTreeAsync` 取树哈希写 `turn_checkpoints`;轮次号从已存检查点续接,否则重开会话后新轮次的检查点会被“已完成轮次不覆盖”规则静默丢弃。非 git 目录跳过。

**布局快照自管。** 两份快照,都用源生成 JSON 存在 `ui_state`:
- `LayoutSnapshot`(v5)存 `layout`:区域顺序、宽度、自动隐藏状态,底部组高度与**是否缩小**(`bottomMinimized`),各区 panel 高度比例,预览组的开关与宽度,浮动窗口(装的对象 + 几何)。检视区右列每块 panel 的高度存成 `belowHeights`:`{ panel id: px }`,是**可选追加字段**——缺省、缺某个 id 或旧版本读写它都退化成今天的平分,所以不升版本也不写迁移函数。v4→v5 把旧的 `bottomCollapsed`(收成底边按钮条)读成 `bottomMinimized` 并停写旧字段,v3 另外只把左列 `projectSplit` 重置为默认;版本不认识的快照一律回默认布局。
- `OpenTabsSnapshot`(v2,增加预览选项卡路径)存 `open-tabs`。
- 拖动区域分隔条/panel 分隔条松手时各触发一次 `LayoutChanged`(`EndPanelSplitterDrag`),配合 800ms 防抖快照写入,确保末次夹紧值也入快照。

恢复规则:
- 版本不符(含旧 Dock 时代的 v2)、缺 `version` 字段或解析失败,一律回落默认布局,不迁移。快照的 `Version` 缺省为 0,序列化时才写入当前版本,所以缺字段不会被当成当前版本。存储异常同样回落;取消照常抛出。
- 未知 id 丢弃;缺失项保持默认位置。
- 浮动窗口在它装的选项卡存在之后才应用;坐标落在所有屏幕之外时,移回主窗口所在屏幕。
- 检视区宽度存的是不含预览列的宽度:恢复时预览选项卡重新打开会再借一次 `PreviewWidth`,若按总宽存就会重复计入。
- 未放置过的浮动窗口不存坐标,恢复时居中于主窗口。

**区域宽度分配。** 每区有最小宽度:项目/检视 200px、主 360px;首次布局的默认宽度是项目 260、检视 275、预览列 420,之后以保存的快照为准。拖动区域分隔条时:
- 分隔条另一侧紧邻的区域吸收全部增量。
- 被挤压的那一侧,主区先缩到最小宽度,其余区域再按离分隔条由近到远依次缩到最小宽度。
- 边栏缩到最小宽度后继续拖,越过最小宽度的一半(`CollapseOvershoot` = 0.5)才自动隐藏;这段粘滞是为了防止贴着最小宽度拖动时误隐藏。主区永不隐藏。
- 空间够但边栏总宽过大时(例如第一次 arrange 之前就打开了预览,检视区已经加上 `PreviewWidth`),也同样先把边栏按顺序缩到最小、再隐藏非 protected 的边栏,主区最后拿到 ≥360px;`protected` 区域只缩不藏。
- 窗口变窄时先缩主区,再缩检视区、项目区,仍不够就依次自动隐藏;变宽的增量给主区。

计算由纯函数 `RegionWidthSolver` 完成,拖动路径不分配内存,松手才写快照。不用 `GridSplitter`,因为它只能调相邻两列。零分配要算上挂着 UI 的整条同步事件链:`ObservableObject` 按属性名缓存 `PropertyChangedEventArgs`;控件只对影响自身的属性名刷新(宽度类属性只触发 arrange,不重算标题栏)。

**Panel 标题栏。** 28px 高(`PanelChrome.TitleBarHeight`,浮出窗口的标题条也读它)。左侧是标题或选项卡条(只在本组内拖动排序,不跨组)。`StackPanel.Orientation` 是组件局部的布局责任：未指定时保持 Avalonia 竖向默认；确需横排的工具条/按钮行在自己的容器上声明 `Orientation="Horizontal"`。不得在 Window/App 范围的 StackPanel 类型样式中设置方向，否则任意嵌套的菜单与面板内容都会被横排。标题栏里的文字分两级:单块标题(`PART_Title`)取强调档 `FontSizeMd`(默认 14px)+ `Bold`,选项卡标签(`PART_Label`)取正文档 `FontSizeBase`(默认 13px)+ `Normal`,与标签页正文字号一致,标签条比标题更紧凑。字重只取界面字体链上真实存在的两档(400 / 700):`SemiBold` 在中文侧没有对应字体面——默认链里只有 Segoe UI 带 600(`seguisb.ttf`),Microsoft YaHei 只有 400 / 700 / Light——600 在汉字上被匹配成 700,于是同一段文字拉丁停在 600、汉字跳到 700,中英混排的标签条上最刺眼。浮出窗口的标题条由 `FloatingPanelWindow` 自建(不读 `PanelChrome` 模板),同样取 `FontSizeMd` + `Bold`,dock 与浮出时面板标题长得一样。激活与未激活标签仍只靠颜色区分(次要色 → 主色),不靠字重。右侧图标按钮按能力显示:
- 自动隐藏/停靠:两边边栏 panel 有,作用于整个区域。一个按钮、一个名字:tooltip 恒为“自动隐藏”,实心图钉 = 已停靠(点击自动隐藏),线条空心图钉 = 已自动隐藏(点击停靠回来),所以图标本身就是状态。主区底部组没有这个图钉,也没有自己的一套“收起”形态:它的收起就是下一条的缩小(只剩 28px 标题栏,标签与工具都还在),由会话底部的“子 Agent · 收起/展开”开关、标题栏自己的还原按钮、以及开启终端时自动展开共同驱动,三处改的是同一个状态。
- 缩小/还原:有可接收空间的展开同伴时显示(`IconMinimize` → 缩成标题条;`IconPanelRestore` → 四角对角箭头的 `arrow_expand`,读作“撑开回来”,与窗口自身最大化/还原的 `square_multiple` 分开,免得两个“还原”在同一屏里撞图形);缩小仅保留 28px 标题栏,正文隐藏但不销毁。同区域的纵向同伴回收高度;预览组缩小为检视区顶部整宽标题条,文件与工具列回收其下空间。最后一个展开同伴消失时自动还原。缩小状态不持久化,不替代整个区域的自动隐藏。
- 没有“放大”:panel 不提供“撑满所在区域、收起同区域其他 panel”的按钮,`PanelChrome`/`PanelModel` 都不带该能力;要局部放大用缩小同区域的同伴(上一条)或把标签浮出成独立窗口。
- 新窗口/停靠:只给可浮出的对象。
- 其他按需工具,如子 Agent 的“已结束 (n)”:标题栏里是 20px 扁平按钮(“已结束 (n)” + 小 chevron),点开 Flyout 列出已结束的子 Agent;空列表时按钮禁用。

除预览组的关闭按钮外不放菜单和关闭按钮;预览组标题栏有 X 按钮,点击倒序关掉组内全部标签 → 组不再 docked-visible、借用宽度归还 Main,与关掉最后一个预览标签同终态。用户关闭经终端与文件内容守卫串行处理,取消即停止;关闭其他标签也逐个等待。选项卡自带关闭,右键菜单每个选项卡一份实例。选项卡视觉参考 VS 工具窗口标签:25px 高、贴标题栏底边;未激活透明、文字居中次要色 + `Normal` 的 `FontSizeBase`,悬停文字变主色;激活标签的轮廓由 `TabHeaderView` 自己画(`Render`,不是模板里的 `Border`),底色取所在 panel 的背景(主区白、边栏灰),外轮廓上两角向内圆 5px,两条侧边到底边处**向外**拐出 5px 圆角(弯弧从侧边切出、在底边处贴平,竖入平出,不是往回收口的圆角),所以标签顺弯弧长回 panel 正文里;底边本身不画线、压在标签条下方那条 1px 分隔线上,标签与正文连成一片。边框是**一条填充的环**(外轮廓与它的垂直向内偏移拼成),不用描边路径。脚的弧是**凸弧**,内缘用**同一圆心、半径 R+1 的同心弧**,环厚沿脚弧保持 1px;同心内弧与底边上方 1px 那一行的交点在 x = r + R − 2√R。交点外侧保留约 2px 的短直段,再用一段两端切线分别匹配分隔线与内圆弧的三次贝塞尔曲线过渡；R=5 时曲线及直段都在 tab Bounds 外,不向 tab 内画横向边框,也不以锐角硬折进圆弧。正文底色覆盖 tab 下方的分隔线,脚边框只在外侧与露出的分隔线相接。**外翻必须真正绘制在标签控件矩形之外**: Avalonia 的 `TemplatedControl` 默认 `ClipToBounds=True`,而弧脚左右各伸出 `Bounds` 5px,若不在 TabHeaderView 主题中显式设 `ClipToBounds=False`,整段外弧会被自身裁掉,连线在控件侧边处截断,看起来既没有圆弧又像断口;`PART_Tabs` 同样禁用子裁切并左右留 5px 安全区,最外层 `ScrollViewer` 仍负责按可视窗口裁切。上一轮只改弧形几何而漏了这一裁切约束,因此用户实测仍看不到效果。曾用“沿路径描 1px”的写法:描边在凹陷角上要么离开外轮廓留一道白缝、要么在拐角收口,缝就出在那里。模板里那个 `Border` 只能把角往内圆,所以它只留 1px 厚度占位、不再画底色和边框;键盘聚焦(`:focus-visible`)只换环的颜色为强调色,未激活但持有焦点时只画环不画底。可关闭标签始终预留 16px 关闭槽与 6px 间距,关闭 × 只在激活或悬停时可见、可点击,不改变标签与相邻标签的几何;会话标签(`TabKind.Session`)在标题前多一个 14px 的气泡图标(`IconChat`,与关闭槽同属标签几何而非标题文字):未激活画线框、激活时同一路径填充成实心气泡,颜色跟标签文字走;图标不占位时(`IsIconVisible=false`,即其他类别标签)不预留宽度。不可关闭的标签(TODO / 评审 / 规格树)没有关闭槽,左右内边距对称(`12,0,12,0`),标签文字因此落在标签几何中心。标签放不下时,标签条右端出现 `…` 按钮(`PART_Overflow`,20px,独占 `Auto` 列,实心圆点 `IconEllipsisSolid`):点击列出所有被裁剪的标签标题(只列当前不在视口内的),点标题直接激活该标签并把它滚进可视区。按钮所在列在无溢出时因 `IsVisible=false` 宽度为 0,所以它只在标签条已经太窄之后才占宽;占宽只会让视口更窄、不会让标签重新变得完整,所以判定不会振荡。溢出判定在每次 layout 之后用 `ScrollViewer` 的 `Offset`/`Viewport` 与各标签 `Bounds` 比较,不分配内存,只在翻转时写 `HasOverflow`。滚轮横向滚动保留。

**文件预览与编辑。** 打开文本文件即进入 AvaloniaEdit 可编辑视图,默认不换行,可水平/垂直滚动到完整内容;20px 图标切换换行,支持选择、复制、撤销/重做与工具栏保存/Ctrl+S,不再切换着色预览与无着色编辑模式。文本与符号不得过滤或用显示占位字符替换。原生文档与撤销历史属于文件模型,切换标签或分离视图不销毁缓冲。着色使用 AvaloniaEdit.TextMate,不重建全文件行列表。迁移期间原生文档增量镜像到 `Forge.Editor.TextDocument`,保存仍经其原子编码保存,保存中的后续编辑保持脏。镜像故障须可见,保留原生未保存文本并阻止错误保存,不能把同步故障当成已保存。文件读取/文本物化/保存在线程池;内容显示不等待 LSP 启动,后台打开语言会话,变更/保存/关闭沿既有同步泵发送,失败显示独立语言服务状态。绝对路径去重复用文件标签,避免同 URI 多份缓冲。未保存关闭/替换需确认,多文件确认全部通过且内容未变才允许继续,不伪造已保存状态;保存中禁止替换/关闭。归档不保存也不丢弃仍打开的编辑。加载取消、标签关闭取消在途加载和语言会话打开。

文件超过 8 MiB 明确拒绝,不再静默截取 20000 行;超过 1 Mi 字符跳过 TextMate,仍可显示、编辑和保存完整文本。预览/文件列之间拖动保持检视区总宽不变,在预览最小宽与文件侧栏最小宽之间分配,不沿用打开预览时向主区借宽的 setter。

**文件编辑与行评审。** 同一代码视图支持文本选择、行号选择、复制、撤销/重做和保存,语言服务沿现有 `Forge.Editor` 接入。选中文本或点击行号后显示评论图标,点击图标展开锚定所选末行的浮动评论框,显示行范围与“保存草稿 / 立即发送 / 取消”;草稿复用 `ReviewStore` 持久化,单条发送只包含该评论,批量发送将当前文件的草稿合成一次消息,队列接受成功后才标记已发送。浮层不推开后续代码、不向源文档插入占位文本,自身输入和复制不被编辑器截获。

以下交互边界已向用户提问,当前未获可用答复,暂采用默认项:常用 LSP 交互覆盖诊断、补全、悬停和跳转定义;发送目标固定为文件所属会话,忙时沿既有队列排队,不随当前活动会话切换;草稿允许基于未保存代码,发送前必须保存成功且内容仍对应评论锚点,失败保留草稿并提示;普通文件仍可编辑保存,无所属会话时不启用评审发送。编辑后评论锚点须跟随文本变化,无法重定位时明确显示失效,不把错误行号当成有效评审。

**diff 中的行评审。** 改动视图复用同一套评审浮层:`ReviewOverlay` 绑定 `IReviewSurface`,文件预览由 `FileReviewController`、diff 由 `DiffReviewController` 实现;diff 里的选区按行映射到 (文件, 新侧行号),跨文件或只落在删除/占位行上不出评论图标,拆分模式只在右侧(新)编辑器评;锚点用该文件的真实 `FileDiff`,发送不保存文件,存储与评审 panel 同 `ReviewStore`。草稿按新文件坐标存,被折叠时显示在折叠条上,文件折叠时显示在文件头上。

实现状态:原生 TextPresenter 原型不采纳。采用 AvaloniaEdit、浮层及原生 LSP 交互,删除旧文件预览行列表与着色控件;共享 Diff 的词法实现不随之删除。构建通过不替代真实编辑、评论提交、语言交互与 Native AOT 发布验证。

依赖与语言范围(已确认):AvaloniaEdit 的配套额外依赖进入白名单,允许使用其 TextMate 集成及语法包,不再要求仅接入自有词法实现。语言范围按所采用方案实际支持的语法提供;无可用语法的文本仍可编辑,明确使用纯文本,不删改源文字符。LSP 能力按已安装并配置的服务器提供,不把语法着色支持宣传为语言服务器已就绪。

**编辑器能力全集与入口。** 编辑器要把 AvaloniaEdit 自述的能力真正开出来,不只是行号与着色:

- 折叠:安装 `FoldingManager` 与 `FoldingMargin`,范围优先取语言服务器的 `textDocument/foldingRange`,服务器未声明 `foldingRangeProvider` 或无会话时回退到结构启发式(`Forge.Editor.Folding.StructuralFolding`),XML/HTML 类文件用库自带 `XmlFoldingStrategy`。文本变化后 250ms 防抖重算,结果按文档版本校验,过期结果丢弃。折叠状态属于控件,不写盘、不跨标签继承。超过 20000 行不折叠并在编辑器提示行说明,而不是卡顿。
- 显示与交互开关:行号、空白、制表符、行尾符、控制字符、文档末尾以下滚动、当前行高亮、超链接、自动折叠、缩进宽度、Tab 转空格、列标尺、着色主题(跟随界面/固定亮/固定暗)。全部落 `settings.json` 的 `preferences` 段(每项可选、缺失取默认),设置页“编辑器”分区给出默认值,改动立即套用到已打开的编辑器。
- 入口:编辑器工具栏 `⋯` 与编辑器右键菜单共用同一份**菜单构建逻辑**,但各自持有自己的实例——Avalonia 的 `ContextMenu` 只能在它挂接的那个控件上打开,工具栏按钮重新打开编辑器菜单会抛 `ArgumentException` 并终止进程,所以工具栏按钮用 `MenuFlyout`。菜单项无绑定:打开时读设置、点击时写设置,因此勾选状态不会说谎且 Native AOT 安全。内容:撤销/重做/剪切/复制/粘贴/全选、显示开关、折叠命令、转换命令(大小写四种、前导 Tab↔空格、缩进选区、删除行)、查找/替换。Ctrl+F / Ctrl+H 用库自带 `SearchPanel`;Ctrl+Shift+[ 折叠当前块、Ctrl+Alt+[ / ] 全部折叠/展开。
- 选区配色:品牌蓝 `#3399FF` 半透明(亮色主题约 24%、暗色约 30%),并清掉库主题给的深底白字前景与边框,选中不得遮住代码本身。搜索命中底色同理用半透明黄。
- 评审图标位置:评论图标挂在选中终点(或行号点击所在行的行首)的**右下角**,靠右边界放不下就翻到左下方,并始终夹在可视区内。
- 多光标:库 12.0.0 **没有实现**(README 宣称,源码只有单 `Caret` 与 `RectangleSelection`)。按用户确认改用矩形(列)选择:保持 `EnableRectangularSelection`,Alt+拖拽选出一列后输入/删除作用于整列,并在设置页与菜单里写明,不把多光标伪装成已实现。
- 行内 adornment:诊断行尾的按严重度着色圆点(零文档长度元素,不改文本与光标;悬停显示该行消息),以及折叠占位符本身。库 12.0.0 的行尾符生成器被注释、`ShowTabs` 无读取者,因此 `¶` 与 `→` 由 Forge 自己的零长度元素绘制;空格与控制字符框仍用库内置生成器。
- 超链接:只认 http/https/mailto,需 Ctrl/Cmd,交给系统默认程序(经 Avalonia `Launcher`);Forge 在编辑器层接管 `VisualLineLinkText.OpenUriEvent`,失败写编辑器提示行,不静默吞掉。
- 补全:按服务器声明的 `triggerCharacters` 自动触发(方向键/PageUp/PageDown/Home/End 在弹窗打开时由编辑器自己移动选中项;弹窗内的 `ListBoxItem` 用 `completion` 类拿回可见的选中背景——工作台的列表样式默认把选中背景清成透明,曾让弹窗“无法选择”),`isIncomplete` 在下一个字符后重试,`InsertTextFormat.Snippet` 的项按纯文本插入(`${1:name}`→`name`,占位符无默认值则不插入,选择项取首项,畸形片段整段消失,不做 Tab 占位符跳转);无会话或服务不支持时用文档词表补全(光标附近窗口、200 项上限)。

语言交互边界:使用原生补全窗口、诊断波浪线、悬停文本与 F12/Ctrl(或 Cmd)点击定义跳转。补全由 Ctrl+Space、服务器声明的触发符或无会话时的词表提供;只跟随第一个定义目标,悬停以纯文本展示;声明不支持 `insert/replace` 之外的 item defaults,不把非法编辑映射为文件开头。异步结果须验证文档、版本、会话与绑定代次,分离视图取消请求。跨文件定义沿源文件的工作区与固定评审会话打开,显式无所属会话不得回退到活动会话;已打开目标保持自身归属。

**语言服务器来源。** 除 `languages.json` 显式配置外,启动时自动检测本机已装的语言服务器(`Forge.Editor.Languages.LanguageServerDiscovery`):先查 PATH 上的已知命令(C#、TS/JS、JSON、CSS、HTML、Python、Go、Rust、C/C++、Shell、YAML、Lua),再查 VS Code / Cursor 的扩展目录(含 C# 扩展里的 Roslyn LSP、`.roslyn` 同名片与 OmniSharp)与安装目录自带的服务(node 启动的 JSON/CSS/HTML);安装目录按三种布局展开(根、`resources/app`、`<版本>/resources/app`)。有界且离线:只做存在性检查、不下载、不安装、不执行探测命令;不存在的目录直接跳过,每个扩展最多看 32 个版本(按版本号取最新)。带注释的 JSON 用独立的 `jsonc` 语言(`.jsonc`、`tsconfig.json`/`jsconfig.json`/`devcontainer.json`,以及 `.vscode` 目录下的任意 `.json`;判定顺序是精确文件名 → `.vscode` 路径段 → 最长扩展名),否则 JSON 服务器会把注释当错误报。TypeScript 会带上 `initializationOptions.tsserver.path`,来源依次是服务器同级的 npm 全局 `node_modules`、npm prefix、编辑器安装目录自带的 `typescript`;找不到就不带选项,让工作区自己的 TypeScript 生效。合并规则:用户在 `languages.json` 里配置过的语言(包括显式配成无服务器或 `disabled`)一律不被覆盖;未被配置的语言才使用发现结果,并继承该服务器的扩展名表与初始化选项。命中后静默使用,并在编辑器状态行写明“语言服务:<服务器名>(来源)”(启动器被隐藏时取实际被启动的文件名,不写成 dotnet/node);仍找不到时提示里说明已查过 PATH 与 VS Code 扩展/安装目录。不使用 Pylance(其许可只允许在 VS Code 内使用)。

**诊断的两条来源与 Roslyn 的加载前提。** 客户端同时声明推送诊断(`textDocument/publishDiagnostics`)与拉取诊断(`textDocument/diagnostic`,LSP 3.17)并从 `diagnosticProvider` 判断;支持拉取的服务器(JSON/CSS/HTML、Roslyn)由编辑器在视图绑定、编辑防抖 500ms、以及服务器发 `workspace/diagnostic/refresh` 时主动拉取,结果写回会话的诊断存储后走与推送同一条映射/渲染/重放链路(晚绑定的视图也能重放)。同时声明 `window.workDoneProgress` 与 `workspace.diagnostics.refreshSupport`,否则 Roslyn 既不开始加载项目也不通知重拉;发现的 Roslyn 另带 `--autoLoadProjects 100`,否则 `.cs` 文件停在“杂项文件”里,永远不会有诊断、悬停与跳转。首次拉取可能早于项目加载而被服务器丢弃,所以打开后还有一次延时重拉兜底;服务器用 `$/progress` 报告自己在加载时,状态行改显示“正在加载项目”,因为这段时间里的 F12、悬停就是不会有回应,把它呈现成等待而不是坏掉。

评论提交边界:草稿可基于未保存代码,发送前保存并验证锚点与内容仍一致。队列接受与数据库标记不是跨系统原子事务,不承诺 exactly-once 或崩溃恢复;接受后标记失败必须提示并在本次运行中阻止重复发送,后续提交或重新加载时重试标记。尚未交给运行时的评论消息被用户撤回或所属会话关闭时,恢复为草稿;恢复失败须提示并阻止再次发送,后续提交或重新加载时重试恢复。标记和恢复按同一 ReviewStore 串行化,避免重试覆盖撤回状态。已交给运行时的消息不恢复;应用退出时异步恢复可能尚未完成,仍属于未提供持久队列与崩溃恢复的边界。保存草稿期间禁止取消释放其锚点,避免数据库留下不可见评论。持久草稿未记录基准提交,重载依赖保存的文本锚点;唯一匹配重定位只搜索不超过 20000 行的文件,超过时仍接受原位置精确匹配,失配不得发送。

**停靠条与自动隐藏。** 以区域为单位。仅自动隐藏的边栏在其所在窗口边缘显示 32px 停靠条(`AutoHideStrip`,底色 `DockStripBackgroundBrush`,内侧 1px 分隔线);停靠状态不显示停靠条,宽度也不占用布局,只为自动隐藏区域按边缘计入 `RegionWidthSolver`;两个自动隐藏边栏在同一侧时并排。条上每个 panel 一个竖排标签(文字旋转 90°,从上往下读),标签外侧(靠窗口边缘)一条 3px 指示条:抽屉打开时为 `DockIndicatorIdleBrush`,抽屉关闭时为 `AccentBrush`。点标签 = 开/关抽屉。抽屉贴着停靠条内侧弹出,覆盖在主区上方,点外部或按 Esc 收起。底部组没有单独的按钮条:它按上一条的方式缩小成标题栏。

**区域置换。** 按住任一 panel 标题栏的空白处横向拖,出现三个落点,放下后两区互换,宽度跟着区域走。自动隐藏中的区域不能拖。按钮条位置、抽屉方向、预览组的“靠主区一侧”都由“角色 + 当前顺序”推导。

**图标按钮的悬停底色。** `IconButtonHoverBrush` 亮 `#D4D4D8` / 暗 `#3F3F46`,按下用 `IconButtonPressedBrush`(亮 `#C4C4C9` / 暗 `#4A4A52`),与分隔线同一档——图标按钮都坐在 chrome 或 panel 正文上,靠这一档才能两种底色上都读得出来。面板标题栏(`PanelIconButton`)、停靠条标签(`AutoHideButton`)、窗口标题行与对话框的 `Button.ghost` / `Button.icon` / `Button.tab` 都用这两个令牌,不再借 `BorderBrush` 当按下底色。Fluent 内置控件(TextBox/ComboBox 等)自己的边框不走这两个令牌。

**TODO 面板(分组 + 步骤)。** 结构与 ThinkRail 的 `todos`/`groups` 一致:自上而下是**置顶的排队输入行** → 进行中的**分组**(组行 + 缩进的步骤)→ **待排散项** → `完成` 区;历史压最底。置顶行是 `＋` + 无边框 `TextBox`(占位 `todo.addPlaceholder`),它在 `ScrollViewer` 之外所以永远可见,Enter 添加,加进来的是 `TodoOrigin.User` 的**待排散项**(不是分组:agent 述领时用 `todo promote` 把它变成分组)。分组行 = 状态图标 + 标题(`FontSizeBase` + `Bold`)+ 右侧 `已完成/总数`;未完成的分组始终展开、没有删除与折叠入口(分组只由 agent 建)。步骤行缩进一级,左侧一条 1px 引导线**居中在分组行状态图标那一列**(固定 30px = 8 内边距 + 14 图标 + 8 间距),所以线正好压在图标的垂直中线上。**状态图标四态且不可点**:未开始空心圆 / 进行中绿点圈(`AccentBrush`)/ 暂停灰 `⏸` / 完成绿 √(`IconTodoPending`、`IconTodoInProgress`、`IconTodoPaused`、`IconTodoDone` 在 `Resources/Icons.axaml`,颜色分别走 `TextMutedBrush`、`AccentBrush`、`SuccessBrush`);分组的状态由步骤推导(全 done → ✓;有 in_progress → ⊙;否则有 paused → ⏸;否则 ○),从不存储。**面板里没有勾选框、也不能改任何状态**(只读展示 + 新建 / 删除 / 调序):改变状态与步骤提交只发生在 agent 的 `todo` 调用里。行尾 `×` 只在悬停或键盘聚焦时出现(`:pointerover`/`:focus`/`:focus-within` 切 `IsVisible`,行自身 `Focusable` 所以能 Tab 到),删除散项或步骤;`完成` 区完全只读(无 `×`、无“清除已完成”按钮)。人工添加的行右端多一枚线框 user 图标(`IconTodoUser`,灰,`todo.source.user` tooltip)。**拖拽调序**只对 `Pending` 行发起,传的是进程内 `TodoDragSource(Id, GroupId)` record,落点先判同层(待排区之间 / 同一分组之间)再 `ITodoStore.MoveAsync`,存储把序号夹到本层;跨组、拖进拖出分组不做。`完成` 区里已完成分组收成一行 `› ✓ 标题 n 个步骤`,点整行展开它自己的步骤(默认收起),已完成散项排在分组之后。状态行只在没会话 / 清单为空 / 存储报错时显示一行 11px 说明(`HasStatus`),有内容时没有汇总行;旧的顶部“3/8 完成”与底部“清除已完成”已删除。视图模型是四个集合:`Groups`(未全完成)/ `Loose`(未完成散项)/ `DoneGroups` / `DoneLoose`,每次 `ListAsync` + `ListGroupsAsync` 一次刷新重建。

**浮动窗口。** 只允许浮出选项卡(任意组的任意选项卡,含 TODO/评审/规格)和文件 panel;其他 panel 不能浮出。

- 文件 panel 给出的是会话相对路径;打开前统一按活动会话工作目录解析成绝对路径,`open-tabs` 里也存绝对路径,恢复时不依赖当时的活动会话。
- 一个对象一个 `FloatingPanelWindow`,用同一视图模型重新套数据模板(视图内的滚动等临时状态不保留)。
- 浮出的选项卡仍留在原组的集合里,只标记浮动、不显示,所以点“停靠”或关窗时天然回到原槽位,不用另记“家”;组里活动选项卡永远不是浮动的。

**交互终端(`Terminal/**`)。** 终端是底部组里的选项卡(`TabKind.Terminal`,id 前缀 `terminal:`),可开多个,也可浮出。工作目录取会话的 worktree。
- **VT 引擎(`Terminal/Vt/`)**:纯 BCL、不依赖 Avalonia,AOT 无警告。包括 DEC ANSI 解析器(UTF-8 跨分块续接,非法字节输出 U+FFFD)、主屏和备用屏、回滚环(偏好 `TerminalScrollbackLines`,1000–100000,默认 10000)、SGR 16/256/truecolor、DECSET/DECRST(含鼠标 1000/1002/1003/1006、2004 括号粘贴、2026 同步输出)、OSC 0/1/2 标题、OSC 8 链接、OSC 52 只写剪贴板、OSC 10/11 按主题回答,以及 xterm 按键与 SGR 鼠标编码、East Asian Width 宽字符。缩放时不重排行。实测吞吐约 99 MiB/s(20 MiB 混合文本),稳态滚动零分配。**已记录偏差**:在整屏顶行执行 `CSI M` 时,被删的行会进回滚(xterm 不会),这是为了保证不丢内容。
- **线程**:每个终端一个后台泵,读 `Output`,持锁喂仿真器,置脏标志;UI 按帧合并刷新,UI 线程从不解析。键盘输入和泵线程产生的设备应答(DA/DSR 等)走**同一个有序通道**,由单个写任务送达 Host,保证管道内有序。
- **`TerminalControl`**:自绘,每行生成 `FormattedText` 并按行版本号缓存。支持键盘与 IME 输入;复制粘贴为 Ctrl+Shift+C/V,macOS 用 Cmd;粘贴前去掉转义字符,启用 2004 时加括号包裹。支持拖选、双击选词、三击选行(开启鼠标上报时按住 Shift 仍是本地选择);滚轮在开启上报时发给程序,在备用屏发方向键,否则滚动回滚区。Ctrl+点击 OSC 8 链接只放行 http/https。尺寸变化防抖 50 ms 后同步给 Host。视口锚定在回滚内容上,新输出不会把正在查看的历史顶走。配色来自 `TerminalPalette`(亮暗各一套),字体跟随“代码字体”偏好。
- **`TerminalViewModel`**:标题取 OSC 标题,没有时为“终端 n”。状态分启动中、运行、已退出(退出码)、失败(原因)。退出后标签保留,画面末尾附一行“进程已退出”。Host 未运行时直接显示失败状态,不抛异常。视图先于会话就绪布局时,先记下尺寸,会话就绪后补发。
- **`TerminalWorkbench` 协调器**:按会话 id 持有终端。新建时取会话的 `WorkDir` 和偏好里的 shell 与参数(参数按空格切分,双引号分组)。切换会话时,其它会话**停靠在任意组**里的终端标签被移出、但不结束,切回时放回底部组;浮出的标签留在自己的窗口里。会话归档时结束该会话的全部终端;App 退出时,先于组合根拆除结束全部终端,限时等待。关闭标签时如果有前台进程,不弹对话框,而是在终端视图里显示横幅,让用户选“结束并关闭”或“取消”。
- **工作台接线**:`WorkbenchLayout.TabCloseRequested` 是一个**单值** `Func<…, Task<bool>>` 属性,不是事件,因为多播委托只会留下最后一个返回值;`PanelTabStrip` 的关闭改走它。终端标签不写进 `open-tabs` 快照。入口有三个:Ctrl+`、窗口标题行的终端图标按钮(`terminal-open`,设置左边)、底部组标题栏的“+”。文案表是 `Localization/Strings.Terminal.cs`(键名前缀 `terminal.`)。
- **设置分区未注册**(用户决定):注册会和 `SettingsPanelTests` 对分区列表的硬性断言冲突。`TerminalSettingsViewModel` 及其模板已写好,但没有接线;shell、参数和回滚行数目前只能经偏好文件修改。
- **已知遗留**:浮出的终端标签仍会写进 `LayoutSnapshot.Floating`(恢复时被丢弃,无副作用);关闭被否决时,浮出的标签不会提到最前。延后项:缩放重排行、缓冲区内搜索、OSC 133、重启后恢复、已退出终端的“重新启动”、图片协议、双向文本、macOS 实机验证。

**审批队列与 Agent 扩展(`Approval/`)。**
- `ApprovalQueue` 归 UI 线程,条目是工具调用卡或插件审批卡;主窗口右下角非模态叠加层(约 420 px、可折叠,每张卡标注来源会话),不阻塞其它会话;有待审批项时会话标签与输入框上条的审批计数显示条数。
- `SessionApprovalHandler : IApprovalHandler` 每个主会话一个(注入 `AgentHost.ApprovalHandler`):先查记住规则,命中即 `Allow`;否则入队等待;`ct` 取消或会话释放时撤卡。
- 记住规则 `ApprovalRules`:键 = 工具名 + 副作用 + 作用域(会话/项目/全局),只记“允许”。会话级只在内存;项目级与永久写 `<数据根>/approval-rules.json`(源生成 JSON、`AtomicFile`、后台线程、写入串行且快照在写锁内取),不放进 `AppPreferences`。项目 id 取自 `ISessionCatalog`,常规会话归 General。文件损坏一律当作无规则并备份 `.bak`。`extension_delete`、插件审批卡、插件命令永不可记住;插件新版本获批时清除其新旧工具名下的全部记住项。
- 策略:`extension_list/create/update/disable` 为 `Allow`(只写暂存区,真正的闸门是插件卡),`extension_delete` 走 `Ask`(即删除确认)。
- `ExtensionAuthoringService` 实现 Core 的 `IExtensionAuthoring`:暂存 → 有诊断则直接把诊断返给 Agent(不入队)→ 插件卡入队 → 批准时把卡上展示的哈希原样传给 `extensions.commit`、拒绝则 `extensions.discard`。插件卡新建显示全文、更新显示与线上版本的逐文件 Diff,另示权限、依赖、三种哈希与诊断;只有“批准/拒绝”。重启后 `extensions.pending` 的项以“重启前提交”卡出现,不阻塞任何 Agent。`SessionRuntime` 订阅 `ToolsChanged` 并调用 `AgentHost.ReplaceExternalTools` 热加载。
- 设置分区 `extensions`(`SettingsSectionIds.Extensions`):已安装扩展(启用/禁用/删除,删除二次确认;enable 只在这里提供)、待审批项、按作用域分组的记住规则(逐条撤销)。文案在 `Localization/Strings.Extensions.cs`(中英)。
- 插件/工作流的 `host.tool_call` 经 `SessionToolCallRouter`(`Approval/`)按 run 注册会话路由:工具取自该会话 `AgentHost.Tools`(内置+外部),策略用与 agent loop 相同的 `SessionPolicy`,Ask 走该会话的 `SessionApprovalHandler`(记住的规则与卡片会话均正确),未知/已释放会话拒绝;五个 `extension_*` 工具对插件永不可解析、永不放行(它们的策略是"免问",真正的门是插件卡)。`SessionRuntime` 在构建 host 时注册、释放时注销;`ExtensionHostSupervisor.Create` 接收路由器。
- 子 Agent 的 `host.tool_call`/`run_code` 内部调用:其 `ToolContext.SessionId` 是子会话 id,但子 Agent 与根共用 AgentHost。`SessionRuntime.RunTurnAsync` 消费事件时,`AgentSubAgentStarted`(任意深度)把 `ChildSessionId` 登记为根 scope 的别名,`AgentSubAgentFinished` 或运行时释放时注销(释放时清掉全部别名,释放后不再登记)。子调用按根的工具集解析(变更仍须审批卡;`extension_*` 仍不可达),卡片显示根会话(与 Core 一致)。别名登记发生在事件被消费时,先于子 Agent 的首次模型往返,实际不会落后于其首个工具调用。
- 插件命令审批的 `ToolName` 是 `plugin-command:<pluginId>:<name>`(`ExtensionHostClient.PluginCommandApprovalName`):模型侧工具名只含字母数字、`_`、`-`,不含 `:`,因此永远不会与内置/外部工具名相等,策略 Allow 规则与"始终允许"都碰不到它。插件命令卡不可记住(`ApprovalRules.IsRememberable` 为 false,无记住按钮,`Allow` 也拒绝入库),每次调用单独确认;卡片标题"插件命令审批"。
- 同一会话可同时显示多张工具卡:Core 的 approvalGate 只串行 agent loop 自己的调用,路由器进来的插件/工作流调用不经过它。每次请求有自己的卡与等待,决定和取消只影响自己的卡(`SessionApprovalHandler`/`ApprovalQueue` 按卡片实例工作)。不加跨组件闸门:agent loop 持着工具调用等插件步骤时再加闸会死锁。
- 插件卡无用户决定的撤回(会话释放、关闭、取消、卡片 Dispose)产出独立的 `Withdrawn`(≠ Deny,映射到 Core `ExtensionSubmitOutcome.Withdrawn` 而非 `Invalid`):不 Discard 暂存稿,稿件留待 `extensions.pending` 重启后作为"重启前提交"卡出现;给 agent 的文本如实说"已撤回、草稿保留待定、不是拒绝"。工具卡的撤回仍是 Deny。
- 提交时先(加载规则后)清除旧/新工具名的已记住规则,再提交,提交后按实际注册名再清一次;提交失败时规则保持已清除。`approval-rules.json` 的 `rules: null`/缺失视为损坏文件(无规则 + `.bak`),加载任务永不 Faulted,`RequestAsync` 对加载异常降级为"询问"。
- 工作流扩展卡显示声明的工具(名称/描述/输入 schema)。
