# Forge.App

Forge 的 Native AOT 桌面主程序(Avalonia 12.1.x,仅桌面)。承载组合根与停靠式工作台:把 `forge-core`(Agent 循环、存储)、`forge-workspace`、`forge-mcp`、`forge-editor`、`forge-host-client`(插件/CodeMode 代理)与 `forge-approval` 串成一个进程。

## 边界

- Native AOT(`IsAotCompatible` + `PublishAot`),依赖闭包不含 Roslyn、`AssemblyLoadContext`、`Forge.Scripting`/`Forge.ScriptExecutor`;只用源生成 JSON(`SettingsJsonContext`、`WorkbenchJsonContext`);无 DI 容器/MVVM 包(手写 `INotifyPropertyChanged` + `ICommand`)。属性 setter 除自身外还要通知派生属性(如 `X` 之于 `HasX`)时用 `ViewModels/NotifyingObject.SetAndNotify`:它零分配(`nameof` 常量走 `ObservableObject` 的 args 缓存),不要写回 `if (Set(...)) OnPropertyChanged(nameof(...))` 的旧形态。
- **不实现任何存储或 Git 管道。** 只经 `ISessionStore`/`ISessionCatalog`/`IProjectRegistry`/`ITodoStore`/`IUiStateStore`/`ITurnCheckpointStore`、`GitCli`、`WorktreeManager`、`SpecGraph`、`ReviewStore` 组合;`src/Forge.App` 中不得出现 `SqliteConnection`、`CREATE TABLE`、`write-tree`、`GIT_INDEX_FILE`。
- 不直接读审批数据库做判断(哈希经 `plugins.status` 取);为状态面用只读连接数 `plugin_approval` 的行数,进程里不持有任何可写审批连接,也不建表、不迁移。计数只在文件不存在(不打开、不创建文件/`-wal`/`-shm`)或没有 `plugin_approval` 表时返回 0;其余错误上抛,设置页的 `approvals` 分区与输入框上条的计数显示"不可读",不把损坏或锁住的库显示成没有插件。
- UI 线程不碰存储:Microsoft.Data.Sqlite 的 `*Async` 是同步执行的,所以所有存储/SQLite/文件调用(含归档、重命名、`ui_state` 写入、TODO 增删)都经后台助手,不在调度器上 await。唯一例外是退出:最后一次布局保存在后台执行,但 UI 线程最多等它 3 秒(超时只记日志),保证关窗时快照尽量落盘又不卡死。
- 无 P/Invoke;进程归属是 `forge-extension-host` 的职责。App 只启动/重启 Host 子进程并保证退出时杀树等待。
- 工作台布局自写(`Workbench/`),不用任何停靠框架;原内化的 Dock 已移除。

## 组合根

构造顺序即依赖方向,拆除严格逆序:`AppPaths` → (审批数据库路径,不打开)→ `ExtensionHostSupervisor`(`--worker`/`--executor` 显式传路径)→ `WorkspaceServices` → `McpServices` → `EditorServices` → `ProviderSettings` + forge.db 上的 5 个存储 + `TurnCheckpointService` + `WorktreeService` → `AgentRuntimeManager`。审批库归 Host 所有,App 只拿到 `<host 数据目录>/approvals.db` 的路径。数据根默认 `%LOCALAPPDATA%/Forge`,`FORGE_DATA_DIR` 覆盖;常规工作区默认 `文档/Forge/General`,`FORGE_GENERAL_WORKSPACE` 覆盖。开发验证一律设置这两个变量,不写真实用户目录。

**模型提供商(多个已连接 + 一个默认)。** `settings.json` 的 `providers` 段是唯一配置源:`{version, defaultId, items[]}`,每条含 `id`/`preset`/`name`/`protocol`(`openai-compatible`|`anthropic`|`openai-responses`)/`baseUrl`/`auth{kind,envVar,secretRef}`/`models`/`defaultModel`/`thinking`/`maxOutputTokens`/`modelMeta`/`headers`。旧的单 `provider` 段只在第一次读到时迁移成一条(Anthropic 协议 → Anthropic 预设,其余 → 自定义 OpenAI 兼容);第一次保存写 `providers` 并删掉旧段。文件按 `JsonNode` 整份读改写,`preferences` 与未知字段原样保留,JSON 无效时拒绝保存而不是覆盖。完全没有配置时不载入任何提供商:不写文件、没有占位条目(无 fake 行);设置页顶部横幅「至少连接一个提供商才能运行 agent」,输入框模型列表为空。
- **密钥库。** 界面粘贴的 key 存 `<数据根>/provider-secrets.json`,AES-GCM,密钥是 `<数据根>/provider-secrets.key`(32 字节,非 Windows 上 `0600`),`settings.json` 只存 `secretRef`;环境变量优先于库内密钥,行内显示「环境变量 key · VAR · 托管中」。这是防误泄露与云同步,不承诺抵挡能读用户目录的本机攻击者——为此不引入 DPAPI 包,也不在 App 里写 P/Invoke。库损坏时 `Problem` 明确报出来,绝不把"读不出"当成"没有密钥"再覆盖写入。
- **预设目录**(`Forge.Core.Providers.ProviderPresets`):Anthropic(产品默认)/OpenAI/GitHub Copilot/OpenRouter/Kimi For Coding/Meta/xAI,外加无 URL 的「自定义 OpenAI 兼容」。每家给协议、base URL、环境变量名、文档链接、种子模型与是否支持 `/models`;模型 id 会变,种子只是离线首屏,列表以服务端为准。**Anthropic 的两种凭据都能列模型**:`{base}/v1/models` 对 API 密钥(`x-api-key`)与账号登录(`Bearer`)都回答,所以 Claude 订阅登录后不再停在种子上;只剩 Kimi For Coding 不列(它没有列表端点,连接测试走一次最小对话)。**一家厂商一个预设,进入方式决定端点**:预设可带一个可选的订阅端点(`ProviderSubscriptionEndpoint`:协议、base URL、种子模型),`ProviderDefinition.FromPreset` 按调用方指定的凭据种类取主端点或订阅端点——OpenAI 的 API 密钥走 `api.openai.com/v1` 的 chat/completions,同一预设的 ChatGPT 订阅走 `chatgpt.com/backend-api/codex` 的 responses;GitHub Copilot 的 API 密钥走静态 `api.individual.githubcopilot.com` 加明文 Bearer(不换会话 token、不发集成头),设备码那条仍是会话 token。OpenCode Zen/OpenCode Go/DeepSeek 已从内置目录移除,旧配置里引用它们的条目降级为自定义并保留原 URL;需要时用「自定义」重新添加。
- **六种认证。** `api-key`(库或环境变量)、`claude-subscription`(复用本机 `~/.claude/.credentials.json`,距过期 5 分钟内自动刷新并写回;推理请求带 `anthropic-beta` 与 Claude Code 身份 system 首块)、`github-copilot`(设备码 → `ghu_` token → 会话 token,`Copilot-Integration-Id: copilot-chat` 必须与铸 token 时一致,base URL 取响应里的 `endpoints.api`)、`kimi-code`(`auth.kimi.com` 设备码 → access/refresh,`Authorization: Bearer`)、`xai-subscription`(`auth.x.ai` 设备码,scope 含 `grok-cli:access`,刷新响应可能省略 `refresh_token` 时沿用旧的)、`meta-subscription`(`auth.meta.com` 设备码 → identity token → `POST api.meta.ai/muse-code/key` 铸 24 小时 `api_key`,到期前 5 分钟用 identity token 重铸)、`chatgpt-subscription`(`auth.openai.com` 设备码 → authorization code + verifier → `/oauth/token`;账号 id 取自 access token 的 JWT claim `https://api.openai.com/auth`.`chatgpt_account_id`,每个请求带 `chatgpt-account-id` 与 `OpenAI-Beta: responses=experimental`)。四种设备码登录的 token bundle 都只存加密密钥库(引用 `kimi:`/`xai:`/`meta:`/`chatgpt:` + provider id),绝不进 `settings.json`、绝不写日志;刷新按 provider 串行,401 只在被拒的 refresh token 仍是当前值时才清库,避免并发刷新互相作废。 **`settings.json` 的 `claudeWire` 段(`Providers/ClaudeWireSettings.cs`)是官方身份的配置口**,故意没有设置页(这是带账号后果的线级决定,不是偏好):`{"enabled":true,"version":"2.1.317","build":"68a","entrypoint":"claude-desktop-3p","note":"…"}`。**默认即为官方身份**(段缺失、或开关缺失,都等于开);开关只有一种拼法 `true`/`false`(不带引号),**只有 `false` 关闭**,不是布尔的值(如 `"off"` 字符串、`0`、对象)一律按缺省当开——一种拼法是规则,读不出来的值是“没说话”而不是“说了反话”。关闭后请求与旧版逐字节一致;`version` 只接受三段数字、`build` 1-8 位小写字母数字、`entrypoint` 只接受 `^[a-z][a-z0-9_-]{0,31}$`(默认 `sdk-cli`,按实测在 5 小时窗口上约为交互类标签的一半),任何不合形状的值退回各自的默认值而不是让整段失效;**追加时 `version` 填的是本机 CLI 报的版本**(`ClaudeCliProbe.ReadVersion`:先 PATH 上的 `claude`,再 WinGet 链接、`~/.claude/local`、VS Code 扩展内置二进制;取不到才用内置默认值),`build` 故意不写——它不是构建号、同一安装会变,由 Core 在发请求时向 CLI 现问;`note` 是给人读的、解析时忽略,`ClaudeWireSettings.Documentation` 里有一行可复制的取值说明。只作用于 `claude-subscription` 凭据(API 密钥没有可声称的客户端身份),读入发生在每次目录加载,改完文件在下次提供商目录重建时生效。**该段由提供商保存自动维护,但只增删不改值**:`ProviderStore.Save` 在保存后核对已连接的提供商——存在 `claude-subscription` 而文件里没有该段时,追加一份默认值与 `note`;一个都不存在时删掉整段(段落治理一个已不存在的提供商没有意义)。已存在的段一律原样保留(包括 `"enabled":false` 和用户加的任何字段),加载路径绝不写文件(启动不得编辑用户文件)。由此带来的已知后果:删掉最后一个 Claude 提供商时用户的 `enabled:false` 会随之消失,重新添加会回到默认的声称开。**提示词跟着开关走**:声称开时内置系统提示用不自报产品名的版本,关掉时用自报 Forge 的版本(`BuiltInPrompts.System` / `SystemNamed`,两文本除首句名字外逐字符相同);用户自己填了 system 模板文本时以模板为准。"声称开"要求**两个条件同时成立**:`claudeWire` 生效且**确实连着一个 `claude-subscription` 提供商**(`ProviderCatalog.ClaimsOfficialIdentity`)——只有 API 密钥的安装既不上身份声称,也就不该按声称态选提示词。凭据在首次流读取时才解析(`CredentialedChatProvider`),首事件之前收到 401 会刷新后重试一次;第二个事件之后不重试,否则会重复输出。
- **模型元数据。** 三源合并链:目录快照(`model-catalog.json`,见下条)→ provider `/models` 返回的窗口与价格(折算成每百万 token,`ProviderModelCache` 持久化到 `<数据根>/provider-models.json`,重启后仍在)→ 用户 `providers[].modelMeta`,未知的一半保持未知。解析结果按 (提供商, 模型) 记进 `ModelMetadataMemo`,并在配置保存、`/models` 刷新、快照更新三处整体作废——它是纯派生值,只活在内存里,绝不落库。刷新 `/models` 仍是显式动作(显式点击与每日定时那一趟),启动时不逐个访问提供商。
- **运行时。** `ProviderServices.CreateProvider(ModelSettings)` 按 `ModelSettings.ProviderId`(空 = 默认)构造,未知名回落默认;`Forge.Core/Providers/Internal/ChatProviderPipeline` 把重试作为中间件套在端点上。composer 的模型弹层列所有已连接提供商的并集,多于一家时每行右侧显示提供商名,选中行同时决定 `ProviderId`,新会话默认值仍只有模型与强度。偏好 `preferences.modelsHidden` 里的模型不列(选型器与内置 Agent 默认模型下拉都读 `AppPreferences.IsModelHidden`,只有一处定义),但会话当前所在的模型即使被隐藏也照常列出——它是状态而非选项;改隐藏标志只让打开着的 composer 重新过滤(`PropertyChanged` 里的 `ModelsHidden`),不重建行、不用重启。
- **全局默认上下文窗口。** `settings.json` 的 `modelCatalog.defaultContextWindow` 只有一个属性、两种写法,由 `Providers/ContextWindowDefault` 统一解析、存盘与换算:正整数是固定 tokens,`"50%"`(也接受 `50 %`,1–1000%)是该模型自身窗口的比例。优先级是 `目录快照 → 提供商上报 → 全局默认 → 每模型覆盖`:绝对值覆盖链上解析出的窗口,但让位于指名了窗口的每模型覆盖;百分比则以链上已解析出的窗口为底数取 `floor(窗口 × 比例 / 100)` 且至少为 1,窗口未知时它不产生任何数值(模型仍是「窗口未知」),不凭空造数。全局值可以低于目录值(省成本/配额)也可以高于它(提供商允许时),这一点与 ThinkRail 的 "Default uses the model's catalog limit … larger contexts may increase cost or quota usage" 一致。只带价格的每模型覆盖不会挡住全局窗口;空输入才等于取消这个设置(删掉该属性),正整数或 1%–1000% 才保存,其余(`0%`、`%`、负数、小数)不保存并在分区内报错。百分比写成 JSON 字符串、绝对值写成数字,旧版本读到百分比时按「无全局默认」处理,不会误读成一个数字。该段只经 `JsonNode` 改 `defaultContextWindow` 与 `sourceUrl` 两个字段,`modelCatalog` 里其它字段原样保留。
- **价格的可编辑范围。** 四个价格字段(输入/输出/缓存读/缓存写)都保留在 `ModelMetadata` 与 `providers[].modelMeta` 里:Anthropic 真的单独收缓存写(5 分钟 1.25×、1 小时 2×),OpenRouter 也暴露四个价。但表单默认只显示三列(输入/输出/缓存读),**缓存写只在提供商协议是 Anthropic、或该模型已有非零缓存写价时出现**——给从不收写入费的提供商摆一个空框,只会读成"漏填"。空值仍是未知,不写 0。模型设置窗口另加一列只读「能力」(输入模态 + 推理档位数),数据来自目录快照,未知即空着而不是写“未知”。
- **目录源(models.dev)。** `settings.json` 的 `modelCatalog.sourceUrl`(默认 `https://models.dev/api.json`,可换成同一 JSON 形状的镜像/内网代理)每天被 `ModelCatalogRefreshService` 抓一次,写进 `<数据根>/model-catalog.json`:紧凑快照,只留窗口、回复上限、四个价格、输入模态、推理标记与 `effort` 档位,235 个提供商 / 8 993 个模型约 1.4 MB,一天写一次,启动时在后台读。**请求侧没有任何过滤能力**——models.dev 是 Cloudflare 上的单个静态文件,查询串与 `/api/<vendor>.json` 都不存在(实测:查询串被忽略、其它路径 302),所以过滤只发生在解析之后:全量入库,查询时按「预设 → 目录提供商」映射取该提供商自己的条目,映射不到的(自定义 OpenAI 兼容网关)按模型 id 全局兜底,一方优先序首方优先。这是把"自定义提供商也要有价"与"同一模型各网关价格不同"同时满足的唯一形状。抓取带 `ETag`:存下的校验值作为 `If-None-Match`(只在使用同一地址时才发——校验值属于签发它的源,改地址后必须强制完整 GET),304 即“已是最新”:不重写模型数据,但会记一次 `checkedAt`,因为“今天已经问过”必须由最后一次**检查**而不是最后一次变更来判定,否则源一周不变就会让每次启动都抓一次并留一条运行记录。失败(超时、非 2xx、形状不对)只记一条失败运行,磁盘上的旧快照继续生效。`sourceUrl` 改动后立即后台重抓,在新源回答之前旧快照仍生效。
- **三个写者共用一个闸门。** `preferences`、`providers` 与 `agents` 都会把整份 `settings.json` 读—合并—原子写;`SettingsFileMutex` 按路径互斥,否则后写者会把先写者的分区合并丢(`AtomicFile` 只保证文件完整,不保证合并正确)。文件根不是对象或 JSON 无效时拒绝保存,原文件保持不动。
- **内置 Agent 默认(`agents` 段)。** `settings.json` 顶层 `agents` 把 agent id(`main`/`scout`/`worker`/`plan`/`reviewer`)映射到 `{ providerId?, model, thinking }`,是 `providers`、`preferences` 的兄弟段;`AgentDefaultsStore` 与 `ProviderStore` 共用文件规则(整份读成 `JsonNode`,只替换 `agents` 节点,未知段、未知 agent id 与条目里的未知字段原样保留,写走同一把设置互斥锁与 `AtomicFile`;无效 JSON 或非对象根拒绝写)。启动加载从不抛异常,缺失/损坏的 `agents` 节点按空表处理。解析规则:自己有条目用自己,否则用 Worker 的条目,再否则用第一个已连接提供商的第一个模型、思考关闭;没有已连接提供商时该 agent 没有模型。思考档位按 `ProviderCatalog.ThinkingStepsFor(model, providerId)`(Pi 核对过的 `ThinkingLevels` 表优先,目录快照的 `effort` 档位兜底)夹到模型接受的最近一档,绝不超过它。`SessionRuntime` 建 host 时把解析结果替换进内置 Agent 定义的占位 `ModelSettings("default", …)`,根 Agent 的空定义用 `main` 的解析结果。
- **先提交配置、再写密钥。** 编辑提供商时先把定义写进 `settings.json`,成功后才把用户输入的密钥写进密钥库:配置保存被拒(无效 JSON、写失败)时,已有提供商的旧密钥保持原样。只有"从服务端刷新模型"会先落密钥,因为那次请求本身要用它。新建提供商的 id 对已连接列表去重(同名加序号),保存按 id 匹配,所以两个同名提供商不会互相覆盖。
- **设置分区 `provider`(提供商)与三个窗口。** 页面自上而下:无可运行提供商时顶部横幅;全局「默认上下文窗口」输入框;«模型目录»一行(状态文本「更新于 … · N 个提供商 · M 个模型」或「尚未更新」、可编辑的目录地址与「立即更新」按钮:地址在失焦/Enter 时提交,不是绝对 http(s) 地址就就地报错且不保存,改了就立刻后台重抓,同一地址不重抓;刷新期间按钮显示「正在更新…」并禁用,失败原因显示在该行下方);**已连接**(名称、凭据摘要、状态点、「编辑」「N 个模型」「设为默认」「删除」,删除需点两次,第一次只把按钮改成「再次点击删除」);**自定义提供商**(说明文字「任何兼容 OpenAI 协议的提供商或者服务器」,右侧「添加提供商」);**内置提供商**(每家一行,按预设能力显示「登录」与「API 密钥」,从不显示做不到的按钮;同一家允许多份)。添加/编辑是同一个模态弹窗 `ProviderEditorWindow`,只有名称、Base URL(仅自定义可改)、密钥与请求头:密钥框前复选框勾选=框内是密钥本身(进加密密钥库),不勾选=框内是环境变量名(从预设的变量名起填)。请求头是每个提供商自己的多行框,每行 `名称: 值`(按第一个冒号拆分,名称不分大小写、后行覆盖前行,格式错误报出行号),存进 `settings.json` 该条目的 `headers`,随该提供商的每个请求发送并覆盖同名内置头;值里的 `{session}` 按请求替换为会话 id(OpenCode Zen/Go 需要 `x-opencode-session: {session}`),没有会话的请求(`/models` 列表、测试连接)不发这条头。底部左侧取消、右侧「测试连接」,测试通过后变「保存」;改动 URL、密钥或请求头会回到「测试连接」。测试对支持 `/models` 的预设请求列表(成功即记下模型清单,保存时写入定义),其余预设(Kimi ## 诊断日志

- **形状。** `Microsoft.Extensions.Logging` 是抽象,ZLogger 是唯一输出端,二者只在 `Forge.App` 引用;其他项目不引用 MEL,仍写 `System.Diagnostics.Trace`。`Logging/AppLog` 持有进程唯一的 `ILoggerFactory`(默认 `NullLoggerFactory`,测试与无头场景不写文件),`Program.Main` 在 Avalonia 启动前用 `AppPaths` 的数据根配置它,退出时 `Dispose` 以冲刷缓冲。`AppLog.Create("<类别>")` 返回按调用时刻解析当前工厂的转发 logger(配置前或测试换工厂后创建的静态字段也写到对的地方);App 内按领域集中在 `Logging/AppLogs`(`AppLogs.Session`、`AppLogs.Approval` …),以 ZLogger 的插值 API(`ZLogWarning($"...")`)写日志,类别沿用原 `[tag]` 前缀名。测试用 `AppLog.Use(factory)` 临时换工厂捕获日志。不引入 DI 容器:MEL 内部用到的 `ServiceCollection` 不外露。
- **桥接。** `Logging/TraceBridgeListener` 注册进 `Trace.Listeners`,把其他项目的 `Trace.WriteLine`/`TraceWarning` 转进同一个工厂:消息以 `[tag]` 开头时取 `tag` 作类别,否则类别为 `trace`;`TraceWarning`/`TraceError` 映射为 Warning/Error,其余(含带 category 参数的 `WriteLine`,category 只作为文本前缀保留)为 Information。Avalonia 不走 `LogToTrace`,`Program` 设 `Logger.Sink = AvaloniaLogSink`:只收 Warning 及以上、保留原级别、area(`Binding`/`Layout` …)作类别,模板按位置填值,自身从不抛错。App 自身迁移后不再写 `Trace`,避免同一条日志经桥接写两遍。**降级与崩溃。** 日志目录不可写等配置失败时 `Configure` 返回空操作句柄,应用照常启动、不写文件;`CaptureCrashes` 把未处理异常记为 Critical 并在进程终止前冲刷,未观察的任务异常记为 Warning;工厂被释放后的转发 logger 退化为 `NullLogger`。
- **输出。** 滚动文本文件 `<数据根>/logs/forge-<yyyyMMdd>_<序号>.log`,按天滚动、单文件 10 MB;启动时在后台删除 14 天前的日志文件,删除失败忽略。格式为一行一条 `本地时间(毫秒,不含偏移) 级别缩写 类别 消息`,前缀用 ZLogger 自带的 `local-longdate`/`short` 格式直接写 UTF-8、不产生字符串,异常按 ZLogger 默认格式追加;不用 JSON 格式化器(省去 STJ 源生成上下文)。最低级别默认 Information,`FORGE_LOG_LEVEL`(`Trace`/`Debug`/`Information`/`Warning`/`Error`)覆盖;原 `FORGE_TRACE_FILE` 废弃。
- **内容边界。** 不记密钥、token、请求头值、提示词与消息正文、文件内容;只记事件、标识(会话 id、提供商 id、路径)与错误。被吞掉的异常记 Warning,导致功能失效的记 Error。
- **热路径。** 流式增量、渲染、逐键处理里不写 Information 及以下的日志;需要时先判 `IsEnabled`(ZLogger 插值 API 已在级别关闭时零分配)。

## 关键决策

**面板滚动边界。** 工作台的区域和面板必须按最终分配的宽高测量与排列,滚动视口不得沿用整窗口或整区域的高度。分割、抽屉、最大化/恢复及窗口缩放后,`ScrollViewer` 与虚拟化 `ListBox` 滚到末端应能完整看到最后一行;不可用额外底部留白或滚动事件补偿掩盖布局错误。仍可见的面板不得在每次排列前临时排列到零尺寸,避免改变其滚动偏移。

标题栏 logo 尺寸为 18×18 DIP;PNG 与多尺寸 ICO 均保留源图的透明通道,不得合成灰色或主题色背景。

**应用标识与启动窗口。** 标题栏以 `Assets/forge.png` 替代原来的 Forge 文本,窗口标题仍保留 Forge 供任务栏与辅助功能识别。PNG 为提供的原始 logo;同源的 `Assets/forge.ico` 含 16/24/32/48/64/128/256 像素图层,经 `ApplicationIcon` 嵌入 Windows 可执行文件(安装后的程序与默认指向该程序的快捷方式使用同一图标),并复制到发布目录供安装打包引用。所有窗口通过应用样式共用该图标。主窗口启动居中于所在屏幕的 `WorkingArea`,不占任务栏;按桌面缩放换算尺寸并计入原生窗口边框。可用区域小于通常最小尺寸时降低最小尺寸,避免窗口底部或右侧越界;打开后用实际屏幕、桌面缩放与边框再校正一次,不在用户后续移动或调整尺寸时重新居中。

**偏好、文案与设置分区。** 三件共用的底座,界面语言、字体、终端、Git/PR、扩展与审批五个功能都从这里取,不再各写一份。

- **偏好。** `Preferences/AppPreferences.cs`:`AppPreferences` 的 setter 就是校验器(空字体族回退默认值,字号夹到 9–28),改完立刻生效;`PreferencesStore` 读写 `settings.json` 的 `preferences` 段。写回先把整份文件读成 `JsonNode`,只替换 `preferences` 节点,再用 `Forge.IO.AtomicFile` 原子替换,因此 `provider` 段(仍由 `ProviderSettings` 读)和任何未知字段原样保留。读写都在线程池(`LoadAsync`/`SaveAsync` 内部 `Task.Run`),UI 线程不碰文件;`LoadAsync` 只读不写,也不发通知(加载发生在窗口绑定之前,语言由组合根自己推给 `Loc`)。只有用户改了偏好才写:每次修改重启 500 ms 防抖窗口,窗口结束在线程池写一次;`DisposeAsync` 强制把待写的改动落盘(组合根拆除时调用)。文件损坏或 `preferences` 段无效时用默认值并填 `LoadProblem`,绝不因加载覆盖文件;第一次写入前先把损坏的原文件复制成 `settings.json.bak`,且只备份一次。源生成 JSON 走新增的 `PreferencesJsonContext`。

**合并队列。** 仓库启用 merge queue 时,`gh pr merge` 成功返回但 PR 仍是 OPEN:这时行里报
`已加入合并队列 PR #n`,不谎报"已合并"(合并发生在队列要求满足之后)。

**推进共享分支前必须确认。** 当推送目标就是默认分支(base)、而且确实有东西要推时,先弹一次
`推送到 {base}？`:这是唯一"推上去就没有 PR 先评审"的推送。推功能分支不问;只为"everything up to date"的空推送更不问。

**两处刻意不做。** (1) `在本地合并` 不按"分支已包含在默认分支里"置灰——那要每次刷新多跑一次 `merge-base`;
点击时如实回答"已经在 main 里了"即可。(2) 不加"移除工作区(保留分支)"菜单项:`RemovalFlow` 已拥有该动作且项目树
已经是指定入口,第二个破坏性入口只会复制它的守卫逻辑。;最近一次操作的结果或读失败占那一行(失败时整行染 `ErrorBubbleBrush`、文字转红,有 stderr 时给 flyout):**数字直接跟在会改状态的两个动词后面**,`↓n` 只画在拉取上(警告色)、`↑n` 只画在推送上(强调色),0 不画,超 99 显示 `99+`,抓取不带数字——它是只读刷新,职责只是让这两个数字变成真的。**数字是信息、不是开关**:`CanPull` 只要有仍存在的上游即成立,`CanPush` 只要有远程且不是分离 HEAD 即成立,因为 ahead/behind 只反映上一次抓取,拿它禁用会让“把别人的提交拉进来”这件唯一该做的事不可达;无上游时推送可用(首次即 `push -u`)。三个按钮都不带 force/lease(被拒就是被拒),失败时给按 `GitRemoteFailureKind` 选出的恢复提示。**rebase/merge 进行中**时树上方出现一条 `Border.git-banner`(唯一使用危险色竖条的地方):操作名、冲突文件(每行可点,打开到编辑器;同样的文件在「已改动」里以 `U` 出现)、继续/中止。随活动会话刷新(attach、每回合结束、每次操作后;不自动 fetch);超前落后文本与分支名仍进输入框上条/标题行,`Instruments.SetGit` 改由这一行推。
**某个出货动作失败**时结果只写在这一行里(错误底 + 文字转红 + stderr 的"详情"),不发系统通知:通知仍只属于
"等待 PR 检查结束"那一种后台进程。**PR 表面回来了,但只做"出货",不做"评审"。** `提交目标 ▾` 里按状态列出:打开 PR(对话框填标题/正文/草稿 →
`IPrPlatform.CreatePullRequestAsync`)、在本地合并到默认分支、合并 PR(`gh pr merge --squash|--merge|--rebase [-d]`,
策略与"合并后删远端分支"开关都在对话框里,策略默认压缩、删除开关默认关)、标记可评审(`gh pr ready`,仅草稿可用,不必
确认:它不删任何东西,已经可评审时按成功处理)、PR 检查…(打开检查面板,见下条)、在浏览器打开、删除远程分支(仅 PR 已
合并或已关闭时可用,必确认)。**仍归 agent 的 `pr_*` 工具**:改标题正文、同步分支、看检查详情、评审线程的回复与解决。
已经不需要的东西:UI 从不自动合并、从不强推,任何破坏性动作(合并提交、删远端分支、PR 合并)都要一次确认。
**合并后自动收尾**:合并成功后在同一行里跑一次收尾——仓库根目录 `fetch --prune`,再当根检出正停在 **PR 自己的 base 分支**
(平台报的 `baseRefName`,不是仓库默认分支)且工作树干净时**仅快进**拉动它(不跟"拉取方式"的设置:这一步不经确认,base 上有本地提交时拒绝而不是 rebase/merge);根检出不在 base 上、
有未提交改动或快进失败都只写进这一行的结果(合并本身已成功,收尾失败不改写这一事实),提示仍是"清理工作区交给项目树的
移除入口"。**出货菜单里的四个写都走同一条写纪律**(`RunShipWriteAsync`:工作区标记 writing、`busy` 置位、第二次点击
no-op、刷新排队,结束时 `EndWork()` 释放并补跑排队中的刷新):`在本地合并`、`合并 PR`+收尾、`打开 PR`、`标记为可评审`、
`删除远程分支`。这条纪律同时修掉了原先三处"写完之后行一直 busy"(打开 PR / 标记可评审 / 删除远程分支:它们只调用
`ReadCoreAsync` 而没有 `EndWork`,`readSource` 清空后没人重算 `busy`,该工作区的所有动词就此永久禁用,直到重新 attach);
只有成功才重读(`gh pr ready` 被拒时保留平台原话,不用一次读失败把它顶掉)。合并的根检出路径在弹窗与首个 await 之前捕获
——期间切会话/项目不会把收尾打到别的仓库。收尾全部走
`GitCli` 已有方法(网络预算与手动 fetch/pull 同一个设置),不加新的 git 原语、不强推、不删本地分支。

**PR 检查面板。** 覆盖层(窗口的 `Checks` 槽位),从 `提交目标 ▾` 的「PR 检查…」打开,读当前会话分支的 PR:标题行是

draft/no CI/已关闭)加各桶计数,读失败时在这一行说明原因并**保留上一次读到的检查**(网络失败不等于检查变了);
其下是检查列表,按 `PrCheckText.BucketRank` 排序(失败→取消→运行中→跳过→通过),每行显示桶、名称、工作流、平台原始
state、描述(最多两行)、耗时(`TextFormat.Elapsed`)与两个按钮:详情(打开平台页面)与失败日志(读 `gh run view --job
--log-failed` 的尾部,行数来自 `GitChecksFailureLogTailLines`,展开后跨刷新保留)。底部是「在浏览器打开」「让 agent 修」
「标记可评审」(仅草稿显示)、「刷新」与最近一次动作的结果与读取时间。轮询复用 `PrChecksPoller.ObserveAsync`(与
`pr_checks` 同一对平台调用),间隔是 git 分区的轮询设置;读到判决就停(没有 pending 检查时不再空转 gh),「刷新」重开
一轮;等待超过同分区的「最长等待」后也停下并提示刷新(检查一直不结束不该让前台面板无限问 gh);连续 `PrChecksPoller.MaxConsecutiveFailures` 次读失败或 gh 缺失时同样停下;面板关闭、活动会话切换或再次打开面板(旧面板先释放)
时取消轮询,以及行日志、「让 agent 修」读日志与「标记可评审」的平台调用;关闭后读完的日志不再交给 agent。所有字段只在 UI 线程写(`Dispatcher.UIThread.Post`),测试注入同步 `post`;每次轮询带世代号,刷新后旧读迟到
的结果与收尾一律丢弃,不会覆盖新读或清掉"正在读取"指示。
**「让 agent 修」**:把失败检查的完整 digest(`PrCheckText.Snapshot`:判决 + 每条检查的 run/job id)+ 每个失败作业的
日志尾(`TextTail.Keep`,每份 ≤4000 字符、合计 ≤20000,超出的点名省略)+ 一句"改因、提交、推到当前分支上游;不要推
base、不要合并、不要无改动重跑"拼成英文消息(模型输入,不进文案表),交给当前会话:空闲时立即跑成一轮(转写里带
「PR 检查」来源行),忙时放进输入框等用户按下发送——从不中断正在跑的回合,也不排队第二次运行;交付失败(会话被接管/
归档/移除)时同样落回输入框,消息不丢;落回输入框时**接在已有草稿之后**(空一行),不覆盖用户正在写的内容。读不到的日志原因截到 500 字符。检查的「详情」链接只打开 http/https。面板自身不发通知:失败与否由这一行的判决与计数说明。

**PR 状态与默认分支随刷新读**(attach、每回合结束、每次操作后、手动刷新),但**只在已发布的分支上问平台**:没有上游

工具不进 `run_code` 的脚本注册表)+ 文件与 shell 工具(`AgentRuntimeServices.FileTools`,由 `Forge.IO.FileTools` 一次构造、全会话共享,取会话 worktree 作为工作区)。**`run_code` 的脚本注册表(W14)**:`CollectExternalTools` 同一次遍历里额外收集一份候选——插件工具 + 所有 `SideEffect == ReadOnly` 的文件工具(`read`/`ls`/`find`/`grep`)、web 工具(`web_fetch`/`web_search`)与 MCP 适配器(即服务端 `readOnlyTools` 列入的那些)——`write`/`edit`/`bash`、git/PR 写工具、扩展编写工具一概不进,脚本既调不到也看不到;候选集合由代码在 **评审工具 `request_review`。** 它要读 git,而 Core 不引 git(见 forge-core 的边界),所以 git 侧在 App:`Git/ReviewChangeSetSource.cs`(实现 `IReviewChangeSetSource`,用与 git 工具同一个 `GitCli` 实例)经 `AgentRuntimeServices.Reviews` 交给 `AgentHostOptions.Reviews`,宿主据此注册工具;没有它就没有这个工具(单元测试里的宿主默认没有)。变更集两种:带 `step_id` 是那一步自己的提交对它的第一父提交(根提交对 `GitCli.EmptyTreeSha`,为此把该常量从 `private` 提升为 `public`);否则是 `base`(默认仓库默认分支)加未提交与未跟踪的树。**分支模式的基准必须先解析成提交再取与前 HEAD 的 merge-base**,`git diff <merge-base>` 才是“这条分支加上未提交部分”:直接 `git diff <base>` 是两点语义,基准一旦越过fork 点(fetch 后默认 `origin/main` 就会),上游新提交在包里会显示成本次变更在删除它们,与 `git_diff`/PR 正文/`pr_create` 的 `base...HEAD` 正好相反;取 merge-base 同时让 `ReviewChangeSet.Base` 是个 sha——它是 ref 名时 `ShortSha` 会截出 `origin/` 这种前缀。基准与 HEAD 无共同历史时直接 `Failed`。`GetDefaultBranchAsync` 解析出当前分支时同理只审未提交的树(与 `git_diff` 一致)。diff 文本与文件清单用一次 `GitCli.GetDiffSnapshotAsync` 读(一次 git 调用同时给文本与解析后的文件),不跑两遍也不在两份实现里各解析一次;`IncludeUntracked: true` 使未跟踪文件进入清单但不进入 diff 文本,评审包固定写明这一句。仓库解析不出、基准不存在或与 HEAD 无共同历史、提交对象已被 rebase/gc 抹掉、超过 git 的捕获上限等预期失败都返回 `Failed` 文本而不抛,取消照常上抛。提交清单按 `paths` 同样收窄,取上限+1 条以区分“恰好这么多”与“被截断”。工具目录(`ToolCatalog`)把它归到 `agents`,可以像其他内置工具一样关掉;它会派生 Reviewer 子 Agent,所以 `agents` 设置里的子 Agent 开关关掉时它与 `spawn_agent` 一起被 `SessionRuntime.ApplyDisabledTools` 撤下(`SpawningTools`),否则开关可被绕过。未跟踪文件只探前 8000 字节(git 自己的二进制判定窗口)来定 binary 标志,内容不进包;提交清单上限 1000 可经构造参数注入供测试。`pr_create` 与 `GitReviewLedger` 完全不受影响:评审不满足自评闸门,结论也不落库。

**步骤提交(`StepCommitter`)。** TODO 条目从非 done 变成 done 时(只有 Agent 能改状态:面板不再有勾选框,见下方“TODO 面板”),把会话 worktree 里全部未提交改动提交到会话分支;开关 `gitStepCommits`(默认开)。子会话(`ParentSessionId` 非空)继承父会话的 worktree,其步骤一律跳过(不把父会话的改动卷进子步骤);无 worktree 的常规会话跳过。范围是 `add -A` + `commit`(会话 worktree 专属),提交说明优先 `commit_subject`、否则条目标题,正文是 summary;verification 不进提交说明。失败(钩子拒绝、冲突中、游离 HEAD)不回滚 done:工具结果与 TODO 行显示失败原因并提供“重试提交”;提交尝试失败后把 index 复位到 HEAD(mixed `git reset`,不动工作区),被拒绝的改动回到未暂存。晚取消:提交对象与 ref 已存在、只差慢 `post-commit` 钩子时被取消(git 被杀),重读 HEAD,前进了就把新 sha 记到该步骤并报已提交;取消发生在 `git add` 阶段则照常抛取消。同 worktree 的提交按路径门串行,不同 worktree 并行。计划摘要(`plan_summaries`)加上各步骤的 sha/summary/verification 由 `PrBodyRenderer`(Workspace)渲染成 PR 正文。

**事件路由与渲染。** 按 `AgentEvent.AgentId` 分发到各自的轮次卡模型,子 Agent 文本不进主会话。所有非文本事件经 `FrameCoalescer<AgentEvent>` 合并:生产者在任意线程无锁入队(`ConcurrentQueue`),只有当前没有已排队的 flush 时才 `Dispatcher.UIThread.Post` 一次(`DispatcherPriority.Background`,用 `Interlocked` 标志控制);一次 flush 在 UI 线程按入队顺序处理当前积累的项目,单次上限 `MaxItemsPerFlush`(2048),超出留到下一帧。优先级选 `Background` 而非 `Render`:skill 建议大批量/低优先级更新用 `Background` 以免挤占输入与渲染,且 flush 本身不占用渲染帧;持续流下仍是每调度周期最多一次 UI 更新(≈ 每帧一次),无需 `TopLevel.RequestAnimationFrame` 或 16ms 定时器。文本增量在后台线程合并进 `TranscriptViewModel` 的 pending 缓冲,flush 由同一个合并器调度:每次 flush 先排空文本、再按 FIFO 处理非文本事件,所以文本落在其后的非文本事件之前;非文本事件间顺序与 Core 发出顺序一致。会话释放时合并器停止调度并丢弃未处理项,释放后不再往 UI 投递。流式增量收进 `TurnTextViewModel` 的流式 Markdown 文档(见下方「聊天 Markdown 渲染」):一次 flush 只重解析未定稿区、只刷新末尾那块,已定稿的块永不重排,也不重建控件。文件树、规格树各自展开成一个 `RangeObservableCollection` 行列表(改动 diff 走 AvaloniaEdit 文档,不再是行列表)配 `ListBox`/`VirtualizingStackPanel`(展开 = 区间插入/移除),树/行视图模型、`FileIndex` 与规格图读取都在线程池构建、UI 线程一次 `ReplaceAll`。轮次卡头“第 N 轮 · 时间 · 耗时 · 输入/输出”:`AgentTurnCompleted` 是实例累计用量,卡上显示本轮差值;子 Agent 用 `AgentSubAgentFinished` 的本 run 用量;未上报一律显示“—”。

**聊天 Markdown 渲染。** 助手回复按 Markdown 渲染:标题、段落、列表与任务项、引用、表格、分隔线、链接、围栏代码块,复用 diff 预览与计划面板的同一套 `MarkdownBlockParser`/`MarkdownRenderer`/`Resources/MarkdownStyles.axaml`;用户消息仍按纯文本渲染(用户打进来的是字面文本,过 Markdown 会把 `*`、`_`、`#` 当语法吃掉)。渲染是**增量**的,不是每帧整段重排:`TurnTextViewModel` 持一个纯状态机 `Changes/Markdown/StreamingMarkdown`(无 Avalonia 依赖,可单独测),把回复切成「已定稿块前缀 + 未定稿区」。定稿边界是**围栏代码块之外**的最后一个空行;前缀只追加、永不重排。还能被后续行延长的块(列表、缩进代码、未闭合的 HTML 注释)由**边界之后的第一行**决定:仍是同类列表项 / 仍缩进 ≥4 才留在未定稿区继续长,否则照常定稿;后续内容还没到时先不决定,所以松列表(项之间有空行)不会在中间被切成两个列表,而结尾段落一开始写、列表当帧就定稿。围栏代码块与 YAML front matter 解析完即闭合,不参与这条判断。未定稿区每帧整体重解析(它是两个空行之间的内容,通常就是一个段落):末尾块若仍是同一段落/标题,只换 `Inlines`(不建控件、不动兄弟节点);若仍是同一围栏代码块,只换 `Text`;列表与表格就地生长:来自**已结束行**的表格行、以及后面已有一项从已结束行开始的列表项保留原控件,只重建其后的部分(正在写的那一行还可能变,例如 `-` 变成 `-x` 而并入前一项);引用与类型变了的块才重建该块及其后缀。正在写的行若以半个代理对结尾(emoji 跨 delta),那半个字符先不显示。超过 4096 字的单段落按行收口成若干已定稿块(分片之间不留块间距,读起来仍是一段),避免每帧对整段做内联解析与文本整形;`Complete()` 再把全文解析一次并与 `stable + live` 逐块比较 `(Kind, StartLine, EndLine)`,不一致(缩进代码跨空行、HTML 注释跨空行、围栏启发式判断偏差、上述段落收口)就以整篇为准整体替换一次控件树——**最终渲染恒等于「对全文做一次块解析」**,这是可断言的不变量,也是分片启发式可以激进的前提。分片解析传 `top: false`(块解析器的 `Parse` 多一个 `bool top = true` 形参),否则一段以 `---` 开头的分片会被当成 YAML front matter 吞成代码块。flush 仍走既有 `FrameCoalescer`,状态机与控件都在 UI 线程,不加锁。

**通知(窗口内 Toast 与系统通知)。** 全部在 `src/Forge.App/Notifications/`,唯一入口是 `INotifications.NotifyAsync(level, LocText title, LocText body, key?, ct)`:通知中心按三件事分流——开关关掉就什么都不做;`IsBackground` 为真走 `SystemNotifier`(桌面通知);否则在窗口顶部居中弹一条 Toast。

**后续任何界面功能需要告诉用户“某件事发生了”,一律走这个入口。** 不许自建 toast、自绘横幅、`MessageBox` 式弹窗或引入第三方通知库,也不许绕过它直接调 `ISystemNotifier`:开关(偏好 `notifications`)、前台/后台分流、去重与计数、停留计时、语言切换后的重新解析都只在这一处成立,多开一个入口就多一套不受开关与系统通知约束、也不随界面语言切换的提示。接线方式按生命周期选:会话级对象持可空 `INotifications`(`NotificationExtensions.Notify` 即发即忘、不抛不阻塞),服务级由组合根注入,叶子视图与窗口 code-behind 读 `NotificationCenter.Current`。只有两种情况不用它:失败当场就能在界面上看到(内联错误文本、审批卡、生命周期对话框自身的结果),以及纯回执(见下方“不接”)——这两类已有常驻提示,再弹一条只会稀释真通知。

**可通知的状态只有四种(`NotificationLevel`),不新增。** 选等级只看“用户是否需要为它做点什么”,不看文案语气;等级同时决定等级条与等级词的颜色和停留时长,两者不分开配置:

- `Info`(提示,4 秒)——事情发生了,但不需要任何动作(例如任务完成、后台工作就绪)。
- `Success`(成功,4 秒)——用户发起的工作按预期完成,值得确认一下(例如 PR 已创建、步骤已提交成功)。
- `Warning`(警告,6 秒)——工作完成了,但结果里有用户可能想看的东西(检查点失败、MCP 服务器异常、设置回落默认、审批卡开始等待用户);停留比 `Info` 长,因为它要求扫一眼。
- `Error`(错误,8 秒)——工作失败或被拒绝(回合失败、保存失败、Git 操作失败、扩展宿主不可用);停留最久,因为它常常是用户唯一看得到的失败痕迹。

两行文本:标题一句话说清“发生了什么”,正文给“哪一次/为什么”;两条都是 `LocText`,文案进 `Localization/Strings.Notifications.cs`(`notifications.*`),不写死在调用点。去重 key 要稳定地指“同一件事”(如 `approval:<session>:<tool>`),缺省 key 是"等级 + 标题 + 正文",只适合天然幂等的句子。新增接线时在 `tests/Forge.App.Tests/Notifications/NotificationWiringTests.cs` 补一条用例,钉住“哪条路径会通知、用哪个等级、key 是什么”。

`NotificationCenter.Current` 是窗口浮层的取用点(与 `ApprovalServices.Current` 同一套接缝),组合根在窗口之前创建它、在拆除时最后释放。Toast:最新的在最上面、最多 5 条,同 key 命中就合并成一条并计数 `×N`(key 缺省是“等级 + 标题 + 正文”,重复到来会重启计时,已被判退出的条目会被召回);停留时长按等级(4/4/6/8 秒,见上),到时先标 `IsLeaving` 走淡出 + 下滑,`ExitDelay`(180 ms)之后才从集合里移除,邻居的平移就在这个窗口里完成。动画不用 `RenderTransform` 的样式动画(headless 里没有对应动画器,会让 `Window.Show` 抛错):样式只管透明度,位移由 `Notifications/ToastStackPanel` 把“附加属性动画 → `TranslateTransform.Y`”自己镜像出来,新条目从 -6px 滑入、离开的卡片由浮层在 `IsLeaving` 翻转时下滑 6px。计时用 `TimeProvider` 的 `ITimer`(测试注入假时钟),集合与计时只在 UI 线程动,`NotifyAsync` 可从任意线程调用(经 `post` 缝合,默认 `UiThreadDispatcher.Instance.Post`,没有 Avalonia 时退化为内联调用)。视图 `Views/NotificationOverlay` 在主窗口工作区行顶部居中、`IsHitTestVisible=False`(纯展示,不挡点击);它挂到窗口后盯着主窗口 `WindowState` 与所有 Forge 窗口的 `IsActive`,只把“最小化或没有 Forge 窗口在前台”写进 `IsBackground`。文案在 `Localization/Strings.Notifications.cs`;开关是偏好 `notifications`(默认开,旧 `gitNotifications` 只读兼容、不再写回),设置分区 `notifications`(order 550)只有这一个复选框,Git 分区不再有自己的通知开关。**释放**:组合根在 `ConfigureAwait(false)` 之后拆除,`Dispose` 可能落在池线程上,所以它用 `Interlocked` 幂等、就地停计时器与字典、只在 UI 线程清空绑定的 toast 集合(否则改走 `post`),并把 `disposed` 作为排队动作与计时器回调的第一道闸;三条用例钉住池线程释放不清集合、释放前排队的 toast 被丢弃、释放后的通知既不显示也不发桌面。

**通知权限引导(14f)。** 平台把通知关掉时,`SystemNotifier` 的失败原先只有一个 `[notify]` trace,用户无从知道为什么没有弹出:新增 `Notifications/NotificationPermissionGuide.cs` 的 `INotificationPermissionGuide`(状态 + 两个动作)。`NotificationPermissionState` 四个值来自 W0 冻结的接缝:`NotApplicable`(这个构建在平台上没有可用的通知工具,什么都不发)、`Unknown`(平台问不出来,也还没试过)、`Granted`/`Denied`(真发了一条测试通知的结果)。配置分区用的宽面是另一个接口 `INotificationPermissionSection : INotificationPermissionGuide`(加同步的 `State`、`CanOpenSettings` 与 `SendTestAsync`),不往 W9 已调用的那个冻结接口上加成员。`SystemNotificationPermissionGuide` 的初值按平台定(无工具→`NotApplicable`,否则 `Unknown`),`SendTestAsync` 发一条真通知并用 `ISystemNotifier.TryNotifyAsync` 的返回值把状态落成 `Granted`/`Denied`(volatile 字段,进程内记住,测试也允许下一次测试推翻上一次)。探测用“真发一条”而不是查权限:受支持的平台没有能让未打包程序查询通知权限的接口(Windows 要装 Start Menu 快捷方式与 AppUserModelID),这条结论写进类注释。`OpenSettingsAsync` 用平台自己的页面(Windows `ms-settings:notifications`、macOS `x-apple.systempreferences:com.apple.preference.notifications`),Linux/`NotApplicable` 直接 `false` 且不调 opener;默认 opener 是 `Process.Start(new ProcessStartInfo(uri.AbsoluteUri) { UseShellExecute = true })`(`MainWindowViewModel` 对 `explorer.exe` 同一写法),URI 是本类常量,不拼任何命令行;opener 失败或超过 5 秒只 trace 并返回 `false`,除取消外不抛。`ISystemNotifier` 因此增 `Task<bool> TryNotifyAsync(...)`(是否交给了平台),`NotifyAsync` 转为委托给它、`NotificationCenter` 照旧不看结果;`true` 只代表交给了平台,不代表用户看见了。设置分区 `notification-permission`(order 560)是这套接口的设置页:一句状态文案(随 `Loc.LanguageChanged` 重算)、“发送测试通知”(运行中禁用并换成进行中文案,结果回填状态)、“打开系统通知设置”(仅 `CanOpenSettings` 为真时显示)、以及 `notificationPermissionReprompt`(“再次提示”)开关;文案键 `notifications.permission.*`。组合根持有单例并暴露成 `AppComposition.NotificationPermissionGuide`(W0 预留的可空槽),W9 首启向导只调冻结接口,不碰 `Notifications/**` 的内部。

调用方(每条都带一个稳定的去重 key,连续重复只累加 `×N`):会话侧——回合失败/发送失败(Error)、提供商未配置(Error)、检查点失败(Warning)、子 Agent 失败或被停止(Error/Warning)、附件被模型/提供商拒绝或非 UTF-8 文本(Warning)、换模型后附件阻塞发送(Warning);Git 侧——步骤提交被拒(Error)、fetch/pull/push 失败(Error,在 `GitSyncViewModel` 的操作结果处);环境侧——扩展宿主失败(Error)、MCP 服务器失败(Warning)、模型列表拉取失败(Warning)、`settings.json` 回落默认(Warning)、启动或数据库初始化失败(Error)、项目列表读取失败(Warning)、彻底删除的收尾重试失败(Warning)、终端进程非零退出(Warning)、文件保存失败(Error)、LSP 应用失败(Warning)、评审保存或存储失败(Error),以及审批卡开始等待用户(Warning,工具审批与扩展草稿两个入队点)。接线方式:会话级经可空的 `INotifications`(`SessionWorkspaceViewModel` 及其转交的 `ComposerViewModel`、`StepCommitter`、`GitSyncViewModel` 的尾参),服务侧(宿主、MCP、审批、步骤提交)由组合根注入,叶子视图(编辑器、终端、评审控制器、窗口 code-behind)读 `NotificationCenter.Current`。**不接**:生命周期对话框(fork/交接/合并/删除)里当场就能看到的失败、上下文压缩、插话/排队回执、折叠与高亮降级、语言/模型切换、TODO 步骤提交成功——都有常驻内联提示,弹出来只会稀释真通知。

**降级。** 提供商未配置 / Host 未找到降级为明确的 UI 状态,绝不抛异常或伪造模型调用。审批:只读自动放行,`todo` 工具显式放行(写会话清单而非工作区);其余写/执行为 Ask,经审批队列由用户当场决定(见“审批队列与 Agent 扩展”),拒绝时轮次卡显示“已拒绝”。

**树一律扁平虚拟化。** 项目树、文件树、规格树(含「已改动」树)都是扁平 `RangeObservableCollection` 行列表 + 虚拟化 `ListBox`;展开/折叠只对子树做区间插入/删除,展开状态跨刷新保留(按路径/id 记住);文件树与规格树刷新仍是整表 `ReplaceAll`,滚动位置会回到顶部(未改为按路径 diff 的区间更新);行模型负责缩进档数与引导线,视图不递归。后台计划只吃 UI 线程上快照好的不可变数据(会话运行集合、Agent 层级都归调度器所有)。

**树与图标。** 文件树、项目树、规格树同一套样式(参考用户 2026-11-05 给的图):
- 标题栏/工具按钮的图标全部取自 Fluent System Icons 的 24px 系列(Regular = 空心态,Filled = 实心态),几何集中在 `Resources/Icons.axaml`。FIS 图形的最细处约 1.5 个网格单位——12–15px 渲染时低于这个尺寸就糊成点,所以树里的小箭头按 12px 画。设置按钮是六齿齿轮(`IconGear`):八齿在 13–15px 下读成一团星芒,六齿才看得出是齿轮。panel 工具图标 13px、设置 15px、窗口最小化/最大化 11px。
- 行高 28px;左侧项目/会话行图标为 12px(`FluentIcon`,容器箱子与会话气泡同尺寸,比字号退后一档),Agent 行图标保持 14px;超长标题省略并在截断时显示全文 tooltip。活动会话行有浅强调底色,气泡本身只用一枚 Regular 图形,靠颜色(次要色 → 主色)表达激活;标签条上激活标签则换成 Filled 气泡,两者不再共用“同一条几何 + 填充开关”。会话气泡是 Fluent `chat_sparkle`(标签与项目树同一枚),文件预览标签用的是文件树里那枚 `document`——两者都直接引用同一个几何对象,不各画一份。文件内审阅的“加一条评论”入口是 `comment_add`。文件/规格树用同一套 `FluentIcon`。文件夹分闭合/打开两种,展开时换成打开的;文件是带折角的纸张;规格节点用文件图标,有子节点的用文件夹图标。
- 项目树行尾工具只有一枚 10px 图标(20px 按钮):常规对话与 worktree 行是加号(新建会话),项目行是分支加号(新建分支);会话行没有行尾按钮,整行本身就是打开入口,有子 Agent(direct 子件)的会话行在气泡前的箭头里展开。
- 箭头是 Fluent `chevron_right`(`TreeChevronGeometry`,`PathIcon` 填充而非描边),折叠向右,展开时 rotate 90°;填充形内部的笔画只有约 1.5 个网格单位,8px 时会落到 1 像素以下、几乎看不见,所以按 12px 画、允许它在 10px 的槽里左右各溢出 1px——树里凡是填充图标都受这条约束。项目树的箭头列再往右让一个面板内边距(6px),使它离面板边缘的距离与面板自身的 padding 一致。

- 引导线:文件树与规格树仍在每个展开的文件夹下面画一条 1px 竖线,对齐它的箭头中线,一直延伸到最后一个子孙行;项目树不再画(容器/会话/Agent 行统一用 `IndentMarks.Plain`:同样的 16px 进深节奏,但不带竖线,免得在窄 panel 里多出一条竞争视觉的列)。行模型维护“祖先展开”位掩码,`IndentMarks.ForMask` 返回缓存数组,模板不分配;折叠/展开时递归刷新子孙的掩码。

**Agent 树。** 会话与它的主 Agent 是同一个东西,所以只占一行:主 Agent 不再单独挂一行子项,它的子 Agent 直接接在会话行下(`PlanSessionAgents` 把主 Agent 的子行提上来),展开/折叠交给会话行前那个箭头——点箭头只展开,点标题打开的是主 Agent 会话;子 Agent 行按 `AgentSubAgentStarted` 的父 `AgentId` 继续嵌套到孙 Agent。点子 Agent 行等于在底部组的子 Agent 下拉里选它(`ProjectTreeViewModel.OpenSubAgent` → `MainWindowViewModel.OpenSubAgentTabAsync`):先把该会话带到主区前台(必要时加载),再展开底部组并打开该标签;已结束的那种走 `OpenFinished`(只读 + 从存储回放 transcript,重启后也有内容)。反过来,底部组当前选中的子 Agent 标签会让树里对应行拿到 `IsActiveAgent`,行底用与活动会话相同的 `active-row` 浅强调底。图标按 `Kind` 选线框(Scout 放大镜、Worker 锤子、Plan 三行、Reviewer 对勾、未知回落会话气泡);行首只放图标,展开箭头跟在标题后面;状态不再是文字:标题右侧一个标记——排队/运行/失败/已停止/未知都是圆点(`Ellipse.status-dot` 的 `agent-*` 变体),只有正常完成是绿色对勾(`IconTodoDone` + `wc|FluentIcon.status-check`),原文案退到该行的 tooltip;不画引导线,只靠缩进和图标区分层级。图标按状态上色(`AgentState`):运行中 `RunningBrush` 加透明度呼吸动画(1↔0.45,1.6s),排队/未知灰、完成绿、失败红、已停止橙。Avalonia 12.1.x(本仓 12.1.6)读不到系统的“减少动画”设置,而本模块不允许 P/Invoke,所以只留了 `TreeMotion.ReducedMotion` 开关,尚未接到系统设置。**子 Agent 行有两个来源。** 树自己查的是**全部**会话(不再只查 `ParentSessionId` 为空的根),于是每个会话的子 Agent 行可以按下 `parent_session_id` 从存储里直接推出来(`PlanStoredAgents`):没被打开的会话也有子行、也有展开箭头,重启后不必先点一次会话。会话一旦加载,就用会话 VM 的实时名单替换(`PlanSessionAgents`,带运行状态与 kind 图标);`RefreshAgentTrees` 对没有实时名单的会话继续用存储那份,不会把子行清空。启动时树的第一遍重建还没有会话(标签是其后才恢复的),所以 `InitializeAsync` 末尾仍补一次 `RefreshAgentTrees`;`LoadHistoryAsync` 回放完 finished 名单后发 `SubAgentsChanged`,让已加载会话的行从存储版切换成实时版。重启后层级靠递归查询 `parent_session_id` 还原;存储没有运行状态列,状态从最后几条存储消息推断(`Cancelled.` 结果=已停止、错误结果或悬空调用=失败、最终文本=完成),推不出显示中性"已结束",不把未知当成完成。

**已改动徽标。** 与"改动"面板同语义(对 HEAD 的整树差异、含未跟踪、路径按会话目录裁剪,`scratch/…` 下也有计数);二进制只显示状态字母,绝不显示 `+0 -0`;watcher 700 ms 一跳,补丁按"状态 + 每文件大小/修改时间"指纹缓存,无变化不重算。

**会话标签与归档。** 会话标签按会话 id 唯一:重开同一会话复用并重绑已有标签;归档先关闭其标签再释放运行时与视图模型。

**区域宽度分配。** 每区有最小宽度:项目/检视 200px、主 360px;首次布局的默认宽度是项目 260、检视 275、预览列 420,之后以保存的快照为准。拖动区域分隔条时:
- 分隔条另一侧紧邻的区域吸收全部增量。
- 被挤压的那一侧,主区先缩到最小宽度,其余区域再按离分隔条由近到远依次缩到最小宽度。
- 边栏缩到最小宽度后继续拖,越过最小宽度的一半(`CollapseOvershoot` = 0.5)才自动隐藏;这段粘滞是为了防止贴着最小宽度拖动时误隐藏。主区永不隐藏。
- 空间够但边栏总宽过大时(例如第一次 arrange 之前就打开了预览,检视区已经加上 `PreviewWidth`),也同样先把边栏按顺序缩到最小、再隐藏非 protected 的边栏,主区最后拿到 ≥360px;`protected` 区域只缩不藏。
- 窗口变窄时先缩主区,再缩检视区、项目区,仍不够就依次自动隐藏;变宽的增量给主区。

计算由纯函数 `RegionWidthSolver` 完成,拖动路径不分配内存,松手才写快照。不用 `GridSplitter`,因为它只能调相邻两列。零分配要算上挂着 UI 的整条同步事件链:`ObservableObject` 按属性名缓存 `PropertyChangedEventArgs`;控件只对影响自身的属性名刷新(宽度类属性只触发 arrange,不重算标题栏)。

**Panel 标题栏。** 28px 高(`PanelChrome.TitleBarHeight`,浮出窗口的标题条也读它)。左侧是标题或选项卡条(只在本组内拖动排序,不跨组)。`StackPanel.Orientation` 是组件局部的布局责任：未指定时保持 Avalonia 竖向默认；确需横排的工具条/按钮行在自己的容器上声明 `Orientation="Horizontal"`。不得在 Window/App 范围的 StackPanel 类型样式中设置方向，否则任意嵌套的菜单与面板内容都会被横排。标题栏里的文字分两级:单块标题(`PART_Title`)取强调档 `FontSizeMd`(默认 14px)+ `Bold`,选项卡标签(`PART_Label`)取正文档 `FontSizeBase`(默认 13px)+ `Normal`,与标签页正文字号一致,标签条比标题更紧凑。字重只取界面字体链上真实存在的两档(400 / 700):`SemiBold` 在中文侧没有对应字体面——默认链里只有 Segoe UI 带 600(`seguisb.ttf`),Microsoft YaHei 只有 400 / 700 / Light——600 在汉字上被匹配成 700,于是同一段文字拉丁停在 600、汉字跳到 700,中英混排的标签条上最刺眼。浮出窗口的标题条由 `FloatingPanelWindow` 自建(不读 `PanelChrome` 模板),同样取 `FontSizeMd` + `Bold`,dock 与浮出时面板标题长得一样。激活与未激活标签仍只靠颜色区分(次要色 → 主色),不靠字重。右侧图标按钮按能力显示:
- 自动隐藏/停靠:两边边栏 panel 有,作用于整个区域。一个按钮、一个名字:tooltip 恒为“自动隐藏”,实心图钉 = 已停靠(点击自动隐藏),线条空心图钉 = 已自动隐藏(点击停靠回来),所以图标本身就是状态。主区底部组没有这个图钉,也没有自己的一套“收起”形态:它的收起就是下一条的缩小(只剩 28px 标题栏,标签与工具都还在),由会话底部的“子 Agent · 收起/展开”开关、标题栏自己的还原按钮、以及开启终端时自动展开共同驱动,三处改的是同一个状态。
- 缩小/还原:有可接收空间的展开同伴时显示(`IconMinimize` → 缩成标题条;`IconPanelRestore` → 四角对角箭头的 `arrow_expand`,读作“撑开回来”,与窗口自身最大化/还原的 `square_multiple` 分开,免得两个“还原”在同一屏里撞图形);缩小仅保留 28px 标题栏,正文隐藏但不销毁。同区域的纵向同伴回收高度;预览组缩小为检视区顶部整宽标题条,文件与工具列回收其下空间。最后一个展开同伴消失时自动还原。缩小状态不持久化,不替代整个区域的自动隐藏。
- 没有“放大”:panel 不提供“撑满所在区域、收起同区域其他 panel”的按钮,`PanelChrome`/`PanelModel` 都不带该能力;要局部放大用缩小同区域的同伴(上一条)或把标签浮出成独立窗口。
- 新窗口/停靠:只给可浮出的对象。
- 其他按需工具,如子 Agent 的“已结束 (n)”:标题栏里是 20px 扁平按钮(“已结束 (n)” + 小 chevron),点开 Flyout 列出已结束的子 Agent;空列表时按钮禁用。

除预览组的关闭按钮外不放菜单和关闭按钮;预览组标题栏有 X 按钮,点击倒序关掉组内全部标签 → 组不再 docked-visible、借用宽度归还 Main,与关掉最后一个预览标签同终态。用户关闭经终端与文件内容守卫串行处理,取消即停止;关闭其他标签也逐个等待。选项卡自带关闭,右键菜单每个选项卡一份实例。选项卡视觉参考 VS 工具窗口标签:25px 高、贴标题栏底边;未激活透明、文字居中次要色 + `Normal` 的 `FontSizeBase`,悬停文字变主色;激活标签的轮廓由 `TabHeaderView` 自己画(`Render`,不是模板里的 `Border`),底色取所在 panel 的背景(主区白、边栏灰),外轮廓上两角向内圆 5px,两条侧边到底边处**向外**拐出 5px 圆角(弯弧从侧边切出、在底边处贴平,竖入平出,不是往回收口的圆角),所以标签顺弯弧长回 panel 正文里;底边本身不画线、压在标签条下方那条 1px 分隔线上,标签与正文连成一片。边框是**一条填充的环**(外轮廓与它的垂直向内偏移拼成),不用描边路径。脚的弧是**凸弧**,内缘用**同一圆心、半径 R+1 的同心弧**,环厚沿脚弧保持 1px;同心内弧与底边上方 1px 那一行的交点在 x = r + R − 2√R。交点外侧保留约 2px 的短直段,再用一段两端切线分别匹配分隔线与内圆弧的三次贝塞尔曲线过渡；R=5 时曲线及直段都在 tab Bounds 外,不向 tab 内画横向边框,也不以锐角硬折进圆弧。正文底色覆盖 tab 下方的分隔线,脚边框只在外侧与露出的分隔线相接。**外翻必须真正绘制在标签控件矩形之外**: Avalonia 的 `TemplatedControl` 默认 `ClipToBounds=True`,而弧脚左右各伸出 `Bounds` 5px,若不在 TabHeaderView 主题中显式设 `ClipToBounds=False`,整段外弧会被自身裁掉,连线在控件侧边处截断,看起来既没有圆弧又像断口;`PART_Tabs` 同样禁用子裁切并左右留 5px 安全区,最外层 `ScrollViewer` 仍负责按可视窗口裁切。上一轮只改弧形几何而漏了这一裁切约束,因此用户实测仍看不到效果。曾用“沿路径描 1px”的写法:描边在凹陷角上要么离开外轮廓留一道白缝、要么在拐角收口,缝就出在那里。模板里那个 `Border` 只能把角往内圆,所以它只留 1px 厚度占位、不再画底色和边框;键盘聚焦(`:focus-visible`)只换环的颜色为强调色,未激活但持有焦点时只画环不画底。可关闭标签始终预留 16px 关闭槽与 6px 间距,关闭 × 只在激活或悬停时可见、可点击,不改变标签与相邻标签的几何;会话标签(`TabKind.Session`)在标题前多一个 14px 的气泡图标(`IconChat`,与关闭槽同属标签几何而非标题文字):未激活画线框、激活时同一路径填充成实心气泡,颜色跟标签文字走;图标不占位时(`IsIconVisible=false`,即其他类别标签)不预留宽度。不可关闭的标签(TODO / 评审 / 规格树)没有关闭槽,左右内边距对称(`12,0,12,0`),标签文字因此落在标签几何中心。标签放不下时,标签条右端出现 `…` 按钮(`PART_Overflow`,20px,独占 `Auto` 列,实心圆点 `IconEllipsisSolid`):点击列出所有被裁剪的标签标题(只列当前不在视口内的),点标题直接激活该标签并把它滚进可视区。按钮所在列在无溢出时因 `IsVisible=false` 宽度为 0,所以它只在标签条已经太窄之后才占宽;占宽只会让视口更窄、不会让标签重新变得完整,所以判定不会振荡。溢出判定在每次 layout 之后用 `ScrollViewer` 的 `Offset`/`Viewport` 与各标签 `Bounds` 比较,不分配内存,只在翻转时写 `HasOverflow`。滚轮横向滚动保留。

**文件预览与编辑。** 打开文本文件即进入 AvaloniaEdit 可编辑视图,默认不换行,可水平/垂直滚动到完整内容;20px 图标切换换行,支持选择、复制、撤销/重做与工具栏保存/Ctrl+S,不再切换着色预览与无着色编辑模式。文本与符号不得过滤或用显示占位字符替换。原生文档与撤销历史属于文件模型,切换标签或分离视图不销毁缓冲。着色使用 AvaloniaEdit.TextMate,不重建全文件行列表。迁移期间原生文档增量镜像到 `Forge.Editor.TextDocument`,保存仍经其原子编码保存,保存中的后续编辑保持脏。镜像故障须可见,保留原生未保存文本并阻止错误保存,不能把同步故障当成已保存。文件读取/文本物化/保存在线程池;内容显示不等待 LSP 启动,后台打开语言会话,变更/保存/关闭沿既有同步泵发送,失败显示独立语言服务状态。绝对路径去重复用文件标签,避免同 URI 多份缓冲。未保存关闭/替换需确认,多文件确认全部通过且内容未变才允许继续,不伪造已保存状态;保存中禁止替换/关闭。归档不保存也不丢弃仍打开的编辑。加载取消、标签关闭取消在途加载和语言会话打开。

文件超过 8 MiB 明确拒绝,不再静默截取 20000 行;超过 1 Mi 字符跳过 TextMate,仍可显示、编辑和保存完整文本。预览/文件列之间拖动保持检视区总宽不变,在预览最小宽与文件侧栏最小宽之间分配,不沿用打开预览时向主区借宽的 setter。

**文件编辑与行评审。** 同一代码视图支持文本选择、行号选择、复制、撤销/重做和保存,语言服务沿现有 `Forge.Editor` 接入。选中文本或点击行号后显示评论图标,点击图标展开锚定所选末行的浮动评论框,显示行范围与“保存草稿 / 立即发送 / 取消”;草稿复用 `ReviewStore` 持久化,单条发送只包含该评论,批量发送将当前文件的草稿合成一次消息,队列接受成功后才标记已发送。浮层不推开后续代码、不向源文档插入占位文本,自身输入和复制不被编辑器截获。

以下交互边界已向用户提问,当前未获可用答复,暂采用默认项:常用 LSP 交互覆盖诊断、补全、悬停和跳转定义;发送目标固定为文件所属会话,忙时沿既有队列排队,不随当前活动会话切换;草稿允许基于未保存代码,发送前必须保存成功且内容仍对应评论锚点,失败保留草稿并提示;普通文件仍可编辑保存,无所属会话时不启用评审发送。编辑后评论锚点须跟随文本变化,无法重定位时明确显示失效,不把错误行号当成有效评审。

**diff 中的行评审。** 改动视图复用同一套评审浮层:`ReviewOverlay` 绑定 `IReviewSurface`,文件预览由 `FileReviewController`、diff 由 `DiffReviewController` 实现;diff 里的选区按行映射到 (文件, 新侧行号),跨文件或只落在删除/占位行上不出评论图标,拆分模式只在右侧(新)编辑器评;锚点用该文件的真实 `FileDiff`,发送不保存文件,存储与评审 panel 同 `ReviewStore`。草稿按新文件坐标存,被折叠时显示在折叠条上,文件折叠时显示在文件头上。

实现状态:原生 TextPresenter 原型不采纳。采用 AvaloniaEdit、浮层及原生 LSP 交互,删除旧文件预览行列表与着色控件;共享 Diff 的词法实现不随之删除。构建通过不替代真实编辑、评论提交、语言交互与 Native AOT 发布验证。

依赖与语言范围(已确认):AvaloniaEdit 的配套额外依赖进入白名单,允许使用其 TextMate 集成及语法包,不再要求仅接入自有词法实现。语言范围按所采用方案实际支持的语法提供;无可用语法的文本仍可编辑,明确使用纯文本,不删改源文字符。LSP 能力按已安装并配置的服务器提供,不把语法着色支持宣传为语言服务器已就绪。

**编辑器能力全集与入口。** 编辑器要把 AvaloniaEdit 自述的能力真正开出来,不只是行号与着色:

- 折叠:安装 `FoldingManager` 与 `FoldingMargin`,范围优先取语言服务器的 `textDocument/foldingRange`,服务器未声明 `foldingRangeProvider` 或无会话时回退到结构启发式(`Forge.Editor.Folding.StructuralFolding`),XML/HTML 类文件用库自带 `XmlFoldingStrategy`。文本变化后 250ms 防抖重算,结果按文档版本校验,过期结果丢弃。折叠状态属于控件,不写盘、不跨标签继承。超过 20000 行不折叠并在编辑器提示行说明,而不是卡顿。
- 显示与交互开关:行号、空白、制表符、行尾符、控制字符、文档末尾以下滚动、当前行高亮、超链接、自动折叠、缩进宽度、Tab 转空格、列标尺、着色主题(跟随界面/固定亮/固定暗)。全部落 `settings.json` 的 `preferences` 段(每项可选、缺失取默认),设置页“编辑器”分区给出默认值,改动立即套用到已打开的编辑器。
- 入口:编辑器工具栏 `⋯` 与编辑器右键菜单共用同一份**菜单构建逻辑**,但各自持有自己的实例——Avalonia 的 `ContextMenu` 只能在它挂接的那个控件上打开,工具栏按钮重新打开编辑器菜单会抛 `ArgumentException` 并终止进程,所以工具栏按钮用 `MenuFlyout`。菜单项无绑定:打开时读设置、点击时写设置,因此勾选状态不会说谎且 Native AOT 安全。内容:撤销/重做/剪切/复制/粘贴/全选、显示开关、折叠命令、转换命令(大小写四种、前导 Tab↔空格、缩进选区、删除行)、查找/替换。Ctrl+F / Ctrl+H 用库自带 `SearchPanel`;Ctrl+Shift+[ 折叠当前块、Ctrl+Alt+[ / ] 全部折叠/展开。
- 选区配色:品牌蓝 `#3399FF` 半透明(亮色主题约 24%、暗色约 30%),并清掉库主题给的深底白字前景与边框,选中不得遮住代码本身。搜索命中底色同理用半透明黄。
- 评审图标位置:评论图标挂在选中终点(或行号点击所在行的行首)的**右下角**,靠右边界放不下就翻到左下方,并始终夹在可视区内。
- 多光标:库 12.0.0 **没有实现**(README 宣称,源码只有单 `Caret` 与 `RectangleSelection`)。按用户确认改用矩形(列)选择:保持 `EnableRectangularSelection`,Alt+拖拽选出一列后输入/删除作用于整列,并在设置页与菜单里写明,不把多光标伪装成已实现。

**语义 token 叠加。** 服务器声明 `semanticTokensProvider.full` 时,编辑器把它的分类叠在 TextMate 词法色之上:词法层给「看起来像什么」,语义层给「实际是什么」(属性、参数、方法、类型名等词法分不清的标识符)。叠加由 `SemanticTokenColorizer`(`DocumentColorizingTransformer`)完成,库只为**即将绘制的行**调它,因此只读可见行的按行索引,文档其余部分零工作。颜色取自编辑器自己的 `Syntax*Brush`——那套值就是 Dark+/Light+ 的调色板,与周围 TextMate 文字同源,所以语义叠加读起来是「更精确的分类」而不是「第二套主题」;取色按编辑器实际使用的主题变体解析(`EditorSettings.Theme` 固定主题时也一致)。请求时机:视图绑定、编辑防抖 400ms、服务器发 `workspace/semanticTokens/refresh`、以及打开后 2.5s 一次兜底(项目型服务器先分析再分类);`full/delta` 由客户端解码并应用,索引按行分桶,**只有服务器真的改了分类的行才重建数组**(`SemanticLineIndex.BuiltLines`/`ReusedLines` 可断言),映射在 UI 线程之外完成,结果带快照版本号。服务器对已变更文本作出的答案落地后,若版本已过期会立即再要一份,不留长期错位的叠加。

**查找引用。** Shift+F12 向服务器要 `textDocument/references`(含声明),结果按「本文件在前,然后路径、行、列」排序并去重(服务器常把同一位置报两次);远程 URI 丢弃。列表以 `Flyout` 贴在光标处(`Views/ReferenceListView`),行显示 文件名 · 目录 · 行:列,Enter 或双击跳转:本文件用 `RevealEditorPosition`,跨文件走与定义跳转同一条「沿源文件工作区打开并定位」的路径。空结果是真答案,在编辑器状态行写「没有找到引用」;服务器未声明 `referencesProvider` 时写「不支持查找引用」。请求绑定绑定代次、文档版本与编辑器实例,过期即丢。

**问题面板。** 右侧工具组的 `问题` 固定标签(`ProblemsPanelView`)列出**所有语言会话当前持有的诊断**——跨文件、跨工作区,而不只是当前打开的那一个。数据来自 `WorkspaceDiagnostics`:它订阅会话池的 `SessionStarted`/`SessionClosed` 与每个会话的 `Diagnostics.Changed`,只把变化冒泡成一次通知,面板再把通知合并成一次 UI 线程刷新,展平与排序在 UI 线程之外做,不轮询、闲置时零开销。列表按严重度→路径→行排序,可在 错误/警告/信息/提示 四档间筛选,标题行给「错误数 · 警告数 · 总数」;超过 2000 条只列前 2000 条并明说已截断(上限是内部实现细节,不进设置)。双击或 Enter 打开该文件并定位到诊断,工作区取自诊断本身而不是当前活动会话。面板只在被显示时刷新(附加到可视树或 DataContext 变化),语言切换后按当前语言重建文案。

语言交互边界:使用原生补全窗口、诊断波浪线、悬停文本、语义 token 叠加、查找引用列表与 F12/Ctrl(或 Cmd)点击定义跳转。补全由 Ctrl+Space、服务器声明的触发符或无会话时的词表提供;只跟随第一个定义目标,悬停以纯文本展示;声明不支持 `insert/replace` 之外的 item defaults,不把非法编辑映射为文件开头。异步结果须验证文档、版本、会话与绑定代次,分离视图取消请求。跨文件定义沿源文件的工作区与固定评审会话打开,显式无所属会话不得回退到活动会话;已打开目标保持自身归属。

**语言服务器来源。** 除 `languages.json` 显式配置外,启动时自动检测本机已装的语言服务器(`Forge.Editor.Languages.LanguageServerDiscovery`):先查 PATH 上的已知命令(C#、TS/JS、JSON、CSS、HTML、Python、Go、Rust、C/C++、Shell、YAML、Lua),再查 VS Code / Cursor 的扩展目录(含 C# 扩展里的 Roslyn LSP、`.roslyn` 同名片与 OmniSharp)与安装目录自带的服务(node 启动的 JSON/CSS/HTML);安装目录按三种布局展开(根、`resources/app`、`<版本>/resources/app`)。有界且离线:只做存在性检查、不下载、不安装、不执行探测命令;不存在的目录直接跳过,每个扩展最多看 32 个版本(按版本号取最新)。带注释的 JSON 用独立的 `jsonc` 语言(`.jsonc`、`tsconfig.json`/`jsconfig.json`/`devcontainer.json`,以及 `.vscode` 目录下的任意 `.json`;判定顺序是精确文件名 → `.vscode` 路径段 → 最长扩展名),否则 JSON 服务器会把注释当错误报。TypeScript 会带上 `initializationOptions.tsserver.path`,来源依次是服务器同级的 npm 全局 `node_modules`、npm prefix、编辑器安装目录自带的 `typescript`;找不到就不带选项,让工作区自己的 TypeScript 生效。合并规则:用户在 `languages.json` 里配置过的语言(包括显式配成无服务器或 `disabled`)一律不被覆盖;未被配置的语言才使用发现结果,并继承该服务器的扩展名表与初始化选项。命中后静默使用,并在编辑器状态行写明“语言服务:<服务器名>(来源)”(启动器被隐藏时取实际被启动的文件名,不写成 dotnet/node);仍找不到时提示里说明已查过 PATH 与 VS Code 扩展/安装目录。不使用 Pylance(其许可只允许在 VS Code 内使用)。

**诊断的两条来源与 Roslyn 的加载前提。** 客户端同时声明推送诊断(`textDocument/publishDiagnostics`)与拉取诊断(`textDocument/diagnostic`,LSP 3.17)并从 `diagnosticProvider` 判断;支持拉取的服务器(JSON/CSS/HTML、Roslyn)由编辑器在视图绑定、编辑防抖 500ms、以及服务器发 `workspace/diagnostic/refresh` 时主动拉取,结果写回会话的诊断存储后走与推送同一条映射/渲染/重放链路(晚绑定的视图也能重放)。同时声明 `window.workDoneProgress` 与 `workspace.diagnostics.refreshSupport`,否则 Roslyn 既不开始加载项目也不通知重拉;发现的 Roslyn 另带 `--autoLoadProjects 100`,否则 `.cs` 文件停在“杂项文件”里,永远不会有诊断、悬停与跳转。首次拉取可能早于项目加载而被服务器丢弃,所以打开后还有一次延时重拉兜底;服务器用 `$/progress` 报告自己在加载时,状态行改显示“正在加载项目”,因为这段时间里的 F12、悬停就是不会有回应,把它呈现成等待而不是坏掉。

评论提交边界:草稿可基于未保存代码,发送前保存并验证锚点与内容仍一致。队列接受与数据库标记不是跨系统原子事务,不承诺 exactly-once 或崩溃恢复;接受后标记失败必须提示并在本次运行中阻止重复发送,后续提交或重新加载时重试标记。尚未交给运行时的评论消息被用户撤回或所属会话关闭时,恢复为草稿;恢复失败须提示并阻止再次发送,后续提交或重新加载时重试恢复。标记和恢复按同一 ReviewStore 串行化,避免重试覆盖撤回状态。已交给运行时的消息不恢复;应用退出时异步恢复可能尚未完成,仍属于未提供持久队列与崩溃恢复的边界。保存草稿期间禁止取消释放其锚点,避免数据库留下不可见评论。持久草稿未记录基准提交,重载依赖保存的文本锚点;唯一匹配重定位只搜索不超过 20000 行的文件,超过时仍接受原位置精确匹配,失配不得发送。

**停靠条与自动隐藏。** 以区域为单位。仅自动隐藏的边栏在其所在窗口边缘显示 32px 停靠条(`AutoHideStrip`,底色 `DockStripBackgroundBrush`,内侧 1px 分隔线);停靠状态不显示停靠条,宽度也不占用布局,只为自动隐藏区域按边缘计入 `RegionWidthSolver`;两个自动隐藏边栏在同一侧时并排。条上每个 panel 一个竖排标签(文字旋转 90°,从上往下读),标签外侧(靠窗口边缘)一条 3px 指示条:抽屉打开时为 `DockIndicatorIdleBrush`,抽屉关闭时为 `AccentBrush`。点标签 = 开/关抽屉。抽屉贴着停靠条内侧弹出,覆盖在主区上方,点外部或按 Esc 收起。底部组没有单独的按钮条:它按上一条的方式缩小成标题栏。

**区域置换。** 按住任一 panel 标题栏的空白处横向拖,出现三个落点,放下后两区互换,宽度跟着区域走。自动隐藏中的区域不能拖。按钮条位置、抽屉方向、预览组的“靠主区一侧”都由“角色 + 当前顺序”推导。

**TODO 面板(分组 + 步骤)。** 结构与 ThinkRail 的 `todos`/`groups` 一致:自上而下是**置顶的排队输入行** → 进行中的**分组**(组行 + 缩进的步骤)→ **待排散项** → `完成` 区;历史压最底。置顶行是 `＋` + 无边框 `TextBox`(占位 `todo.addPlaceholder`),它在 `ScrollViewer` 之外所以永远可见,Enter 添加,加进来的是 `TodoOrigin.User` 的**待排散项**(不是分组:agent 述领时用 `todo promote` 把它变成分组)。分组行 = 状态图标 + 标题(`FontSizeBase` + `Bold`)+ 右侧 `已完成/总数`;未完成的分组始终展开、没有删除与折叠入口(分组只由 agent 建)。步骤行缩进一级,左侧一条 1px 引导线**居中在分组行状态图标那一列**(固定 30px = 8 内边距 + 14 图标 + 8 间距),所以线正好压在图标的垂直中线上。**状态图标四态且不可点**:未开始空心圆 / 进行中绿点圈(`AccentBrush`)/ 暂停灰 `⏸` / 完成绿 √(`IconTodoPending`、`IconTodoInProgress`、`IconTodoPaused`、`IconTodoDone` 在 `Resources/Icons.axaml`,颜色分别走 `TextMutedBrush`、`AccentBrush`、`SuccessBrush`);分组的状态由步骤推导(全 done → ✓;有 in_progress → ⊙;否则有 paused → ⏸;否则 ○),从不存储。**面板里没有勾选框、也不能改任何状态**(只读展示 + 新建 / 删除 / 调序):改变状态与步骤提交只发生在 agent 的 `todo` 调用里。行尾 `×` 只在悬停或键盘聚焦时出现(`:pointerover`/`:focus`/`:focus-within` 切 `IsVisible`,行自身 `Focusable` 所以能 Tab 到),删除散项或步骤;`完成` 区完全只读(无 `×`、无“清除已完成”按钮)。人工添加的行右端多一枚线框 user 图标(`IconTodoUser`,灰,`todo.source.user` tooltip)。**拖拽调序**只对 `Pending` 行发起,传的是进程内 `TodoDragSource(Id, GroupId)` record,落点先判同层(待排区之间 / 同一分组之间)再 `ITodoStore.MoveAsync`,存储把序号夹到本层;跨组、拖进拖出分组不做。`完成` 区里已完成分组收成一行 `› ✓ 标题 n 个步骤`,点整行展开它自己的步骤(默认收起),已完成散项排在分组之后。状态行只在没会话 / 清单为空 / 存储报错时显示一行 11px 说明(`HasStatus`),有内容时没有汇总行;旧的顶部“3/8 完成”与底部“清除已完成”已删除。视图模型是四个集合:`Groups`(未全完成)/ `Loose`(未完成散项)/ `DoneGroups` / `DoneLoose`,每次 `ListAsync` + `ListGroupsAsync` 一次刷新重建。

**计划面板(W7)。** 窗口标题行右侧搜索按钮旁的计划按钮(`plan-open`)打开**当前会话**的计划,再点一次、右上角关闭按钮、点遮罩或按 Esc 关掉;切换会话时自动关闭(面板读的是一个会话的计划,留着上一个会话的清单等于报错)。没有活动会话时按钮禁用。面板是一张居中卡片(`Border.plan-card`,最宽 1120、最高 760),左列是**计划摘要 + 步骤**,右栏是**下一步 + 三个出口 + 修订历史**。

- **摘要**是 agent 用 `todo` 的 `plan_summary_set` 写的那段 Markdown,由 `MarkdownRenderer` 渲染(与 diff 预览共用 `Resources/MarkdownStyles.axaml`,两个宿主不再各存一份 `md-*` 样式),只在文本真的变了时重建控件树。标题右侧是 `更新于 MM-dd HH:mm`。没写过摘要时显示 `plan.summary.empty` 一行说明。
- **步骤**是一张扁平虚拟化 `ListBox`,行模型只有一种(`PlanRowViewModel`):分组行画成一条 band(状态图标 + 组名 + `已完成/总数`),步骤行画状态图标、标题(下一步带一枚强调色 `下一步` 小片)、`改动:`、带对勾的 `验证:`、note、7 位 sha 或提交失败原因(危险色)。分组顺序同 `PrBodyRenderer`(分组顺序 → 组内顺序 → 无分组的散项归在 `其他步骤` 标题下;分组缺失的步骤落回散项而不是消失)。行按 key 就地更新(改动的字段才通知),所以 agent 干活期间刷新不会把列表滚回顶部。
- **只读是契约**:面板不写存储、没有勾选框、不改状态;状态与步骤提交只由 agent 的 `todo` 调用产生。唯一的动作是**把这一步交回 agent**(下一步卡片上的按钮 + 每个未完成步骤行尾的发送图标):把一句带步骤 id 的话写进该会话的输入框再发送——回合进行中则排队;输入框里有用户还没发的文字或附件时**不覆盖、不夹带**(附件会随发送进交接消息),改为报一行提示;只读会话、正在交接、压缩中或门控中一律报 `不可用` 并清掉刚写进去的草稿。
- **下一步**取计划顺序里第一个 `in_progress`,否则第一个 `pending`;全做完时写 `没有未完成的步骤了`,此时自然的下一步就是右栏的开 PR。
- **修订历史**是 `plan_summary_revisions`(见 Core SPEC)的最近 50 条,新→旧:每行是 `MM-dd HH:mm` + 首行预览 + 复制按钮;点整行把该版本显示在左列摘要区(顶部一条 `正在看修订 · 该版本被替换于 …` 与`回到当前摘要`按钮),被存储裁掉的版本预览自行退出。顺序以存储为准(按记录先后,不按时间戳再排),历史没变的刷新不重建行。
- **三个出口**:`复制 Markdown`(=`PrBodyRenderer.Render(摘要, 步骤, 分组)`,与 `pr_create` 默认正文、打开 PR 对话框的预填正文同一份文本)、`导出 Markdown…`(保存对话框,建议文件名 `<会话标题>-plan.md`,成功/失败都报一行)、`从计划开 PR…`(跑与提交目标行同一个 `GitSyncViewModel.ComposePullRequestCommand`,对话框与正文都由那条路径给出,可用性与该命令的 `CanExecute` 一致(含 git 行忙),面板打开期间随它的 `CanExecuteChanged` 刷新;禁用时 tooltip 说明条件)。
- **线程与刷新**:一次刷新在后台线程读四条(摘要、条目、分组、修订),用 `BackgroundRead` + 世代号丢弃被顶掉的读;读进行中再来 `ITodoStore.Changed` 只排队一次补读,不并行开第二份;结果回 UI 线程应用。面板打开时创建、关闭时 `Dispose`(退订存储与语言表),所以关掉的面板不会被下一次存储变化唤醒。语言切换只重解文案,不重读存储。左列状态行一行:读取中、读失败(`读不到这个计划: …`)、交接结果、导出结果——失败用危险色;读失败在下一次读成功时撤掉,交接/导出的回执不被刷新冲掉。

**浮动窗口。** 只允许浮出选项卡(任意组的任意选项卡,含 TODO/评审/规格)和文件 panel;其他 panel 不能浮出。

**交互终端(`Terminal/**`)。** 终端是底部组里的选项卡(`TabKind.Terminal`,id 前缀 `terminal:`),可开多个,也可浮出。工作目录取会话的 worktree。
- **VT 引擎(`Terminal/Vt/`)**:纯 BCL、不依赖 Avalonia,AOT 无警告。包括 DEC ANSI 解析器(UTF-8 跨分块续接,非法字节输出 U+FFFD)、主屏和备用屏、回滚环(偏好 `TerminalScrollbackLines`,1000–100000,默认 10000)、SGR 16/256/truecolor、DECSET/DECRST(含鼠标 1000/1002/1003/1006、2004 括号粘贴、2026 同步输出)、OSC 0/1/2 标题、OSC 8 链接、OSC 52 只写剪贴板、OSC 10/11 按主题回答,以及 xterm 按键与 SGR 鼠标编码、East Asian Width 宽字符。缩放时不重排行。实测吞吐约 99 MiB/s(20 MiB 混合文本),稳态滚动零分配。**已记录偏差**:在整屏顶行执行 `CSI M` 时,被删的行会进回滚(xterm 不会),这是为了保证不丢内容。
- **线程**:每个终端一个后台泵,读 `Output`,持锁喂仿真器,置脏标志;UI 按帧合并刷新,UI 线程从不解析。键盘输入和泵线程产生的设备应答(DA/DSR 等)走**同一个有序通道**,由单个写任务送达 Host,保证管道内有序。
- **`TerminalControl`**:自绘,每行生成 `FormattedText` 并按行版本号缓存。支持键盘与 IME 输入;复制粘贴为 Ctrl+Shift+C/V,macOS 用 Cmd;粘贴前去掉转义字符,启用 2004 时加括号包裹。支持拖选、双击选词、三击选行(开启鼠标上报时按住 Shift 仍是本地选择);滚轮在开启上报时发给程序,在备用屏发方向键,否则滚动回滚区。Ctrl+点击 OSC 8 链接只放行 http/https。尺寸变化防抖 50 ms 后同步给 Host。视口锚定在回滚内容上,新输出不会把正在查看的历史顶走。配色来自 `TerminalPalette`(亮暗各一套),字体跟随“代码字体”偏好。
- **`TerminalViewModel`**:标题取 OSC 标题,没有时为“终端 n”。状态分启动中、运行、已退出(退出码)、失败(原因)。退出后标签保留,画面末尾附一行“进程已退出”。Host 未运行时直接显示失败状态,不抛异常。视图先于会话就绪布局时,先记下尺寸,会话就绪后补发。
- **`TerminalWorkbench` 协调器**:按会话 id 持有终端。新建时取会话的 `WorkDir` 和偏好里的 shell 与参数(参数按空格切分,双引号分组)。切换会话时,其它会话**停靠在任意组**里的终端标签被移出、但不结束,切回时放回底部组;浮出的标签留在自己的窗口里。会话归档时结束该会话的全部终端;App 退出时,先于组合根拆除结束全部终端,限时等待。关闭标签时如果有前台进程,不弹对话框,而是在终端视图里显示横幅,让用户选“结束并关闭”或“取消”。
- **工作台接线**:`WorkbenchLayout.TabCloseRequested` 是一个**单值** `Func<…, Task<bool>>` 属性,不是事件,因为多播委托只会留下最后一个返回值;`PanelTabStrip` 的关闭改走它。终端标签不写进 `open-tabs` 快照。入口有三个:Ctrl+`、窗口标题行的终端图标按钮(`terminal-open`,设置左边)、底部组标题栏的“+”。文案表是 `Localization/Strings.Terminal.cs`(键名前缀 `terminal.`)。
- **设置分区未注册**(用户决定):注册会和 `SettingsPanelTests` 对分区列表的硬性断言冲突。`TerminalSettingsViewModel` 及其模板已写好,但没有接线;shell、参数和回滚行数目前只能经偏好文件修改。
- **已知遗留**:浮出的终端标签仍会写进 `LayoutSnapshot.Floating`(恢复时被丢弃,无副作用);关闭被否决时,浮出的标签不会提到最前。延后项:缩放重排行、缓冲区内搜索、OSC 133、重启后恢复、已退出终端的“重新启动”、图片协议、双向文本、macOS 实机验证。

**审批队列与 Agent 扩展(`Approval/`)。**
- `ApprovalQueue` 归 UI 线程,条目是工具调用卡或插件审批卡;主窗口右下角非模态叠加层(约 420 px、可折叠,每张卡标注来源会话),不阻塞其它会话;有待审批项时会话标签与输入框上条的审批计数显示条数。
- `SessionApprovalHandler : IApprovalHandler` 每个主会话一个(注入 `AgentHost.ApprovalHandler`):先查记住规则,命中即 `Allow`;否则入队等待;`ct` 取消或会话释放时撤卡。
- 记住规则 `ApprovalRules`:键 = 工具名 + 副作用 + 作用域(会话/项目/全局),只记“允许”。会话级只在内存;项目级与永久写 `<数据根>/approval-rules.json`(源生成 JSON、`AtomicFile`、后台线程、写入串行且快照在写锁内取),不放进 `AppPreferences`。项目 id 取自 `ISessionCatalog`,常规会话归 General。文件损坏一律当作无规则并备份 `.bak`。`extension_delete`、插件审批卡、插件命令永不可记住;插件新版本获批时清除其新旧工具名下的全部记住项。
- 策略:`extension_list/create/update/disable` 为 `Allow`(只写暂存区,真正的闸门是插件卡),`extension_delete` 走 `Ask`(即删除确认)。
- MCP 工具卡(`Forge.Mcp` 的 `<server>__<tool>`)额外显示**服务器段**:服务器名、传输方式(`stdio`/`http`)、`command` + 参数(后台线程拼成一行、含空白的参数加引号、4 000 字符封顶)、`cwd`、`url`,以及 `env` / `headers` 的**键名列表**——值永不出现在卡片上(卡片可能被截图),这一行由 `McpServices.DescribeForApproval` 从 `McpServerManager.ConfigOfTool` 反查得到,反查走的是暴露名分配时同一张表,消歧过的名字也不会认错服务器。卡片上还有**即时撤销**:当记住规则里有覆盖本工具名的条目时,按钮显示条数,点击撤销全部(会话/项目/全局一并),本卡决策不受影响。
- `ExtensionAuthoringService` 实现 Core 的 `IExtensionAuthoring`:暂存 → 有诊断则直接把诊断返给 Agent(不入队)→ 插件卡入队 → 批准时把卡上展示的哈希原样传给 `extensions.commit`、拒绝则 `extensions.discard`。插件卡新建显示全文、更新显示与线上版本的逐文件 Diff,另示权限、依赖、三种哈希与诊断;只有“批准/拒绝”。重启后 `extensions.pending` 的项以“重启前提交”卡出现,不阻塞任何 Agent。`SessionRuntime` 订阅 `ToolsChanged` 并调用 `AgentHost.ReplaceExternalTools` 热加载。
- 设置分区 `extensions`(`SettingsSectionIds.Extensions`):已安装扩展(启用/禁用/删除,删除二次确认;enable 只在这里提供)、待审批项、按作用域分组的记住规则(逐条撤销)。文案在 `Localization/Strings.Extensions.cs`(中英)。
- 插件/工作流的 `host.tool_call` 经 `SessionToolCallRouter`(`Approval/`)按 run 注册会话路由:工具取自该会话 `AgentHost.Tools`(内置+外部),策略用与 agent loop 相同的 `SessionPolicy`,Ask 走该会话的 `SessionApprovalHandler`(记住的规则与卡片会话均正确),未知/已释放会话拒绝;五个 `extension_*` 工具对插件永不可解析、永不放行(它们的策略是"免问",真正的门是插件卡)。`SessionRuntime` 在构建 host 时注册、释放时注销;`ExtensionHostSupervisor.Create` 接收路由器。
- 子 Agent 的 `host.tool_call`/`run_code` 内部调用:其 `ToolContext.SessionId` 是子会话 id,但子 Agent 与根共用 AgentHost。`SessionRuntime.RunTurnAsync` 消费事件时,`AgentSubAgentStarted`(任意深度)把 `ChildSessionId` 登记为根 scope 的别名,`AgentSubAgentFinished` 或运行时释放时注销(释放时清掉全部别名,释放后不再登记)。子调用按根的工具集解析(变更仍须审批卡;`extension_*` 仍不可达),卡片显示根会话(与 Core 一致)。别名登记发生在事件被消费时,先于子 Agent 的首次模型往返,实际不会落后于其首个工具调用。
- 插件命令审批的 `ToolName` 是 `plugin-command:<pluginId>:<name>`(`ExtensionHostClient.PluginCommandApprovalName`):模型侧工具名只含字母数字、`_`、`-`,不含 `:`,因此永远不会与内置/外部工具名相等,策略 Allow 规则与"始终允许"都碰不到它。插件命令卡不可记住(`ApprovalRules.IsRememberable` 为 false,无记住按钮,`Allow` 也拒绝入库),每次调用单独确认;卡片标题"插件命令审批"。
- 同一会话可同时显示多张工具卡:Core 的 approvalGate 只串行 agent loop 自己的调用,路由器进来的插件/工作流调用不经过它。每次请求有自己的卡与等待,决定和取消只影响自己的卡(`SessionApprovalHandler`/`ApprovalQueue` 按卡片实例工作)。不加跨组件闸门:agent loop 持着工具调用等插件步骤时再加闸会死锁。
- 插件卡无用户决定的撤回(会话释放、关闭、取消、卡片 Dispose)产出独立的 `Withdrawn`(≠ Deny,映射到 Core `ExtensionSubmitOutcome.Withdrawn` 而非 `Invalid`):不 Discard 暂存稿,稿件留待 `extensions.pending` 重启后作为"重启前提交"卡出现;给 agent 的文本如实说"已撤回、草稿保留待定、不是拒绝"。工具卡的撤回仍是 Deny。
- 提交时先(加载规则后)清除旧/新工具名的已记住规则,再提交,提交后按实际注册名再清一次;提交失败时规则保持已清除。`approval-rules.json` 的 `rules: null`/缺失视为损坏文件(无规则 + `.bak`),加载任务永不 Faulted,`RequestAsync` 对加载异常降级为"询问"。
- 工作流扩展卡显示声明的工具(名称/描述/输入 schema)。

**会话生命周期(进行中,已落地部分)。**
- 单实例:`App` 在打开 `forge.db` 之前 `SingleInstanceLock.TryAcquire(数据根)`;拿不到锁只显示“Forge 已在运行。”后退出,不转交、不 IPC、不把已有窗口带到前台。锁持有到 `ShutdownAsync` 结束。
- 只读查看:打开会话从不改状态;非 `Active` 会话(历史行、按 id 打开)开成只读标签,不建 `SessionRuntime`(`SessionWorkspaceViewModel` 的 runtime 为 null,子 Agent 经 `ChildQuery` 只读回放),composer 换成只读条,`Archived` 显示“继续此会话”(工作区目录缺失时禁用并写〔目录缺失〕;仓库 worktree 会话的目录在、但 `git worktree list --porcelain` 把它标为 prunable 或没列出时同样禁用,写 git 的说法;列表读失败或返回空按未知处理,不禁用:继续只是重新打开会话,不删不改任何文件,回合里的 git 调用会自己报错,树上该工作区行同时标〔git 状态未知〕,不把它当正常显示)。树上历史会话行的“继续”跟随所在工作区行的标记一并禁用;点击“继续”时 `ContinueSessionAsync` 不信树上的旧读数,后台重查目录与 worktree 列表,失效则在状态栏说明原因并停止。“继续”只走 `ISessionCatalog.ActivateAsync`;成功后同一标签换成活动视图。
- 回合前校验:每个回合开始前后台读库确认会话仍是 `Active`,否则拒绝、提示“该会话已被接手”、释放 runtime 并转只读(库里已是 `Deleted` 或查无此会话时转成已删除的只读视图,不给“继续”);再读 `WorkspaceStates` 的合并冲突快照(树刷新时对活动的项目会话标签后台读 `MERGE_HEAD`,回合前不跑 git),是则拒绝、提示“合并冲突待处理”并暂停队列。被拒的文本回到草稿(草稿非空时排到队首),不丢;只读条上注明“仍有 n 条未发送的消息”,“继续”把草稿与排队消息带进新的活动视图(队列保持暂停)。读库失败放行(校验防陈旧标签,不是第二真相源),但在状态栏提示校验失败。目录是否存在的探测在后台线程。
- 占用冲突:任何 `WorktreeOccupiedException`(新建、继续)都进占用对话框(点名持有会话),不进通用错误。带意图(新建的 `SessionCreate` 或要继续的会话 id)时给“接手 / 查看 X / 取消”,无意图时只有“查看 X / 取消”。新建路径经 `SessionCreateOccupiedException` 把待建的 `SessionCreate` 带回外壳。
- 接手(`Lifecycle/HandoverFlow`):先查空闲,原因取自持有会话的标签(回合运行中、子 Agent 运行/排队、有排队消息、有未送达插话、正在交接)与 `WorkspaceStates`(工作区操作中、合并冲突);忙时列原因只给“等待 / 取消”,不排队、不强制。再过未保存缓冲区守卫,守卫后复查一次空闲,然后在整个对话框期间置“正在交接”(该标签停止接受发送)。对话框:有未提交改动时选“以旧会话名义提交”(默认)或“带进新会话”(根检出另有提示);新建会话时选上下文模式——摘要(默认)/完整继承/空白,继续已有会话时不选模式。执行顺序:读状态 → 需要时以 `handover: <旧标题>` 提交(走 `StepCommitter.CommitHandoverAsync`:同一把锁与同样的护栏,不看逐步提交偏好、不写 todo 库;失败或跳过即停,不换手)→ 构建上下文(完整:`InheritsFrom`/`InheritsUpToSeq` 与一条继承说明;摘要:旧会话自有消息经 `HandoverSummary` 生成一条用户消息;二者复制 todos/计划,空白不复制)→ `HandoverAsync` 一个事务换手(开始后不可取消)→ 新会话复制评审标记(失败只提示,换手不回退)。摘要失败或取消不回滚已落地的提交,错误里写出提交 sha;重试时工作树已干净,不会再提交。换手失败而提交已落地时同样写出 sha。成功后旧标签转只读、释放其 runtime,打开接手会话并刷新树。
- 尚未做(见未决):摘要只用旧会话自有消息,不沿继承链取父会话;对话框不选模型/推理档位,也没有缓存剩余时间、接近压缩阈值、前缀指纹不符的提示,换模型时禁用完整继承一项随模型选择一并缺席。
- 并行分叉(`Lifecycle/ForkFlow`):树上仓库项目的每个工作区行(主检出与 worktree,默认摘要)和活动根会话行(默认完整继承)有“分叉”。打开菜单不读 git:主检出行用已读的 HEAD 种类禁用游离/未出生分支,worktree 行不预读(点击后由流程读实时 HEAD)。点击后后台读实时 HEAD(游离、未出生、非仓库即拒绝并通知)、未提交改动与稀疏配置,再开分叉对话框:新分支名(默认 `<分支前缀>fork-MMdd-HHmmss`)、未提交改动“先提交”(默认)/“照样分叉”(未带走的改动数另行提示)、有源会话时选上下文模式、稀疏与冷构建提示。源会话忙时只给“照样分叉”,不排队、不强制。读 HEAD 前与执行前都重读源会话,自树刷新以来已被接手或归档(不再是 `Active`)则拒绝、通知并刷新树,不建任何东西。“先提交”在 UI 线程复查源会话空闲并置“正在交接”、把源工作区标为“操作中”(此间不能并回、同步或中止)到本次尝试结束(其排队消息保留),以 `handover: <源标题>` 走交接提交路径;起点是提交后的实时 HEAD。上下文先于 worktree 建好(摘要失败不建任何东西),再以新分支在起点建 worktree(带源的稀疏配置),再建会话行(`fork_of_branch`、`fork_base_sha`、`lineage_root_id` 承自源的谱系根,从不写 `parent_session_id`)并写首条消息;完整继承是引用继承加一条 `InheritanceNote.BuildFork` 说明,摘要是一条用户消息,空白无消息;todos、计划、评审标记都不复制。无活动会话的工作区只能空白分叉。任一步失败都写明原因并收回本次所建(会话行软删后清除,再 `TryRemoveCreatedAsync` 收回 worktree 与未移动的分支);已落地的提交保留并写出 sha。成功后打开新会话、刷新树,源会话照常。
- 合并回 / 同步(`Lifecycle/MergeFlow`):树从工作区最近一条记有 `fork_of_branch` 的会话(含历史)得出分叉关系,worktree 行标“分叉自 <源>”并给“合并回 <源>”“从 <源> 同步”;菜单可用性只看内存(工作区操作中/冲突、活动会话忙),目标是否存在不预读,故目标缺失时项仍可点。点击后后台读 `git worktree list` 定位目标(合并回:检出源分支的工作区;同步:分叉工作区;分叉分支按其工作区当前检出的分支,改名跟随),不按 `fork_base_sha` 猜祖先。源分支无人检出、改名或删除时降级为只给“推送分叉分支”(`push -u`),不做 PR、cherry-pick 或 rebase。已合入/已同步只通知。确认框列最新 50 个提交并给总数。目标空闲判定(其活动标签的忙原因与工作区状态)在确认前后各一次,忙时列原因;通过后置“工作区操作中”、把目标的活动标签置“正在交接”,合并前重读目标工作区当前检出的分支(确认框可能久开,期间被切走),已不是目标分支则不合并、提示重新打开;再在目标工作区 `merge --no-ff --no-edit`(不做逐步提交、不 stash),结束即清除。目标工作树不要求干净:git 拒绝覆盖本地改动时原样转述其文件列表。冲突时标记“合并冲突态”(会话不能开回合,工作区的分叉/合并/新建/归档/重命名禁用),对话框给“中止合并 / 稍后处理”,树上该工作区行在冲突态下出现“中止合并”(`merge --abort`,期间置操作中;成功清冲突标志,失败说明原因;之后的树刷新从 `MERGE_HEAD` 重读)。合并回成功后,外壳设置了 `RemoveForkWorkspace` 时给“移除分叉 / 保留”,以源分支为 `baseBranch` 走移除流水线;未设置时只通知结果。
- 回合前校验另读“工作区操作中”:是则拒绝并提示“此工作区正在执行合并等操作”,草稿与队列同冲突时处理;这也拦住操作开始后才打开的标签。
- 合并冲突快照覆盖两棵树的全部仓库工作区行与活动的项目会话标签,按占用键去重,后台最多 4 个并发读 `MERGE_HEAD`,读完让树重读标志;读不出的工作区保留原标志。正在操作的工作区不读;读的期间该工作区开始过操作或流程写过冲突标志(`WorkspaceStates.Epoch` 变了)则丢弃这次读数,免得旧读数盖掉合并刚标的冲突或中止刚清的标志。冲突在终端里解决后,标志要等下一次树刷新才解除(回合前校验按 6.3 只读快照,不跑 git)。
- 启动:迁移之后、树加载之前跑 `HealMissingDirectoriesAsync`,再把未确认的 `storage_notices`(去重归档、自愈移除)合成一条通知显示并确认;只确认已识别种类的通知,未知种类留在库里;自愈、读通知或确认失败在状态栏提示,不静默。没有对话框服务的外壳不确认,留给下一个窗口。自愈只按目录是否存在判定,有意不读 worktree 列表:它会软删除会话,而 git 标为 prunable 或未登记的目录里仍有用户文件,这类目录只在树上标出,由用户决定移除。自愈之后重试上次彻底删除留下的附属文件清理(见“彻底删除”),仍失败时在状态栏提示,下次启动再试。
- 移除 / 恢复 / 彻底删除 / 关闭项目(`Lifecycle/RemovalFlow` 与外壳的 `MainWindowViewModel.Removal`):
  - 树:活动与已归档的根会话行有“移除会话…”;仓库项目的 worktree 行(不含主检出与项目根)有“移除工作区…”;项目行的移除是“关闭项目…”(软关闭,原硬删除入口已去掉)。菜单可用性只看内存(工作区操作中/冲突、活动会话忙),打开菜单不跑 git、不读库。树经 `ListHistoryAsync` 一并列出 `Deleted` 根会话:目录在时标〔已移除〕,不在时标〔目录已回收〕,只能只读打开、“恢复”或“彻底删除”。目录不在但仍有未删除会话的 worktree 行标〔目录缺失〕,新建、显示、分叉、合并、同步禁用,只留移除;全部会话已删除且目录不在的 worktree 行标〔已回收〕、整行变淡,只给“恢复工作区”“全部彻底删除”。目录在时再对照刷新时读到的 `git worktree list --porcelain`:git 标 prunable 的行标〔git 标记为可清理〕,列表里没有的行标〔git 未登记〕,二者都禁用新建、替换、分叉、合并、同步与改名(原因写 git 的说法),显示与移除照常;列表读失败或返回空时行标〔git 状态未知〕,不按正常也不按失效处理,什么都不禁用,由点击后的流程实时再查。目录不在时始终是〔目录缺失〕/〔已回收〕,不看 git。git 输出的路径与 Forge 记的路径先按规范化拼写比较,不同时再解析符号链接比较(macOS 的 `/var` 即 `/private/var`);这一步在后台读列表时做完,规划与菜单只比较字符串。
  - 移除会话:重读会话(已删除即提示已变化)→ 忙则列原因拒绝 → 线程池算计划:目录去向(根检出与项目根保留;同目录还有其它未删除根会话保留;目录不在只 `worktree prune`;否则进回收站)、仅进回收站时跑删除守卫并原样列出原因(守卫先读 `git worktree list --porcelain`:目录被 git 标为 prunable 或未列出时,在里面跑 `git status` 会失败或答成外层仓库的状态,所以守卫不再查改动,而是给出“git 已将此工作区标记为可清理 / git 工作区列表中没有此目录,无法检查其中未提交的改动”这一条原因,对话框因此是“仍要移除”,目录照常进回收站;列表读失败或返回空时状态未知,照旧检查改动,但改动检查的答案可能来自外层仓库,所以守卫另加一条“无法读取 git 工作区列表(原因),未能确认此目录仍是 git 工作区”,对话框同样是“仍要移除”,从不静默移除;改动检查本身失败(git 出错、进程起不来、超时、文件系统错误;调用方取消不算)时同样不报错停下,而是列一条原因:列表给出该目录的 HEAD 时先在仓库根目录用它补查提交(`CheckCommitsAsync`),成功则列“无法检查其中未提交的改动(提交已从仓库根目录检查)”加查出的提交原因,补查也失败或没有 HEAD 时列“无法检查其中未提交的改动与未合入的提交”;其它异常仍让计划失败并提示“无法检查能否移除”)、子 Agent 数、源分支是本工作区分支且未并入的分叉 → 一个对话框(有原因时按钮为“仍要移除”)→ 未保存缓冲守卫 → 复查空闲 → 置工作区操作中并扣住同目录的标签 → 执行。执行前重读,会话已删除或去向新变成进回收站则拒绝;要进回收站时再跑一次守卫,出现对话框里没列过的新原因则不移除并列出这些原因(不追加确认,用户重新移除即可看到完整列表)。新旧原因按种类比较:查出的改动按原文(改动变多即是新的);可清理、未登记、列表未知、检查失败按种类,git 措辞变了不算新;“只查了提交”被“全都查不了”涵盖,反之不然;检查失败后查出改动、或原本干净而现在检查失败,都是新原因。目录进回收站前,该工作区所有打开的会话视图先像归档一样离开窗口(结束终端、关标签、释放运行时),免得 Forge 自己的句柄锁住目录;此时已过空闲检查与缓冲守卫,不丢排队消息与未保存编辑,回收失败时记录不动,会话可从树上重新打开。先 `ITrashService` 移入回收站再 prune(Windows 上 UNC 路径与非固定盘没有回收站,回收服务直接拒绝、什么都不动,移除因此失败而不是永久删除),最后 `SoftDeleteAsync`(级联子会话,子会话的标签一并关闭);回收失败不动记录;目录已进回收站而记录写失败时明说目录已回收。分支从不删除。
  - 移除工作区:计划同上,另列该目录全部未删除根会话;有活动会话 X 时按钮为“归档 X 并移除”(有守卫原因时为“仍要归档 X 并移除”),先归档 X 再执行;第二步失败时提示 X 已归档、工作区未移除及原因。执行前若有会话重新成为 `Active`,或缺失的目录又出现,则拒绝。项目根(根检出)与常规项目没有“移除工作区”,`RemovalFlow` 在计划与执行两处再拒一次,不依赖调用方。合并回成功后的“移除分叉”走这条路径,以源分支为守卫的 `baseBranch`,错误回给合并流程。
  - 恢复会话:重读(不是 `Deleted` 即提示已变化)→ 目录不在时重建(扣住工作区;General 目录直接创建;仓库 worktree 先 prune 再以原分支 `worktree add`,分支已不在则说明并停止;项目根/根检出缺失不重建)→ `ActivateAsync`,占用时进占用对话框(带“接手”意图)。重建成功而未激活(占用框取消或失败)时提示目录已重建、会话仍是已移除,下次恢复跳过重建。仓库 worktree 重建后提示稀疏检出等本地设置没有恢复。恢复工作区只重建目录,会话保持已移除。
  - 彻底删除:确认后 `PurgeAsync`;被继承守卫拒绝时列出继承者标题;成功后经 `IArtifactStore.DeleteSessionAsync` 删该会话在 `artifacts` 表里的行与 `<UserData>/artifacts/<id>` 目录,再删评审标记与评论;都只按会话 id 删,不动其它会话,可重复执行。工件与评审两部分互不阻断,任一失败都汇总进同一条“部分清理失败”提示,记录已删除。清理前把会话 id 记进 `<UserData>/purge-pending.txt`(`PurgeCleanupJournal`,整文件经临时文件替换写入),清理成功后划掉;失败或中途崩溃时 id 留在文件里,下次启动重试,会话行重新存在的 id 直接划掉、不碰其文件;记不进文件时清理照做,失败提示里说明不会自动重试。一次彻底删除连带子会话、清理了多个 id 时,以及启动重试的失败提示,每条原因前缀所属会话 id。日志只接受存储层同样接受的 id(ASCII 字母数字与 `-_.`,不全是点、不以点结尾),所以不会有一行每次启动都必然失败。“全部彻底删除”按轮重试直到无进展(先删继承者再删被继承者),列出仍被拒绝的会话与错误。
  - 关闭项目:确认 → 查项目全部会话,任一忙(含工作区操作中、合并冲突)则列原因拒绝 → 逐个打开的视图过未保存缓冲守卫 → 复查空闲 → 扣住项目的活动标签执行 `IProjectRegistry.CloseAsync` → 成功后才关闭其标签、释放运行时;关闭失败则窗口原样,只提示原因。目录与会话记录不动;同一路径再添加时注册表复活原项目行,会话随之回来。
- 树菜单(`ViewModels/TreeMenu` 生成、`ProjectTree.Menu` 接线、外壳的 `MainWindowViewModel.Menu`):
  - 菜单由一个纯函数 `TreeMenu.Build(TreeRowState)` 按“行类型 × 状态”生成(键、启用、禁用原因、默认项),视图只渲染;禁用项一律带原因(悬停提示),默认项不会是禁用项。打开菜单只读内存:上次刷新的计划,加上活动标签的忙原因、“正在交接”、`WorkspaceStates` 的操作中/冲突标志;不跑 git、不读库(测试以计数替身钉住)。优先级:正在交接 > 工作区操作中 > 合并冲突/合并或变基进行中。
  - 刷新时(不是开菜单时)在后台为仓库项目的每个已链接工作区目录读一次 HEAD 种类、合并/变基进行中与稀疏配置,并读项目默认分支与 `git worktree list --porcelain`;读数缓存 15 秒,流程改了分支或检出后作废缓存;出现一个缓存那次读取没问过、列表里也没有的现存已链接目录(缓存之后新建的工作区)时当次重读,不拿旧答案判它未登记;已判过未登记的目录照常等缓存过期,不会每次刷新都跑 git。读失败只记日志,相应项照常显示,由点击后的流程实时再查。
  - 行类型与要点:项目行“+”(仓库项目开新建工作区对话框,带稀疏选项;非仓库常规项目没有“+”)、“链接已有工作区…”、“关闭项目…”;检出行(主检出/worktree)的首组是“新建会话”或有活动会话时的“新会话(替换 X)…”与“分叉”;HEAD 游离或未出生时分叉禁用(“HEAD 不在分支上”)、改名分支隐藏;默认分支上改名隐藏;合并/变基进行中(刷新时读到)只禁用“重命名分支”(7.8);合并冲突态(`WorkspaceStates`)与交接中、操作中一样禁用首组、改名、移除与合并/同步,显示仍可用;稀疏检出行标〔稀疏〕。条目在生成状态里可用、但行上的命令此刻不能执行(例如同一命令正在运行)时,显示为禁用并写“此操作现在不可用”,不出现无原因的禁用项。会话行“继续此会话…”在目录缺失时禁用并写原因。“新建工作区…”是原“新建 worktree 会话”的改名,沿用同一个键。
  - 改名分支(7.8):先查空闲(该目录打开的非只读标签忙、交接中、操作中、冲突)→ 实时读默认分支,是默认分支即通知并停止(菜单的隐藏依赖可能过期的刷新读数)→ 读上游,有上游时先警告(“继续 / 取消”)→ 输入新名(空或不变即退出;非法、已存在各有提示)→ 再查空闲并置工作区操作中 → 重读 HEAD(已不在原分支则提示“分支已变化”)与合并/变基(进行中则拒绝)→ `git branch -m` → `ISessionCatalog.RenameBranchAsync` 一个事务改 `branch` 与 `fork_of_branch`。库写失败时把分支改回并提示原因;改回也失败时写明两个名字与两条错误。每个失败分支都有通知,结束释放操作标志并刷新树。所有生命周期流程结束时的树刷新都先作废菜单的 git 读数缓存。“新会话(替换 X)…”点击后实时读 HEAD,新会话记录当前分支(游离时为空),不用刷新时的旧值。
  - 链接已有工作区(7.10):点击后后台读 `git worktree list`,去掉裸库条目、项目根,以及任何会话(含已归档、已移除)指向的目录;锁定与可清理的条目灰显并写原因;无候选只通知。选中游离 HEAD 的条目先警告。以条件插入建会话(`Branch` 取条目分支,游离时为空);占用(列表之后被别的会话占了,或别的项目的会话指向同一目录)进占用对话框并带“接手”意图;其它失败通知。成功后打开新会话;打开失败时树照样刷新。
  - 稀疏检出(7.9):只在项目行“+”的新建工作区对话框提供;稀疏步骤失败时的提示写明稀疏检出与 git 版本要求。勾选后后台 `git ls-tree -d` 列起点的顶层目录(换起点重列、取消勾选清空),至少选一个才可创建;创建走 `worktree add --no-checkout` → `sparse-checkout set --cone` → `checkout`,失败一步即收回本次所建。已核实(git 2.56.1):这一序列只在新 worktree 的 `config.worktree` 写 `core.sparseCheckout`,共享配置只多 `extensions.worktreeConfig=true`,主检出不受影响;`set --cone` 需 git ≥ 2.25,自动启用 worktreeConfig 需 ≥ 2.35。
- `WorkspaceStates`(组合根持有,进程级、线程安全)按占用键保存“工作区操作中”与“合并冲突态”两组标志。

**自动化(`Automations/`)。** 组合根经 `AutomationComposition.Create` 建 `AutomationService`(定义 `automations.json` 在 `settings.json` 旁,运行与状态在 `forge.db`),设置页加“自动化”分区(Agent 组,`IconBolt`)。引擎在主窗口恢复完标签后 `Attach(IAutomationHost)` 才启动,主窗口视图模型(`MainWindowViewModel.Automations.cs`)实现宿主:按 id 找已打开会话、在**不抢焦点**的前提下打开活动根会话、列出已加载会话、报告窗口是否前台。
- **投递只走邮箱。** 自动化写进会话一律经 `SessionMailbox`:会话忙(回合、子 Agent、排队消息、交接)就等它空闲(运行状态 `WaitingIdle`),从不打断;会话被接手/归档/移除/关闭即撤回。自动化回合在转录里先插一条来源提示,被回合闸拒绝时报告“撤回”,不落进输入框。回合结果按工作线程收到的根 Agent 失败/额度事件判定(不等 UI 合并帧),额度用尽随结果带回 `MailboxResult.Quota`;自动化自己的回合用尽额度不再另起恢复运行,由发起的运行决定。消息可携带本回合专用的 Agent(只读工具、模型),回合前应用、回合后恢复为输入框所选,复用的分支会话不会被永久改成只读;会话打不开时运行直接撤回,不投递。运行状态更新按运行串行,等待空闲的进度写在运行自身的下一次更新前落盘。
- **两种会话环境。** 用户定义的放置方式:`Scratch` 每次在 General 项目建一个暂存目录会话(带 `AutomationId`/`AutomationRunId`);`FixedFork` 在指定仓库项目里复用该自动化自己的 `forge/` 分支 worktree 会话(状态 `fork.session:<id>`,失效才新建);`Scout` 在指定活动根会话下起只读 Scout 子 Agent,不占主 Agent 回合。`ReadOnlyTools` 把工具限为 read/grep/find/ls;可单独指定模型。`Remind` 只发通知。
- **内置项**(定义按 id 合成,可在设置页逐项停用,全局可暂停):
  - 额度恢复 `QuotaResume`:根 Agent 回合以额度用尽失败时,记下 `quota.latest:<会话>` 并起一次运行(`WaitingQuota`,`ResumeAt` = 重置时间 + 0–60 秒抖动;无重置时间则探测)。到点后同一提供商的恢复间隔至少 10 秒,经邮箱发“继续”;再次用尽(以投递结果里的额度为准)回到等待,最多 5 轮。关闭时仍在等会话空闲的恢复运行,重启后作为“等待额度、无恢复时刻”续跑(先探测再发)。用户自己在该会话发消息即取消等待中的运行;用户取消(横幅或设置页)时一并删除 `quota.run:` 状态键,只有关闭应用造成的取消保留它供重启续跑。
  - CI 失败修复链 `CiChain`:每 5 分钟查有打开 PR 的分支会话的检查结果;新失败(`ci.seen:`)起一次运行:Scout 只读分析失败日志(截断:每 job 200 行/12k 字符,总 40k),再把结论经邮箱交给该会话的主 Agent 修复;修复后**只推送到 PR 的 head 分支,永不推 base**,可按项目关闭自动推送(`CiAutoPushOffProjects`)。推送前在会话 worktree 里逐项核对,任一不符即不推并通知原因:head 不是 PR base 也不是仓库默认分支;HEAD 不游离;当前分支名等于 head 或其上游是 `origin/<head>`;HEAD 是 PR head 提交的后代。推送固定为 `HEAD:refs/heads/<head>`,从不强推。“修复后同样失败”按“推送的提交 + 失败检查集”记录,在起 Scout 之前判定,PR 转绿时清除。来自 fork 的 PR(`PullRequestInfo.IsCrossRepository`,取自 `gh` 的 `isCrossRepository`)修复只提交在本地,从不推送,并通知原因。每个 PR 尝试预算 3 次,耗尽时通知一次。
  - 长任务看护 `SessionWatch`:每分钟看一次已打开会话,回合 15 分钟无 Agent 事件记“停滞”;有工具(外部命令)正在执行时改按 60 分钟记“命令运行时间很长”(`SessionWorkspaceViewModel.IsToolRunning`,按工作线程收到的工具开始/结束计数),审批卡等待 10 分钟记“待审批”,窗口在后台时用户回合结束记“已完成”;只通知,不动会话。
  - 模型目录更新 `ModelCatalogRefresh`(每日 05:00,与 04:00 的内务错开):抓 `modelCatalog.sourceUrl` 写 `model-catalog.json`,随后刷新每个已连接、凭据就绪且支持 `/models` 的提供商列表,单个提供商失败不挡其余。三条入口共用一个单飞服务,由触发来源决定范围:定时/补跑那次**一定**去问源(带 `ETag`,304 只记“已是最新”)且**一定**刷提供商列表;设置页「立即更新」与启动后的补跑在“今天已经抓过”时整个跳过。启动补跑只抓快照、不碰各提供商列表(那需要逐个带凭据,而窗口正在启动),且只在今天的快照缺失时发起,正常启动不留运行记录。`provider-models.json` 的写入是这次刷新的一部分(在池上写,写完才算完成):一次提供商列表刷新只写一次,而不是后台排队写——后台写会活过调用,和删数据目录、退出进程抢同一个临时文件。
  - 周期清理 `Housekeeping`(每日 04:00):prune 仓库项目的 worktree 记录、删除空的未使用暂存目录(不足 1 小时的目录不动,删除前重查目录库)、修剪运行历史(每定义 200 / 总 2000)、归档闲置超过配置窗口且未打开的根会话(窗口默认 7 天、默认只归档自动化创建的会话,范围可改为全部根会话,也可整体关掉;自动化复用中的分支会话 `fork.session:*` 除外;读不到定义时本次不归档)。三个值经 `IdleArchiveSettings` 由工厂委托每轮读一次,默认值等于此前的硬编码行为。归档后经 `IAutomationHost.OnSessionsArchivedAsync` 在 UI 线程做与界面归档相同的收尾(结束该会话的终端、关标签、释放运行时)并刷新项目树;这一步失败不影响运行结果。
- **界面。** 会话视图在输入框上方显示附着运行的横幅(等待额度到某时刻并倒计时“约 N 分钟后”——随窗口每秒时钟重算,文字变了才通知/等待恢复、等待空闲、执行中)与“取消”;项目树里自动化创建的会话行带闪电标记(提示“由自动化任务创建”)。设置页列出定义(启停、立即运行、编辑、删除需确认)与运行历史(点运行可打开其会话);切换界面语言时定义行即时刷新。`automations.json` 的校验错误带本地化键与参数(`AutomationDefinitionError.MessageKey`/`MessageArgs`),设置页按当前语言显示,英文 `Message` 留给日志与测试。

**两个运行参数分区:`agents` 与 `idle-archive`(W1)。** `agents`(order 120,AGENT 组)是子 Agent 的两个旋钮:“同时运行的 Agent 上限”(1–16,`settings.json` 的 `preferences.agentsMaxParallelSubAgents`,默认 4)与“允许派生 Agent”(`preferences.agentsSubAgentsEnabled`,默认开)。数值由 `AppPreferences` 的 setter 钳制,`SubAgentLimits.From` 再经同一个 `Clamp` 交给运行时,所以设置页给出的范围、接受的取值与宿主实际执行的上限是同一份。组合根把 `AgentRuntimeServices.SubAgents` 接成该偏好的工厂:`SessionRuntime` 建宿主时把它注入 `AgentOptions.MaxParallelSubAgents`,并在每回合前核对一次(`AgentHost.SetMaxParallelSubAgents`,值未移动就不碰宿主,提示词缓存不破),因此扩容立即唤醒排队中的 Agent、缩容不打断已在跑的一轮;开关关闭时 `spawn_agent` 并入宿主的禁用集合(steer/follow_up/stop 仍在),与 `tools` 分区的工具开关落到同一个集合。`idle-archive`(order 570,SYSTEM 组)是每日清理任务的归档步:开关(`preferences.idleArchiveEnabled`,默认开)、闲置天数(1–365,`preferences.idleArchiveDays`,默认 7)与范围(`preferences.idleArchiveScope`,`automation`(默认)/`all`)。`AutomationService` 收的是 `Func<IdleArchiveSettings>`,`HousekeepingRunner` 每轮读一次;关掉时该步在 `openSessions()` 与周任务分支查询之前短路,worktree 清理、空暂存目录与运行历史修剪照常。其余豁免(未打开的会话、子会话、周任务复用的 `fork.session:*`)不开放配置,写进分区提示。文案在 `Localization/Strings.AgentSettings.cs`(`agents.`/`idleArchive.` 前缀);四个分区都在 W1 的 `Composition/RuntimeSettingsComposition.cs` 里注册,视图经 `Views/SectionViewTemplate.Register<TViewModel>(factory)` 挂上(`App.axaml` 已冻结,该模板是后加波次的唯一入口,显式工厂保持 AOT 安全),图标 `IconBot` 与新增的手绘 `IconArchive`。

**MCP 服务器管理(`Views/McpSettingsView.axaml`、`ViewModels/Settings/McpSettingsSectionViewModel.cs`、`Composition/McpServices.cs`、`Services/McpConfigStore.cs`)。** `mcp` 分区不是只读列表:一页里增删改、启停、测试、重连、看工具清单与 stderr 尾,并从 Claude/Cursor/Claude Desktop 的配置导入、用内置预设起步。**文件规则**:写 `~/.forge/mcp.json` 与 `<workspace>/.forge/mcp.json` 中的**被编辑那一份**,走 `SettingsFileMutex` + `AtomicFile`(与 `network` 段同一套),只替换/删除目标条目——其它条目、其它根键与该条目里 Forge 不认识的字段原样保留;写回去的永远是**文件原文**,`${VAR}` 仍是占位符(展开只发生在运行时那份 `McpServerConfig` 里),所以编辑器不会把明文密钥写进用户文件;JSON 注释在写回时丢失,统一两空格缩进(已记入 `Forge.Mcp` 未决)。文件根不是对象时拒绝写并报错,不覆盖用户文件。**导入**按节点原样拷贝(占位符、未知字段、乃至值的 JSON 种类都不变),已在 Forge 里的同名项默认不勾选;导入源不存在时该行说明路径与原因。**预设**(filesystem/context7/memory/playwright/git/fetch/time)只填进编辑器,不静默写文件,需要目录的预设留 `{path}` 给用户确认。**应用**:每次保存=`写文件 → 重新读取两份 → McpServerManager.ApplyConfigAsync` 差量应用(删的先停进程、改的连传输一起回收再用新条目重启、新增的懒启动),单台启动失败只落在它自己的状态与 stderr 上,页面照常;改名的保存会在同一次写里删掉旧键,不留幽灵条目。**读不懂的文件不等于删除**:某份文件的根坏了(非法 JSON、根不是对象、没有 `mcpServers`)时,那份文件贡献不出服务器,于是**来自该文件的运行中服务器原样保留**,只应用其余文件的变化——一次手改打错一个字不该把整台服务器停掉;「重新读取」按钮同样走这条 `apply` 路径(不只刷新页面)。**参数**四项直连 `AppPreferences`(默认请求超时 60 s、重连初始延迟 1 s、工具检索上限 0=不限、stderr 尾行数 200):超时与重连延迟由 `McpServerManager` 在**每次建客户端/每次退避**时经 `Func<McpServerManagerOptions>` 现读,改完对下一次连接生效,不重建管理器;stderr 尾行数只在显示时截断。线程:文件读写、`ApplyConfigAsync`、`ProbeAsync` 全部在线程池;`StateChanged` 可能来自任意线程,页面把它合并成**一次** dispatcher post 再重建行,工具清单与 stderr 只在展开时读,展开/导入列表都有上限。

**MCP 工具进入会话与工具检索上限(`Agents/McpToolExposure.cs`、`Agents/SessionRuntime.cs`、`Forge.Mcp/McpToolSearchTool.cs`)。** 就绪服务器的工具经 `CollectExternalTools` 出现在会话的工具面上,`ToolOrigin.Mcp`,组与来源都是服务器名,开关跟随服务器(`tools` 分区只读)。`mcpToolSearchLimit` 为 0(默认)时**全部**就绪工具都给模型,与引入上限前一致;大于 0 时按请求选面:固定的(pin,多于上限时取最近固定的)→ 按**本回合用户文本**打分的前若干名,不够时按目录顺序补足;打分是小写词包含(暴露名 > 工具名/服务器名 > 描述),每个(目录快照, 上限, 请求文本)算一次并缓存,结果按暴露名排序以保证集合不变时工具定义字节不变。被隐藏时同时提供 `mcp_tool_search`(只读,不需要审批):命中即 pin 并**当场重新发布**工具面,所以上限永远不会让某台服务器的工具不可达;每回合开始由 `ResolveAsync` 比较选中的名字与宿主持有的名字,不一致才 `ReplaceExternalTools`(与 `web_search` 有无的机制同形),集合没变就不发布、提示词缓存不破。pin 与会话绑定,`McpToolExposure` 内部有锁(回合线程与工具线程都会碰它)。

**上下文压缩设置与 `/compact`。** `settings.json` 的 `compaction` 段 `{"enabled":true,"triggerPercent":85,"targetPercent":50}`(`Agents/CompactionSettingsStore.cs`):触发 50–95,目标 ≥1 且低于触发;文件里的非法值按默认值读、保留 `enabled`。编辑入口在 `provider` 分区(`Settings/CompactionSettingsViewModel.cs`,行内校验,失焦或回车保存)。设置**实时生效**:`AppComposition` 把设置存储交给 `AgentRuntimeServices.CompactionChanges`,每个已建宿主的 `SessionRuntime` 订阅其 `Changed`,保存后立刻经 `AgentHost.SetCompactionPolicy` 换上新策略(正在跑的回合从下一次模型请求起按新触发线判断);`ResolveAsync` 在每回合前再按当前设置核对一次(与上次应用的值相同则不动)。换策略只替换开关、比例与窗口/最大输出解析器,不改请求内容、不重置迟滞与上次提示词大小,提示词缓存不受影响;会话释放后不再监听。窗口与最大输出取自模型目录。输入框发送 `/compact [关注点]`(命令词不分大小写,后接空白与可选关注点文本,`/compactfoo` 不算;且没有附图)时不发消息,而是 `SessionRuntime.CompactNowAsync(sink, 关注点)` 手动压缩根上下文:关注点作为 `Additional focus` 追加到摘要指令;保留最近 keepRecent 的原文(见 Core SPEC);自动压缩关闭时手动压缩照样可用;回合进行中拒绝,压缩期间禁止发送,结果以会话内提示给出(已压缩 / 无可压缩 / 忙 / 失败),摘要被拒(截断、工具调用、提供商出错,即 `CompactionFailedException`)时提示失败;自动压缩 Stalled 时也给一条提示。上下文量规在每次模型请求与每次压缩后刷新(见“会话输入框”),点击量规等同发送 `/compact`。

**`ask_user` 问题卡(`Approval/SessionQuestionHandler.cs`、`UserQuestionCardViewModel.cs`)。** 会话有审批服务时建一个问题处理器交给宿主;模型调用 `ask_user` 时在审批浮层里出一张问题卡(选项按钮 + 自由文本),用户作答或取消后回合继续。文案在 `Strings.Questions.cs`(`questions.*`)。多选题按 `MinSelect`/`MaxSelect` 约束(自由文本算一次选择):卡上显示“选择 2–3 项”之类的提示,达到上限后其余未选项禁用、再选被拒;选择数在 [min,max] 内才算已回答(单选仍是恰好一项或自由文本)。每题有“跳过本题”开关,跳过的题输入禁用、算已解决,`ToAnswer()` 返回 `Skipped: true`;所有题都已回答或跳过且至少一题已回答时才可提交,全部跳过时提交禁用并提示改用“忽略”。**串行化:** 同一会话(含子 Agent,它们共用会话 id)同时有多个提问时,`ApprovalQueue` 每会话只把一张问题卡放进 `Items`,其余按 FIFO 暂存(不进 `Items`),当前卡被回答/忽略/取消后下一张出现;暂存中的请求被取消则立即以 Cancelled 完成且从不显示;可见卡上显示“还有 N 个问题等待”。不同会话互不阻塞;待决问题不阻塞审批卡(两者独立)。

**Web 工具设置(`Web/`)。** `web` 分区(AGENT 组,order 140):`settings.json` 的 `web` 段存搜索后端(`brave` / `tavily` / `searxng` / 无)、SearXNG 地址与“允许访问私网”(默认关);Brave/Tavily 密钥不进该段,存 `ProviderSecretStore`(`web.brave.apiKey`、`web.tavily.apiKey`)。`WebServices.CreateTools` 经 `AgentRuntimeServices.WebTools` 提供 Web 工具,作为外部工具加入、策略为询问:`web_fetch` 始终注册;`web_search` 只在有可用后端时注册(`WebServices.SearchAvailable`,与 `CreateBackend` 非空同义:选了 Brave/Tavily 且有密钥,或选了 SearXNG 且地址是 http/https),没配置时模型看不到它,不会再先弹“询问”再得到“未配置”。两个工具实例在 `WebServices` 里只造一次、所有会话共用。已打开的会话在每个回合开始(`SessionRuntime.ResolveAsync`)比较工厂此刻给出的 Web 工具名与宿主持有的是否一致,不一致才重新收集外部工具并 `ReplaceExternalTools`,所以改后端、存/删密钥、改 SearXNG 地址从各会话的下一回合起生效,而不影响 `web_search` 有无的改动(如 Brave 换 Tavily 且都有密钥)不发布新工具集版本、不破坏提示词缓存;正在运行的回合保留开始时的工具集直到结束。`web_search` 仍在每次调用时按当前设置与密钥现造后端,作为兜底:回合中途后端被移除时调用返回“未配置”的失败结果(审批照常)。`WebServices` 从 `NetworkStack` 造两个客户端:抓取客户端关自动重定向并带 `AddressFilter`(允许私网或地址非私网),搜索客户端不过滤;私网判定由此落在连接时,见 forge-core 的 Web 工具。

**网络设置(`Network/`)。** `network` 分区(系统组,order 580,图标 `IconGlobe`,标题“网络与代理”)。`NetworkSettingsStore` 读写 `settings.json` 的 `network` 段(`dns`:`system`/`servers`/`doh`,`dnsServers`,`dohUrl`,`proxy`:`system`/`none`/`manual`,`proxyUrl`,`proxyBypass`),遵循与压缩设置相同的文件规则(节点树、只替换本段、`SettingsFileMutex` + 原子写、根不是对象时拒绝写);读取从不抛异常:无效值按字段回退默认(列表保留有效项,所选模式缺少服务器/URL 时回退 `system`),被替换的字段写入 `LoadProblem`,启动时由 `MainWindowViewModel` 发一条 toast,设置页顶部也显示;文件本身损坏时静默读成默认,由偏好存储报告。`Save` 先规范化,`NetworkSettingsRules.Problems` 非空即抛 `ArgumentException`。`NetworkSettingsSectionViewModel` 只校验所选模式的字段,未选模式中无效的文本保留存储值;“应用”= 保存后 `INetworkStack.Apply`,之后的新连接即用新设置,无需重启;“测试”用未应用的候选设置经 `NetworkStack.CreateResolver` 解析测试主机(默认 `api.anthropic.com`,15 秒超时),结果与错误写在状态行。两条内联提示(警示色,不阻止应用):手动代理填的是有效的 `socks4://` 地址时(`ShowsSocks4Hint`),说明 SOCKS4 只传 IPv4、目标主机名在本机用系统 DNS 解析(不走上面设置的 DNS),要交给代理解析请改用 socks4a/socks5;DNS 选 DoH 且 URL 有效、主机是名字而非 IP 字面量时(`ShowsDohNameHint`),说明 DoH 服务器自身的名字先由系统 DNS 解析,写 IP 形式的 URL 可避免。组合根在通知之后、提供商之前创建 `NetworkStack`,把它交给 `ProviderHttpClient.Create`、MCP 的 `HttpClient` 与 `WebServices`,拆除时在 `HttpClient` 之后释放;这些客户端在交给拥有者之前构造失败时就地释放(MCP 客户端在 `McpServices.Create` 抛出时、提供商客户端在 `ProviderServices` 构造抛出时、`WebServices` 第二个客户端构造失败时释放第一个),不泄漏处理器与连接池。

**附件输入。** 输入框可粘贴、拖放或选取图片、PDF、音频、视频与文本/源码文件,三条入口都走同一个分类器 `FileAttachmentRules.Classify`(`ViewModels/FileAttachments.cs`:扩展名决定"声称是什么",以便超限文件读之前就拒;前导字节嗅探决定"实际是什么";其余字节严格按 UTF-8 解码、含 NUL 或非法 UTF-8 即拒并弹 Warning 通知)。每类上限是常量:PDF 32 MB、音频/视频 20 MB、文本 256 KB、非图片附件每条最多 10 个(图片沿用 `ImageAttachmentRules`)。图片走原有缩放路径成为 `ImageBlock`;PDF/音频/视频成为 `FileBlock`(带文件名);文本文件内联为一个 `TextBlock`,形如首行 `File: <名称>`、内容放进比内容中最长反引号串多一个的围栏(`Forge.Core.Storage.TextAttachment`,回放靠它识别)。**门控**:当前模型的 `ModelInputs` 已知且缺该类 → 拒绝并经 `INotifications` 弹 Warning(key `attachment-refused:<会话>:<原因>`);能力未知则放行;提供商协议没有该类的线路形状(`ProviderAttachments.CanCarry(协议, 媒体类型)`,如 Anthropic 无音视频、Chat Completions 音频只认 wav/mp3)同样拒绝并通知;文本文件不受模型门控。**换模型后**已有附件不再被接受时:弹一次 Warning(key `attachments-blocked:<会话>`,进入阻塞态才弹)、输入框下方常驻原因、发送/排队/插话/转弯全部禁用,附件**绝不静默丢弃**,移除或换回模型即解除。发送时文本与附件一起成为 `ComposerPrompt(Text, Attachments)`,经 `SessionRuntime.RunTurnAsync(text, attachments, …)` 交给 Core;插话同样带附件(`TryInterject(text, attachments)`)在回合中送达,未送达的插话连同附件回到队首。用户气泡显示图片缩略图与其余附件的小片(图标 + 名称 + 大小),回放从存储里的 `ImageBlock`/`FileBlock`/文本附件形状还原。文案在 `Strings.Images.cs`(`session.images.*`)与 `Strings.Attachments.cs`(`session.attachments.*`)。已知限制:真实编解码与文件选择器在无头测试中未覆盖;插话通知只显示键入的文本(仅附件的插话通知为空串)。

**富文件查看器(`ViewModels/Preview/`、`Views/Preview/`)。** 文件标签先**分类再读**,分类是纯函数 `FilePreviewClassifier.Classify(path, firstBytes)`(无 IO,可单测),`LoadAsync` 只负责喂它前 512 字节。顺序有讲究:**Git LFS 指针最先**——被 LFS 管的 PNG 在磁盘上是文本指针,按扩展名会走错路;判据是内容以 `version https://git-lfs.github.com/spec/v1` 开头,不管扩展名。其后按扩展名:`.png/.jpg/.jpeg/.gif/.webp` → 图片;`.csv/.tsv` → 表格;`.ipynb` → 笔记本;`.pdf` → PDF 占位;其余(含 `.html/.htm`)走原有的文本路径,只有 `TextDocument.LoadAsync` 抛 `NotSupportedException`(二进制)时才改出二进制占位——超 `MaxFileBytes` 的仍是原来的“文件过大”错误。**预览是只读的**:`HasDocument` 保持 false,编辑器与工具条上的换行/保存/复制/编辑菜单一起隐藏,`IsDirty`/`CanSave` 恒 false;标签始终显示路径,并常驻一个“用默认程序打开”按钮(`AutomationProperties.AutomationId="file-open-external"`,`Process.Start(UseShellExecute)`),这就是 PDF 不做内部渲染的兑现方式——能交给 OS 的不引渲染器。**网页不设占位**:HTML 在编辑器里就是可编辑源码(取不到 `TextDocument` 的二进制仍有占位卡),而同一个「打开」按钮对 `.html/.htm` 换成「在浏览器中打开」的说法(`files.preview.openInBrowser`;`ExternalOpenLabel` 按当前文件与界面语言现读),一键交给系统默认浏览器——既不在面板里渲染网页,也不为「看一眼源码」多要一次点击。图片预览在后台线程解码,先从头部读尺寸(`ImageHeader`:PNG/GIF/JPEG/WebP),长边超 4096 时**直接解码到 4096**,不先全尺寸解码——几十 MB 的截图展开是几百 MB 像素;头部读不出时才退回原尺寸解码后缩放并释放原图;小图从不放大(工具缩略图走同一个有界解码);解码函数可注入(`Create(imageDecoder:)`),无头测试不碰真实渲染。表格是真 RFC 4180 读取器:引号字段、成对引号、CRLF/LF、字段内换行、参差行补齐;TSV 用制表符且不认引号;超过行数上限的行照常流式读完,只计数(不建字符串)并于标题下说明跳过多少;单字段最多保留 4096 字符、单行最多 1024 列(防御上限:改名成 `.csv` 的二进制或单行巨型导出不能变成几 GB 字符串);读取过程可取消;列宽按前 200 行最宽单元格估算,行用 `VirtualizingStackPanel` 虚拟化,不把整张表画成一段等宽文本。笔记本读 `nbformat`:`stream`/`execute_result`/`display_data`/`error` 四种输出,每段输出按字符上限截断(截断点不落在代理对中间)并标出截断,`image/png` 输出按需用与图片预览相同的有界解码器解码、超过 5 MB 的直接不显示,坏 JSON 出提示不出异常;整个 `.ipynb` 以读取上限 8 MiB 把关(它按文本读,和编辑器文档同一条界限),否则一张带大截图的笔记本会把几百 MB 拉进内存。每个非文本预览都继承 `FilePreviewViewModel`(路径、名称、字节数、本地化标题、打开命令、失败提示),切换界面语言时由 `FileDocumentView` 在 `Loc.LanguageChanged` 上调用 `FileDocumentViewModel.RefreshText`,重发标签页与预览卡片的本地化属性(VM 自己不订阅全局事件,离屏标签重新挂上时补刷);`Release()` 释放已解码的位图并计数(`ReleaseCount`,重复调用无害);换文件、取消、被后续加载顶掉的三条路径都释放——竞赛失败那一份也要释放,否则位图跟着看不见的 VM 一起活到 GC,这条有专门的并发测试(两个加载重叠,输的那份恰好释放一次、赢的那份只在关闭文档时释放一次)。分类、CSV/笔记本/LFS 解析都是纯逻辑,单测覆盖;真实解码与文件选择器在无头测试中不覆盖。

**`files` 设置分区(`Settings/FilesSettingsSectionViewModel.cs`,同一个模块注册)。** 界面组,order 360(`SettingsSectionIds.FilesOrder`,W0 分配),图标 `IconEye`,在编辑器分区之后、终端之前。三项都用 W0 登记的偏好原单位编辑,控件范围也直接取自偏好的夹取常量(不再写死字面量):CSV/TSV 预览行数(`FilesCsvMaxRows`,100–100000,默认 1000)、`.ipynb` 单段输出(`FilesNotebookOutputKilobytes`,1–1024 KB,默认 20 KB)、图片预览上限(`FilesImagePreviewMaxMegabytes`,1–256 MB,默认 20 MB)。三者都直接写 `AppPreferences`,下一次预览即生效;`FilePreviewSettings`(与 `EditorSettings` 同一种投影,`Current` 由组合根绑定)把偏好透给查看器,单位换算只在它一处:KB→字符、MB→字节。

## 提示词模板

**三种模板,一套分层。** `Forge.Abstractions/PromptTemplates.cs` 定契约,`Forge.Core/Prompts/Templates/` 实现,`Prompts/PromptTemplateServices.cs` 是 App 的入口(`AppComposition.PromptTemplates`,也挂在 `AgentRuntimeServices.PromptTemplates`)。种类:
- **命令(Command)**:用户在输入框里敲 `/名称 参数`,正文展开后作为消息发出。frontmatter `description`、`argument-hint`、`mode`;正文里 `$ARGUMENTS`/`$@` 是整串参数,`$1`..`$9` 是第 n 个参数(空白分隔、引号成组),都没用到而又给了参数时参数接在正文后空一行——与 PI/Claude Code 一致。单次从左到右替换,参数里的 `$1` 不会再被展开。内置 `review`、`explain`、`tests`、`fix`。
- **Agent**:frontmatter `name`、`description`、`model`、`thinking`(off/minimal/low/medium/high/xhigh/max)、`tools`(列表)、`mode`;正文是角色提示词。内置 Scout/Worker/Plan/Reviewer 就是 id 为 `scout`/`worker`/`plan`/`reviewer` 的 Agent 模板;覆盖时没写的元数据(尤其 `tools` 白名单)沿用内置值,改提示词不会悄悄放开只读 Agent 的写权限。Agent 按名称派生,所以名称是身份:内置 Agent 的覆盖文件不得改名(`name` 与内置名不同即无效),用户 Agent 的名称(未写时取 id)不得与任何内置 Agent 的名称或 id 重名(否则它会顶替内置项而没有白名单);两个用户 Agent 同名时按 id 序先到者胜。空的 `tools` 列表无效,不当作“全部工具”。`settings.json` 里 Agent 默认值的键是模板 id(文件名),不从名称推导;文件写了 `model` 时用它,否则用设置页的默认值,文件写了 `thinking` 时只替换模型与提供商、保留该强度。
- **槽位(Slot)**:固定 id 的内置提示词,只能覆盖不能新增。Core:`system`、`compaction.summarizer`、`handover.summary`;App:`pr.workflow.<阶段>`(六段 `pr_workflow` 文本)、`automations.quota.continue`、`automations.ci.scout`(占位符 `{pr}` `{branch}` `{failures}`)、`automations.ci.fix`(`{pr}` `{analysis}`)。这三条自动化提示词原先在 `Strings.Automations.cs` 的中英两栏里,现在是固定英文的槽位(它们是模型输入,不随界面语言变)。占位符是单花括号小写标识符,单次替换;声明了占位符的槽位里出现未声明的 `{名字}` 判为无效,未声明占位符的槽位不做替换与检查(PR 文本里的 JSON/URL 花括号原样保留)。

**存储与优先级。** 每个模板一个 `<id>.md`,id 即文件名(1–64 位 `a-z 0-9 . _ -`,字母或数字开头,不以点结尾,不是 Windows 设备名)。作用域按优先级升序:内置(编译期常量,只读)→ 全局 `~/.forge/{commands,agents,prompts}/` → 项目 `<工作区>/.forge/{commands,agents,prompts}/`。同种类同 id 时高层**替换**低层;`mode: append` 时高层正文接在低层合成结果之后(空一行),没写的元数据继承。合成从链上最后一个 replace 成员开始,内置算 replace。无效文件不参与合成但照样列出并带问题码(`PromptTemplateProblemCode`),不静默跳过。"恢复默认"就是删掉自己的那份文件;复制内置时编辑器以 `PromptTemplateStore.BuiltInText` 预填。读写走 `IPromptTemplateStore`,按"种类 + 作用域 + id"寻址,从不按路径;保存带读取时的修订号(文件字节的 SHA-256 前 12 字节),文件在外面被改过即 `Conflict`、不覆盖;新建传 `null` 修订号,文件已存在同样是冲突;写入走临时文件 + 改名。全部方法都是文件 IO,界面线程不得直接调用。`Read` 与列表同样拒绝超过 256 KiB 或不是合法 UTF-8 的文件(抛 `IOException`),编辑器不会打开它们,以免卡住文本框或把看不见的字节覆盖掉。

**生效时机与缓存。** 会话在建 `AgentHost` 时对它的工作区 `Resolve` 一次快照(`PromptTemplateSet`):系统槽位作为 `PromptLayers.System`(`PromptComposer` 把它当完整系统层,空时回落 `BuiltInPrompts.System`)、Agent 集合、压缩提示词都在这个宿主的生命周期内固定,稳定前缀字节不变;改动从下一次建宿主起生效。`pr_workflow` 每次调用按调用的工作目录现取覆盖;交接摘要取全局作用域的 `handover.summary`。

**设置分区 `prompts`。** 位于 AGENT 组(order 130,provider 之后、automations 之前)。左侧列表按 命令 / Agent / 内置提示词 分组,每行左侧是种类图标(斜杠 / Agent / 齿轮),右侧是来源徽标:`内置`(锁、灰)、`全局`、`项目`(两种强调色),另有附加徽标 `覆盖内置` / `追加` / `已被覆盖`(行变暗)/ `无效`(错误色,悬停看问题);顶部过滤 全部 / 内置 / 自定义;悬停显示文件路径。右侧是表单 + Markdown 编辑器;内置项只读,按钮"复制到全局"/"复制到项目";自定义项可保存、还原、删除(确认)。新建时选种类与作用域。槽位不能新建。**项目作用域就是前台会话的工作目录**(`AppComposition.ActiveSessionWorkspace`,worktree 或 scratch 目录),与会话运行时、输入框读取的 `<工作区>/.forge` 同一处;没有前台会话时只能写全局。worktree 会话的项目模板随分支走,要让其它 worktree 看到须提交合并。编辑器有未保存修改时,点别的行或“新建”只给警告,再点一次同一目标才放弃修改。追加模式的勾选文案写明"接在下层同名模板之后",不写成"追加到系统提示词"。

**与 Skills 的关系。** Skills 仍是独立的 `skills` 分区(目录形态:`SKILL.md` + `scripts/` 等,语义是模型按描述自取,与用户触发的命令不同),与本分区共用作用域与徽标约定。输入框 `/` 弹层把命令与技能合并列出,命令在前;同名时命令胜出,技能不再单列。插件的 `WorkflowDefinition` 以后按"来源 = 插件"的技能接入同一目录,不另起一套;技能的 `scripts/` 只能经现有 shell/代码执行工具运行,走原有审批。

## 全局搜索与命令面板

Cmd/Ctrl+P 三个入口之外没有第四种面板:一个覆盖层、五个来源、一份结果列表和一个预览栏。`PaletteView.axaml` 只做键盘路由(隧道期吃掉 Esc/↑/↓/Enter,焦点在查询行)与聚焦,状态全在 `PaletteViewModel`(三个分部:状态机、快照、预览),I/O 全在 `IPaletteHost` 后面——由 `MainWindowViewModel.Palette.cs` 实现,所以视图模型可以在没有窗口的测试里被驱动。

**入口。** `Ctrl+P` 文件、`Ctrl+Shift+P` 命令、`Ctrl+Shift+F` 工作区文本;同一个手势再按一次关闭(手势属于来源,不属于"打开"这个动作,重复按不会清掉已输入的查询)。标题栏的放大镜是同一个动作的按钮(`OpenPaletteCommand`,`AutomationId` 仍是 `shell-search`)。覆盖层的宿主是 `MainWindow.axaml` 里最后那个 `ContentControl Content="{Binding Palette}"`:关闭时属性为 null,视图不存在;打开时 `App.axaml` 按视图模型类型模板出 `PaletteView`,所以它画在审批卡与 toast 之上。来源内还接受首字符前缀 `>` 命令、`#` 内容、`:` 会话、`@` 符号,与点击来源条等价;前缀只在第一位生效,所以 `a>b` 仍是文件查询。切换前台会话即关闭面板(否则它列的是刚离开的那个工作区的文件)。

**五个来源。** 文件来自 `FileIndex`(仓库内 `git ls-files`,否则有界遍历,`.gitignore` 与构建目录一样遵守),匹配复用输入框 `@` 弹层的 `ComposerSuggestions.FilterFiles`,两处排序一致;内容来自 `GrepEngine`(字面量、大小写不敏感、`Limit` = 每来源上限),结果按路径与行号排序后取前 N;会话来自 `ISessionCatalog.QueryAsync` 的内存快照,标题为主、`项目 + 分支` 为次,子 Agent 会话与已删除(软删除)会话不入列,归档会话带徽标(打开为只读);命令是 `PaletteCommandCatalog` 的静态表,id 与 `MainWindowViewModel.RunPaletteCommand` 的 switch 一一对应,行里带手势;符号来自当前编辑器文档的语言服务器(`FileDocumentViewModel.Symbols.cs` 复用编辑器的请求闸门),位置取 `SelectionRange` 起点,上限 2000 个后再排序。

**刷新模型。** 每个来源是"快照 + 后台刷新":打开或切来源时先用上一次的快照立刻出列表,同时发起一次刷新,回来再重建;每次刷新带代号,换代(切来源、关面板、换会话)后到达的答案被丢弃。文件快照按工作区缓存在 `PaletteFileCache`(引用原子换出,读者只会看到旧数组或新数组),内容搜索 180 ms 去抖后一次只有一个在跑,前一次取消。UI 线程每敲一键只做一遍快照过滤(两万文件的列表也是一帧内),分配只在排好序的结果对和结果行(默认上限 50 行)。

**预览。** 命令与会话直接由行字段拼出;文件、匹配行、符号走 `PalettePreview`:最多保留 256 K 字符、首 40 行或命中行 ±12 行、带行号,解码在后台线程,最近一个文件留在缓存里,所以在同一文件的行之间移动不再读盘。读不到(文件没了、无权限)、空文件或二进制文件(首块含 NUL,与内容搜索同一判据)时给"没有可预览的内容",不留空白;位置落在字符预算截掉的部分时显示已读部分的末尾。

**空与失败。** 列表为空时说清原因:没有会话、没有打开的编辑器文件、没有语言服务器、搜索失败(带原因)、或首份快照还在读;这些都以一条不可打开的 notice 行呈现,Enter 对它无效。

**可配置项。** `preferences.palettePerSourceLimit`(默认 50,钳在 [10, 500])与 `preferences.paletteExcludeDirectories`(逗号/分号/换行分隔的目录名,任意层级整段匹配、大小写不敏感;留空表示只遵循 `.gitignore`)。两者都在设置页 `palette` 分区(界面组,`SettingsSectionIds.PaletteOrder`)里编辑,写穿到活偏好,下一次按键即生效;分区由 `Composition/PaletteComposition.cs` 注册视图模型与视图(`SectionViewTemplate`),不改 `App.axaml`。排除目录在结果侧过滤:`GrepEngine` 不接受排除钩子,所以配了排除目录时搜索向引擎要 4 倍上限的匹配行再丢掉排除目录下的行(否则匹配多半落在 `node_modules` 之类目录里的工作区会显示空列表),过滤后仍多于上限或引擎自己截断时状态行注明"只显示前 N 条";扫描成本仍由 `.gitignore` 与引擎的字节/行数上限压住。

## 未决

- 文件预览已支持编辑保存、TextMate 着色、LSP 文档同步、诊断(波浪线 + 行尾圆点 + 拉取)、补全、悬停、跳转定义、语义 token 叠加、查找引用与工作区级问题面板。非文本文件另有图片/CSV/TSV/.ipynb/LFS/二进制预览与 PDF 占位,网页则是可编辑源码 + 「在浏览器中打开」(见「富文件查看器」;不含 SVG 内部渲染与图片 diff、缩放/平移)。未做:代码操作(code action)、重命名、文档符号列表、内联提示(inlay hints)、语义 token 的 range 请求(只用 full/delta)。语义叠加在两次答案之间不随编辑重映射:一次编辑后旧索引的行内坐标可能短暂落在改动过的行上,下一次答案(防抖 400ms 或服务器 refresh)即纠正——不做编辑重映射是为了不在热路径上维护第二份坐标表。声明式插件面板渲染未做。
- 聊天 Markdown 的未决项:用户消息按纯文本渲染(用户输入的字面文本,不做 Markdown);代码块没有行号、折叠与高亮,复制成功没有提示;一个每帧都在长的**不封口**超大围栏代码块会让每次 flush 重设一遍整块文本(流式速率下可接受,没有按行分片);一条**不换行**的超长单行(例如几十 KB 的压缩 JSON)写完之前每次 flush 都整行重解析一遍(分片只按行切,行内不切,否则行号就不再是块的身份);Mermaid 等图表不在本波(归 W11,且要先批准两个包)。
- git 写工具(`git_branch`/`git_sync`)按工具名划为写操作,经会话的审批队列逐次询问;读工具自动放行,且 git 工具不论读写都不暴露给 `run_code` 脚本(脚本面只收只读的文件/web/MCP 三族,见“会话运行”)。
- 资源检查器(W8):面板列的是本窗口打开的会话,不含未打开的后台自动化会话;新打开的空闲会话在下一次拉取(换会话或定时器)时才挂上监听;折叠展开的工具行里的实时尾部按会话时钟(1 s)刷新,只有检查器里的尾部跟着「刷新间隔」走;检查器不落库、不跨进程,关掉窗口就没了。

- 会话交接的未决项:完整继承且继承前缀本身已超过触发线时,Core 的迟滞把重复压缩限制在两次无效尝试后停住(见 Core SPEC),根因(持久化压缩后的表示或历史边界)需要新的存储契约,归 T0,本阶段不引入。交接摘要不沿继承链取父会话消息;历史检索工具也不跟继承链。对话框的模型/推理档位初值、缓存剩余时间、接近压缩阈值、前缀指纹不符等提示未做。
